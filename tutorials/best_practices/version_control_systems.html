Hệ thống quản lý phiên bản

Giới thiệu

Godot hướng tới việc thân thiện với VCS và tạo ra các file phần lớn dễ đọc và dễ merge.

Các plugin quản lý phiên bản

Godot cũng hỗ trợ dùng hệ thống quản lý phiên bản ngay trong trình chỉnh sửa. Tuy nhiên, quản lý phiên bản trong trình chỉnh sửa cần một plugin cho VCS cụ thể mà bạn đang dùng.

Tính đến tháng 10 năm 2025, mới chỉ có plugin Git, nhưng cộng đồng có thể tạo thêm các plugin VCS khác.

Plugin Git chính thức

Việc dùng Git từ bên trong trình chỉnh sửa được hỗ trợ bằng một plugin chính thức. Bạn có thể tìm các bản phát hành mới nhất trên GitHub.

Tài liệu hướng dẫn dùng plugin Git có trên wiki của nó.

Các file cần loại trừ khỏi VCS

Ghi chú

Phần này liệt kê các file và thư mục nên được bỏ qua khỏi quản lý phiên bản trong Godot 4.1 trở về sau.

Danh sách file và thư mục cần bỏ qua khỏi quản lý phiên bản trong Godot 3.x và Godot 4.0 là hoàn toàn khác. Điều này quan trọng vì Godot 3.x và 4.0 có thể lưu thông tin xác thực nhạy cảm trong export_presets.cfg (khác với Godot 4.1 trở về sau).

Nếu bạn đang dùng Godot 3, hãy xem phiên bản 3.6 của trang tài liệu này.

Có một số file và thư mục Godot tự động tạo khi mở một dự án trong trình chỉnh sửa lần đầu. Để tránh làm phình kho quản lý phiên bản bằng dữ liệu được sinh ra, bạn nên thêm chúng vào danh sách bỏ qua của VCS:

  • .godot/: Thư mục này lưu nhiều dữ liệu cache của dự án.

  • *.translation: Các file này là bản dịch dạng nhị phân đã import, được sinh ra từ file CSV.

Bạn có thể để trình quản lý dự án của Godot tự động sinh metadata quản lý phiên bản khi tạo dự án. Khi chọn tùy chọn Git, nó sẽ tạo các file .gitignore và .gitattributes trong thư mục gốc của dự án:

Với các dự án có sẵn, chọn menu Project ở đầu trình chỉnh sửa, rồi chọn Version Control > Generate Version Control Metadata. Thao tác này tạo ra cùng các file như khi thực hiện trong trình quản lý dự án.

Làm việc với Git trên Windows

Hầu hết các client Git cho Windows được cấu hình với core.autocrlf đặt thành true. Điều này có thể khiến Git đánh dấu file là đã sửa đổi một cách không cần thiết do ký tự xuống dòng bị tự động chuyển từ LF sang CRLF.

Tốt hơn là đặt tùy chọn này như sau:

git config --global core.autocrlf input

Tạo metadata quản lý phiên bản bằng trình quản lý dự án hoặc trình chỉnh sửa sẽ tự động bắt buộc dùng ký tự xuống dòng LF thông qua file .gitattributes. Trong trường hợp này, bạn không cần thay đổi cấu hình Git.

Git LFS

Git LFS (Large File Storage) là một phần mở rộng của Git cho phép bạn quản lý các file lớn trong repository. Nó thay các file lớn bằng con trỏ dạng văn bản bên trong Git, còn nội dung file được lưu trên một server từ xa. Điều này hữu ích để quản lý các asset lớn như texture, file âm thanh và mô hình 3D mà không làm phình repository Git.

Ghi chú

Khi dùng Git LFS, bạn cần đảm bảo nó đã được thiết lập trước khi commit bất kỳ file nào vào repository. Nếu đã commit file vào repository, bạn sẽ cần xóa chúng khỏi repository rồi thêm lại sau khi thiết lập Git LFS.

Có thể dùng git lfs migrate để chuyển đổi các file hiện có trong repository, nhưng cách này phức tạp hơn và đòi hỏi hiểu biết tốt về Git.

Một cách phổ biến là thiết lập một repository mới với Git LFS (và một file .gitattributes phù hợp), rồi sao chép các file từ repository cũ sang repository mới. Bằng cách này, bạn có thể đảm bảo mọi file đều được LFS theo dõi ngay từ đầu.

Để dùng Git LFS với Godot, bạn cần cài phần mở rộng Git LFS và cấu hình nó theo dõi các loại file bạn muốn quản lý. Bạn có thể làm điều này bằng cách chạy lệnh sau trong terminal:

git lfs install

Lệnh này sẽ tạo một file .gitattributes trong repository để báo Git dùng LFS cho các loại file được chỉ định. Bạn có thể thêm loại file bằng cách sửa file .gitattributes. Ví dụ, để theo dõi tất cả file GLB, bạn có thể chạy lệnh sau trong terminal:

git lfs track "*.glb"

Khi bạn thêm hoặc sửa các file được LFS theo dõi, Git sẽ tự động lưu chúng vào LFS thay vì lịch sử Git thông thường. Bạn có thể push và pull file LFS giống như file Git thông thường, nhưng lưu ý rằng file LFS được lưu tách biệt khỏi phần còn lại của lịch sử Git. Điều này có nghĩa là bạn có thể cần cài Git LFS trên mọi máy mà bạn clone repository về để truy cập được các file LFS.

Dưới đây là một file .gitattributes mẫu bạn có thể dùng làm điểm khởi đầu cho Git LFS. Các loại file này được chọn vì chúng thường được dùng, nhưng bạn có thể sửa danh sách để bao gồm bất kỳ loại file nhị phân nào có trong dự án.

# Normalize EOL for all files that Git considers text files.
* text=auto eol=lf

# Git LFS Tracking (Assets)

# 3D Models
*.fbx filter=lfs diff=lfs merge=lfs -text
*.gltf filter=lfs diff=lfs merge=lfs -text
*.glb filter=lfs diff=lfs merge=lfs -text
*.blend filter=lfs diff=lfs merge=lfs -text
*.obj filter=lfs diff=lfs merge=lfs -text

# Images
*.png filter=lfs diff=lfs merge=lfs -text
*.svg filter=lfs diff=lfs merge=lfs -text
*.jpg filter=lfs diff=lfs merge=lfs -text
*.jpeg filter=lfs diff=lfs merge=lfs -text
*.gif filter=lfs diff=lfs merge=lfs -text
*.tga filter=lfs diff=lfs merge=lfs -text
*.webp filter=lfs diff=lfs merge=lfs -text
*.exr filter=lfs diff=lfs merge=lfs -text
*.hdr filter=lfs diff=lfs merge=lfs -text
*.dds filter=lfs diff=lfs merge=lfs -text

# Audio
*.mp3 filter=lfs diff=lfs merge=lfs -text
*.wav filter=lfs diff=lfs merge=lfs -text
*.ogg filter=lfs diff=lfs merge=lfs -text

# Font & Icon
*.ttf filter=lfs diff=lfs merge=lfs -text
*.otf filter=lfs diff=lfs merge=lfs -text
*.ico filter=lfs diff=lfs merge=lfs -text

# Godot LFS Specific
*.scn filter=lfs diff=lfs merge=lfs -text
*.res filter=lfs diff=lfs merge=lfs -text
*.material filter=lfs diff=lfs merge=lfs -text
*.anim filter=lfs diff=lfs merge=lfs -text
*.mesh filter=lfs diff=lfs merge=lfs -text
*.lmbake filter=lfs diff=lfs merge=lfs -text

Để biết thêm về Git LFS, hãy xem tài liệu chính thức: https://git-lfs.github.com/ và https://docs.github.com/en/repositories/working-with-files/managing-large-files.
