Khi nào dùng scene, khi nào dùng script

Chúng ta đã tìm hiểu scene và script khác nhau như thế nào. Script định nghĩa phần mở rộng của lớp engine bằng mã mệnh lệnh, còn scene thì bằng mã khai báo.

Do đó, khả năng của mỗi hệ thống là khác nhau. Scene có thể định nghĩa cách một lớp mở rộng được khởi tạo, nhưng không định nghĩa hành vi thực sự của nó. Scene thường được dùng kết hợp với script: scene khai báo một tổ hợp các node, còn script bổ sung hành vi bằng mã mệnh lệnh.

Kiểu ẩn danh

Bạn hoàn toàn có thể định nghĩa toàn bộ nội dung của scene chỉ bằng script. Về bản chất, đây chính là điều Godot Editor làm, chỉ có điều là trong constructor C++ của các đối tượng của nó.

Nhưng việc chọn dùng cái nào có thể là một tình thế khó xử. Tạo instance script giống hệt tạo các lớp trong engine, trong khi xử lý scene đòi hỏi thay đổi API:

const MyNode = preload("my_node.gd")
const MyScene = preload("my_scene.tscn")
var node = Node.new()
var my_node = MyNode.new() # Same method call.
var my_scene = MyScene.instantiate() # Different method call.
var my_inherited_scene = MyScene.instantiate(PackedScene.GEN_EDIT_STATE_MAIN) # Create scene inheriting from MyScene.

using Godot;

public partial class Game : Node
{
    public static CSharpScript MyNode { get; } =
        GD.Load<CSharpScript>("res://Path/To/MyNode.cs");
    public static PackedScene MyScene { get; } =
        GD.Load<PackedScene>("res://Path/To/MyScene.tscn");
    private Node _node;
    private Node _myNode;
    private Node _myScene;
    private Node _myInheritedScene;

    public Game()
    {
        _node = new Node();
        _myNode = MyNode.New().As<Node>();
        // Different than calling new() or MyNode.New(). Instantiated from a PackedScene.
        _myScene = MyScene.Instantiate();
        // Create scene inheriting from MyScene.
        _myInheritedScene = MyScene.Instantiate(PackedScene.GenEditState.Main);
    }
}

Ngoài ra, script sẽ chạy chậm hơn scene một chút do chênh lệch tốc độ giữa mã engine và mã script. Node càng lớn và càng phức tạp thì càng có lý do để xây dựng nó thành scene.

Kiểu có tên

Script có thể được đăng ký thành một kiểu mới ngay trong trình chỉnh sửa. Khi đó nó hiển thị như một kiểu mới trong hộp thoại tạo node hoặc resource, kèm biểu tượng tùy chọn. Nhờ vậy, người dùng sử dụng script dễ dàng hơn nhiều. Thay vì phải...

  1. Biết kiểu cơ sở của script họ muốn dùng.

  2. Tạo một instance của kiểu cơ sở đó.

  3. Gắn script vào node.

Với script đã đăng ký, kiểu được viết bằng script sẽ trở thành một lựa chọn trong hộp thoại tạo giống như các node và resource khác trong hệ thống. Hộp thoại tạo thậm chí còn có thanh tìm kiếm để tra cứu kiểu theo tên.

Có hai hệ thống để đăng ký kiểu:

  • Kiểu tùy chỉnh

    • Chỉ có trong trình chỉnh sửa. Tên kiểu không truy cập được khi chạy.

    • Không hỗ trợ kiểu tùy chỉnh kế thừa.

    • Một công cụ khởi tạo. Tạo node kèm script. Không gì hơn.

    • Trình chỉnh sửa không nhận biết kiểu của script hay quan hệ của nó với các kiểu engine hoặc script khác.

    • Cho phép người dùng định nghĩa biểu tượng.

    • Hoạt động với mọi ngôn ngữ script vì nó làm việc với resource Script ở mức trừu tượng.

    • Thiết lập bằng EditorPlugin.add_custom_type.

  • Lớp script

    • Truy cập được cả trong trình chỉnh sửa lẫn khi chạy.

    • Hiển thị đầy đủ quan hệ kế thừa.

    • Tạo node kèm script, nhưng cũng có thể đổi kiểu hoặc mở rộng kiểu từ trình chỉnh sửa.

    • Trình chỉnh sửa nhận biết quan hệ kế thừa giữa các script, lớp script và lớp C++ của engine.

    • Cho phép người dùng định nghĩa biểu tượng.

    • Nhà phát triển engine phải thêm hỗ trợ cho từng ngôn ngữ một cách thủ công (cả việc công khai tên lẫn khả năng truy cập khi chạy).

    • Trình chỉnh sửa quét các thư mục dự án và đăng ký mọi tên được công khai cho tất cả ngôn ngữ script. Mỗi ngôn ngữ script phải tự triển khai hỗ trợ việc công khai thông tin này.

Cả hai phương pháp đều thêm tên vào hộp thoại tạo, nhưng riêng lớp script còn cho phép người dùng truy cập tên kiểu mà không cần tải resource script. Có thể tạo instance và truy cập hằng số hoặc phương thức static từ bất cứ đâu.

Với những tính năng như vậy, bạn có thể muốn kiểu của mình là một script không kèm scene vì sự tiện dụng nó mang lại cho người dùng. Những ai phát triển plugin hoặc tạo công cụ nội bộ cho nhà thiết kế sử dụng sẽ thấy cách này dễ dàng hơn.

Mặt trái là nó cũng đồng nghĩa với việc phải dùng phần lớn là lập trình mệnh lệnh.

Hiệu năng của Script so với PackedScene

Khía cạnh cuối cùng cần cân nhắc khi chọn giữa scene và script là tốc độ thực thi.

Khi kích thước đối tượng tăng lên, kích thước script cần thiết để tạo và khởi tạo chúng cũng tăng lên rất nhiều. Việc tạo hệ phân cấp node minh chứng cho điều này. Logic của mỗi Node có thể dài vài trăm dòng mã.

Ví dụ mã dưới đây tạo một Node mới, đổi tên nó, gán script cho nó, đặt node cha tương lai làm owner để nó được lưu xuống đĩa cùng node cha, và cuối cùng thêm nó làm con của node Main:

# main.gd
extends Node

func _init():
    var child = Node.new()
    child.name = "Child"
    child.script = preload("child.gd")
    add_child(child)
    child.owner = self

using Godot;

public partial class Main : Node
{
    public Node Child { get; set; }

    public Main()
    {
        Child = new Node();
        Child.Name = "Child";
        var childID = Child.GetInstanceId();
        Child.SetScript(GD.Load<Script>("res://Path/To/Child.cs"));
        // SetScript() causes the C# wrapper object to be disposed, so obtain a new
        // wrapper for the Child node using its instance ID before proceeding.
        Child = (Node)GodotObject.InstanceFromId(childID);
        AddChild(Child);
        Child.Owner = this;
    }
}

Mã script như thế này chậm hơn nhiều so với mã C++ phía engine. Mỗi lệnh đều gọi tới API script, dẫn đến nhiều lần "tra cứu" ở phía back-end để tìm logic cần thực thi.

Scene giúp tránh vấn đề hiệu năng này. PackedScene, kiểu cơ sở mà scene kế thừa, định nghĩa các resource dùng dữ liệu được tuần tự hóa để tạo đối tượng. Engine có thể xử lý scene theo lô ở phía back-end và cho hiệu năng tốt hơn nhiều so với script.

Kết luận

Rốt cuộc, cách tiếp cận tốt nhất là cân nhắc những điều sau:

  • Nếu bạn muốn tạo một công cụ cơ bản sẽ được tái sử dụng trong nhiều dự án khác nhau và có thể được người dùng ở mọi trình độ sử dụng (kể cả những người không tự nhận mình là "lập trình viên"), thì nhiều khả năng nó nên là một script, có lẽ kèm tên/biểu tượng tùy chỉnh.

  • Nếu bạn muốn tạo một khái niệm riêng cho game của mình, thì nó luôn nên là một scene. Scene dễ theo dõi/chỉnh sửa hơn và an toàn hơn script.

  • Nếu bạn muốn đặt tên cho một scene, bạn vẫn có thể làm gần như vậy bằng cách khai báo một lớp script và gán scene cho nó dưới dạng hằng số. Về thực chất, script khi đó trở thành một namespace:

    # game.gd
class_name Game # extends RefCounted, so it won't show up in the node creation dialog.
extends RefCounted

const MyScene = preload("my_scene.tscn")

# main.gd
extends Node
func _ready():
    add_child(Game.MyScene.instantiate())

    // Game.cs
public partial class Game : RefCounted
{
    public static PackedScene MyScene { get; } =
        GD.Load<PackedScene>("res://Path/To/MyScene.tscn");
}

// Main.cs
public partial class Main : Node
{
    public override void _Ready()
    {
        AddChild(Game.MyScene.Instantiate());
    }
}
