Sử dụng NavigationServer

Phiên bản 2D và 3D của NavigationServer lần lượt là NavigationServer2D và NavigationServer3D.

Giao tiếp với NavigationServer

Làm việc với NavigationServer nghĩa là chuẩn bị các tham số cho một truy vấn có thể được gửi tới NavigationServer để cập nhật hoặc yêu cầu dữ liệu.

Để tham chiếu đến các đối tượng nội bộ của NavigationServer như map, region và agent, RID được dùng làm số định danh. Mỗi node liên quan đến navigation trong scene tree đều có một hàm trả về RID cho node đó.

Đa luồng và đồng bộ hóa

NavigationServer không cập nhật từng thay đổi ngay lập tức mà đợi đến cuối physics frame để đồng bộ tất cả thay đổi cùng lúc.

Việc chờ đồng bộ là bắt buộc để áp dụng thay đổi cho mọi map, region và agent. Đồng bộ được thực hiện vì một số cập nhật như tính toán lại toàn bộ navigation map rất tốn kém và cần dữ liệu đã cập nhật từ mọi đối tượng khác. Ngoài ra, NavigationServer mặc định dùng một threadpool cho một số chức năng như tính toán avoidance giữa các agent.

Không cần chờ đối với hầu hết các hàm get() chỉ yêu cầu dữ liệu từ NavigationServer mà không tạo thay đổi. Lưu ý rằng không phải mọi dữ liệu đều phản ánh các thay đổi được thực hiện trong cùng frame. Ví dụ, nếu một avoidance agent đổi navigation map trong frame này, hàm agent_get_map() vẫn sẽ trả về map cũ trước khi đồng bộ. Ngoại lệ là các node lưu giá trị nội bộ trước khi gửi cập nhật tới NavigationServer. Khi dùng getter trên một node cho một giá trị đã được cập nhật trong cùng frame, nó sẽ trả về giá trị đã cập nhật được lưu trên node.

NavigationServer là thread-safe vì nó đặt mọi lệnh gọi API muốn tạo thay đổi vào một hàng đợi để thực thi trong giai đoạn đồng bộ. Việc đồng bộ của NavigationServer diễn ra ở giữa physics frame, sau khi input của scene từ script và node đều đã xong.

Ghi chú

Điểm quan trọng cần nhớ là hầu hết các thay đổi trên NavigationServer có hiệu lực sau physics frame tiếp theo chứ không phải ngay lập tức. Điều này bao gồm mọi thay đổi do các node liên quan đến navigation trong scene tree hoặc qua script thực hiện.

Ghi chú

Mọi hàm setter và hàm xóa đều cần đồng bộ.

Khác biệt giữa NavigationServer 2D và 3D

NavigationServer2D và NavigationServer3D tương đương về chức năng trong chiều không gian của chúng.

Về mặt kỹ thuật, bạn có thể dùng các công cụ tạo navigation mesh của một chiều cho chiều còn lại, ví dụ bake navigation mesh 2D bằng NavigationMesh 3D khi dùng hình học nguồn 3D phẳng, hoặc tạo navigation mesh 3D phẳng bằng các công cụ vẽ đường viền đa giác của NavigationRegion2D và NavigationPolygon.

Chờ đồng bộ hóa

Khi bắt đầu game, một scene mới hoặc các thay đổi navigation theo thủ tục, mọi path query tới NavigationServer sẽ trả về rỗng hoặc sai.

Tại thời điểm này, navigation map vẫn còn trống hoặc chưa được cập nhật. Mọi node trong scene tree trước hết cần tải dữ liệu liên quan đến navigation của chúng lên NavigationServer. Mỗi map, region hoặc agent được thêm hoặc thay đổi đều cần được đăng ký với NavigationServer. Sau đó, NavigationServer cần một physics frame để đồng bộ nhằm cập nhật các map, region và agent.

Một cách khắc phục là gọi trì hoãn (deferred call) tới một hàm thiết lập tùy chỉnh (để mọi node đều đã sẵn sàng). Hàm thiết lập thực hiện mọi thay đổi navigation, ví dụ thêm các thành phần theo thủ tục. Sau đó, hàm đợi physics frame tiếp theo trước khi tiếp tục với các path query.

extends Node3D

func _ready():
    # Use call deferred to make sure the entire scene tree nodes are setup
    # else await on 'physics_frame' in a _ready() might get stuck.
    custom_setup.call_deferred()

func custom_setup():

    # Create a new navigation map.
    var map: RID = NavigationServer3D.map_create()
    NavigationServer3D.map_set_up(map, Vector3.UP)
    NavigationServer3D.map_set_active(map, true)

    # Create a new navigation region and add it to the map.
    var region: RID = NavigationServer3D.region_create()
    NavigationServer3D.region_set_transform(region, Transform3D())
    NavigationServer3D.region_set_map(region, map)

    # Create a procedural navigation mesh for the region.
    var new_navigation_mesh: NavigationMesh = NavigationMesh.new()
    var vertices: PackedVector3Array = PackedVector3Array([
        Vector3(0, 0, 0),
        Vector3(9.0, 0, 0),
        Vector3(0, 0, 9.0)
    ])
    new_navigation_mesh.set_vertices(vertices)
    var polygon: PackedInt32Array = PackedInt32Array([0, 1, 2])
    new_navigation_mesh.add_polygon(polygon)
    NavigationServer3D.region_set_navigation_mesh(region, new_navigation_mesh)

    # Wait for NavigationServer sync to adapt to made changes.
    await get_tree().physics_frame

    # Query the path from the navigation server.
    var start_position: Vector3 = Vector3(0.1, 0.0, 0.1)
    var target_position: Vector3 = Vector3(1.0, 0.0, 1.0)
    var optimize_path: bool = true

    var path: PackedVector3Array = NavigationServer3D.map_get_path(
        map,
        start_position,
        target_position,
        optimize_path
    )

    print("Found a path!")
    print(path)

using Godot;

public partial class MyNode3D : Node3D
{
    public override void _Ready()
    {
        // Use call deferred to make sure the entire scene tree nodes are setup
        // else await on 'physics_frame' in a _Ready() might get stuck.
        CallDeferred(MethodName.CustomSetup);
    }

    private async void CustomSetup()
    {
        // Create a new navigation map.
        Rid map = NavigationServer3D.MapCreate();
        NavigationServer3D.MapSetUp(map, Vector3.Up);
        NavigationServer3D.MapSetActive(map, true);

        // Create a new navigation region and add it to the map.
        Rid region = NavigationServer3D.RegionCreate();
        NavigationServer3D.RegionSetTransform(region, Transform3D.Identity);
        NavigationServer3D.RegionSetMap(region, map);

        // Create a procedural navigation mesh for the region.
        var newNavigationMesh = new NavigationMesh()
        {
            Vertices =
            [
                new Vector3(0.0f, 0.0f, 0.0f),
                new Vector3(9.0f, 0.0f, 0.0f),
                new Vector3(0.0f, 0.0f, 9.0f),
            ],
        };
        int[] polygon = [0, 1, 2];
        newNavigationMesh.AddPolygon(polygon);
        NavigationServer3D.RegionSetNavigationMesh(region, newNavigationMesh);

        // Wait for NavigationServer sync to adapt to made changes.
        await ToSignal(GetTree(), SceneTree.SignalName.PhysicsFrame);

        // Query the path from the navigation server.
        var startPosition = new Vector3(0.1f, 0.0f, 0.1f);
        var targetPosition = new Vector3(1.0f, 0.0f, 1.0f);

        Vector3[] path = NavigationServer3D.MapGetPath(map, startPosition, targetPosition, optimize: true);

        GD.Print("Found a path!");
        GD.Print((Variant)path);
    }
}

Callback avoidance của server

Nếu các avoidance agent RVO được đăng ký nhận callback avoidance, NavigationServer sẽ phát signal velocity_computed của chúng ngay trước khi PhysicsServer đồng bộ.

Để tìm hiểu thêm về NavigationAgent, xem Sử dụng NavigationAgent.

Thứ tự thực thi đơn giản hóa cho các NavigationAgent có dùng avoidance:

  • physics frame bắt đầu.

  • _physics_process(delta).

  • Thuộc tính velocity được đặt trên Node NavigationAgent.

  • Agent gửi vận tốc và vị trí tới NavigationServer.

  • NavigationServer chờ đồng bộ.

  • NavigationServer đồng bộ và tính toán vận tốc avoidance cho mọi avoidance agent đã đăng ký.

  • NavigationServer gửi vector vận tốc an toàn qua signal cho từng avoidance agent đã đăng ký.

  • Agent nhận signal và di chuyển node cha của chúng, ví dụ bằng move_and_slide hoặc linear_velocity.

  • PhysicsServer đồng bộ.

  • physics frame kết thúc.

Vì vậy, di chuyển một actor physics body trong hàm callback bằng vận tốc an toàn là hoàn toàn an toàn về luồng lẫn vật lý, vì mọi thứ diễn ra trong cùng một physics frame trước khi PhysicsServer chốt các thay đổi và thực hiện tính toán của riêng nó.
