Tối ưu bằng Server

Các engine như Godot mang lại sự dễ dùng hơn nhờ các cấu trúc và tính năng cấp cao. Hầu hết chúng được truy cập và sử dụng thông qua hệ thống scene. Dùng node và resource giúp đơn giản hóa việc tổ chức dự án và quản lý asset trong các game phức tạp.

Cách này có một số nhược điểm:

  • Có thêm một lớp phức tạp.

  • Hiệu năng thấp hơn so với khi dùng trực tiếp các API đơn giản.

  • Không thể dùng nhiều luồng để điều khiển chúng.

  • Cần nhiều bộ nhớ hơn.

Trong hầu hết trường hợp, đây không thực sự là vấn đề. Godot được tối ưu tốt, và hầu hết thao tác được xử lý bằng signal, nghĩa là không cần polling. Dù vậy, đôi khi chúng ta muốn khai thác hiệu năng tốt hơn từ phần cứng khi các hướng tối ưu khác đã cạn kiệt. Ví dụ, việc xử lý hàng chục nghìn instance cho thứ gì đó cần được xử lý mỗi frame có thể trở thành điểm nghẽn.

Loại tình huống này khiến lập trình viên hối tiếc vì đang dùng game engine và ước có thể quay lại cách triển khai code game cấp thấp, thủ công hơn.

Dù vậy, Godot được thiết kế để giải quyết vấn đề này.

Server

Một trong những quyết định thiết kế thú vị nhất của Godot là việc toàn bộ hệ thống scene là tùy chọn. Mặc dù không thể loại bỏ nó khi biên dịch, nó có thể được bỏ qua hoàn toàn.

Ở phần lõi, Godot dùng khái niệm Server. Chúng là các API cấp thấp để điều khiển kết xuất, vật lý, âm thanh, v.v. Hệ thống scene được xây dựng trên chúng và dùng chúng trực tiếp. Các server phổ biến nhất là:

  • class_RenderingServer: Xử lý mọi thứ liên quan đến đồ họa.

  • class_PhysicsServer3D: Xử lý mọi thứ liên quan đến vật lý 3D.

  • class_PhysicsServer2D: Xử lý mọi thứ liên quan đến vật lý 2D.

  • class_AudioServer: Xử lý mọi thứ liên quan đến âm thanh.

Hãy khám phá API của chúng, và bạn sẽ nhận ra rằng tất cả các hàm được cung cấp đều là triển khai cấp thấp của mọi thứ mà Godot cho phép bạn làm bằng node.

RID

Chìa khóa để sử dụng các server là hiểu các đối tượng Resource ID (RID). Đây là các handle mờ (opaque) trỏ tới phần triển khai của server. Chúng được cấp phát và giải phóng thủ công. Hầu như mọi hàm trong các server đều cần RID để truy cập resource thực sự.

Hầu hết các node và resource của Godot đều chứa sẵn bên trong các RID này từ các server, và bạn có thể lấy chúng bằng nhiều hàm khác nhau. Thực tế, bất cứ thứ gì kế thừa Resource đều có thể được ép kiểu trực tiếp thành RID. Tuy nhiên, không phải resource nào cũng chứa RID: trong những trường hợp đó, RID sẽ rỗng. Khi đó, resource có thể được truyền vào các API của server dưới dạng RID.

Cảnh báo

Resource được đếm tham chiếu (xem RefCounted), và các tham chiếu tới RID của một resource không được tính khi xác định resource đó còn được sử dụng hay không. Hãy đảm bảo giữ một tham chiếu tới resource bên ngoài server. Nếu không, cả resource lẫn RID của nó đều sẽ bị xóa.

Đối với node, có nhiều hàm có sẵn:

  • Với CanvasItem, phương thức CanvasItem.get_canvas_item() sẽ trả về RID của canvas item trong server.

  • Với CanvasLayer, phương thức CanvasLayer.get_canvas() sẽ trả về RID của canvas trong server.

  • Với Viewport, phương thức Viewport.get_viewport_rid() sẽ trả về RID của viewport trong server.

  • Với 2D, resource class_World2D (lấy được từ các node class_Viewport và CanvasItem) chứa các hàm để lấy RenderingServer Canvas và PhysicsServer2D Space. Điều này cho phép tạo và sử dụng các đối tượng 2D trực tiếp bằng API của server.

  • Với 3D, resource class_World3D (lấy được từ các node class_Viewport và class_Node3D) chứa các hàm để lấy RenderingServer Scenario và PhysicsServer Space. Điều này cho phép tạo và sử dụng các đối tượng 3D trực tiếp bằng API của server.

  • Lớp class_VisualInstance3D cho phép lấy instance và instance base của scenario lần lượt thông qua VisualInstance3D.get_instance() và VisualInstance3D.get_base().

Hãy thử khám phá các node và resource mà bạn đã quen thuộc và tìm các hàm để lấy RID của server.

Không nên điều khiển RID từ các đối tượng đã có node gắn liền. Thay vào đó, luôn dùng các hàm của server để tạo và điều khiển RID mới cũng như tương tác với các RID hiện có.

Tạo một sprite

Đây là ví dụ về cách tạo một sprite từ code và di chuyển nó bằng API cấp thấp class_CanvasItem.

Ghi chú

Khi tạo canvas item bằng RenderingServer, bạn nên reset nội suy vật lý ở frame đầu tiên bằng RenderingServer.canvas_item_reset_physics_interpolation(). Điều này đảm bảo đồng bộ chính xác giữa hệ thống kết xuất và hệ thống vật lý.

Nếu không làm vậy, canvas item có thể trông như bị dịch chuyển tức thời vào khi scene được tải, thay vì xuất hiện ngay tại vị trí mong muốn.

extends Node2D


# RenderingServer expects references to be kept around.
var texture


func _ready():
    # Create a canvas item, child of this node.
    var ci_rid = RenderingServer.canvas_item_create()
    # Make this node the parent.
    RenderingServer.canvas_item_set_parent(ci_rid, get_canvas_item())
    # Draw a texture on it.
    # Remember to keep this reference.
    texture = load("res://my_texture.png")
    # Add it, centered.
    RenderingServer.canvas_item_add_texture_rect(ci_rid, Rect2(-texture.get_size() / 2, texture.get_size()), texture)
    # Add the item, rotated 45 degrees and translated.
    var xform = Transform2D().rotated(deg_to_rad(45)).translated(Vector2(20, 30))
    RenderingServer.canvas_item_set_transform(ci_rid, xform)
    # Reset physics interpolation for this item.
    RenderingServer.canvas_item_reset_physics_interpolation(ci_rid)

public partial class MyNode2D : Node2D
{
    // RenderingServer expects references to be kept around.
    private Texture2D _texture;

    public override void _Ready()
    {
        // Create a canvas item, child of this node.
        Rid ciRid = RenderingServer.CanvasItemCreate();
        // Make this node the parent.
        RenderingServer.CanvasItemSetParent(ciRid, GetCanvasItem());
        // Draw a texture on it.
        // Remember to keep this reference.
        _texture = ResourceLoader.Load<Texture2D>("res://my_texture.png");
        // Add it, centered.
        RenderingServer.CanvasItemAddTextureRect(ciRid, new Rect2(-_texture.GetSize() / 2, _texture.GetSize()), _texture.GetRid());
        // Add the item, rotated 45 degrees and translated.
        Transform2D xform = Transform2D.Identity.Rotated(Mathf.DegToRad(45)).Translated(new Vector2(20, 30));
        RenderingServer.CanvasItemSetTransform(ciRid, xform);
        // Reset physics interpolation for this item.
        RenderingServer.CanvasItemResetPhysicsInterpolation(ciRid);
    }
}

API Canvas Item trong server cho phép bạn thêm các primitive vẽ vào nó. Một khi đã thêm, chúng không thể bị sửa đổi. Item cần được xóa sạch và các primitive phải được thêm lại. Điều này không áp dụng cho việc đặt transform, vốn có thể thực hiện bao nhiêu lần tùy ý.

Các primitive được xóa theo cách này:

RenderingServer.canvas_item_clear(ci_rid)

RenderingServer.CanvasItemClear(ciRid);

Tạo instance một Mesh vào không gian 3D

Các API 3D khác với API 2D, vì vậy phải dùng API tạo instance.

extends Node3D


# RenderingServer expects references to be kept around.
var mesh


func _ready():
    # Create a visual instance (for 3D).
    var instance = RenderingServer.instance_create()
    # Set the scenario from the world. This ensures it
    # appears with the same objects as the scene.
    var scenario = get_world_3d().scenario
    RenderingServer.instance_set_scenario(instance, scenario)
    # Add a mesh to it.
    # Remember to keep this reference.
    mesh = load("res://my_mesh.obj")
    RenderingServer.instance_set_base(instance, mesh)
    # Move the mesh around.
    var xform = Transform3D(Basis(), Vector3(2, 3, 0))
    RenderingServer.instance_set_transform(instance, xform)

public partial class MyNode3D : Node3D
{
    // RenderingServer expects references to be kept around.
    private Mesh _mesh;

    public override void _Ready()
    {
        // Create a visual instance (for 3D).
        Rid instance = RenderingServer.InstanceCreate();
        // Set the scenario from the world. This ensures it
        // appears with the same objects as the scene.
        Rid scenario = GetWorld3D().Scenario;
        RenderingServer.InstanceSetScenario(instance, scenario);
        // Add a mesh to it.
        // Remember to keep this reference.
        _mesh = ResourceLoader.Load<Mesh>("res://my_mesh.obj");
        RenderingServer.InstanceSetBase(instance, _mesh.GetRid());
        // Move the mesh around.
        Transform3D xform = new Transform3D(Basis.Identity, new Vector3(2, 3, 0));
        RenderingServer.InstanceSetTransform(instance, xform);
    }
}

Tạo một RigidBody 2D và di chuyển sprite theo nó

Đoạn này tạo một class_RigidBody2D bằng API class_PhysicsServer2D và di chuyển một class_CanvasItem khi body di chuyển.

# PhysicsServer2D expects references to be kept around.
var body
var shape


func _body_moved(state, index):
    # Created your own canvas item; use it here.
    # `ci_rid` from the sprite example above needs to be moved to a
    # member variable (instead of within `_ready()`) so it can be referenced here.
    RenderingServer.canvas_item_set_transform(ci_rid, state.transform)


func _ready():
    # Create the body.
    body = PhysicsServer2D.body_create()
    PhysicsServer2D.body_set_mode(body, PhysicsServer2D.BODY_MODE_RIGID)
    # Add a shape.
    shape = PhysicsServer2D.rectangle_shape_create()
    # Set rectangle extents.
    PhysicsServer2D.shape_set_data(shape, Vector2(10, 10))
    # Make sure to keep the shape reference!
    PhysicsServer2D.body_add_shape(body, shape)
    # Set space, so it collides in the same space as current scene.
    PhysicsServer2D.body_set_space(body, get_world_2d().space)
    # Move initial position.
    PhysicsServer2D.body_set_state(body, PhysicsServer2D.BODY_STATE_TRANSFORM, Transform2D(0, Vector2(10, 20)))
    # Add the transform callback, when body moves
    # The last parameter is optional, can be used as index
    # if you have many bodies and a single callback.
    PhysicsServer2D.body_set_force_integration_callback(body, self, "_body_moved", 0)

    # Also create a sprite using RenderingServer here.
    # See the section above on creating a sprite.
    # ...

using Godot;

public partial class MyNode2D : Node2D
{
    private Rid _canvasItem;

    private void BodyMoved(PhysicsDirectBodyState2D state, int index)
    {
        // Created your own canvas item; use it here.
        // `ciRid` from the sprite example above needs to be moved to a
        // member variable (instead of within `_Ready()`) so it can be referenced here.
        RenderingServer.CanvasItemSetTransform(_canvasItem, state.Transform);
    }

    public override void _Ready()
    {
        // Create the body.
        var body = PhysicsServer2D.BodyCreate();
        PhysicsServer2D.BodySetMode(body, PhysicsServer2D.BodyMode.Rigid);
        // Add a shape.
        var shape = PhysicsServer2D.RectangleShapeCreate();
        // Set rectangle extents.
        PhysicsServer2D.ShapeSetData(shape, new Vector2(10, 10));
        // Make sure to keep the shape reference!
        PhysicsServer2D.BodyAddShape(body, shape);
        // Set space, so it collides in the same space as current scene.
        PhysicsServer2D.BodySetSpace(body, GetWorld2D().Space);
        // Move initial position.
        PhysicsServer2D.BodySetState(body, PhysicsServer2D.BodyState.Transform, new Transform2D(0, new Vector2(10, 20)));
        // Add the transform callback, when body moves
        // The last parameter is optional, can be used as index
        // if you have many bodies and a single callback.
        PhysicsServer2D.BodySetForceIntegrationCallback(body, new Callable(this, MethodName.BodyMoved), 0);

        // Also create a sprite using RenderingServer here.
        // See the section above on creating a sprite.
        // ...
    }
}

Phiên bản 3D sẽ rất tương tự, vì các server vật lý 2D và 3D giống hệt nhau (lần lượt dùng class_RigidBody3D và class_PhysicsServer3D).

Lấy dữ liệu từ các server

Cố gắng không bao giờ yêu cầu bất kỳ thông tin nào từ class_RenderingServer, class_PhysicsServer2D hoặc class_PhysicsServer3D bằng cách gọi hàm, trừ khi bạn biết mình đang làm gì. Các server này thường chạy bất đồng bộ để tăng hiệu năng, và việc gọi bất kỳ hàm nào trả về giá trị sẽ làm chúng đình trệ và buộc chúng xử lý mọi thứ đang chờ cho đến khi hàm thực sự được gọi. Điều này sẽ làm giảm hiệu năng nghiêm trọng nếu bạn gọi chúng mỗi frame (và sẽ không rõ ràng vì sao).

Vì lý do này, hầu hết API trong các server đó được thiết kế sao cho thậm chí không thể yêu cầu thông tin trả về, trừ khi đó là dữ liệu thực sự có thể lưu lại.
