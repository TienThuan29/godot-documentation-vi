Đang cập nhật

Nội dung trang này chưa được cập nhật cho Godot 4.7 và có thể đã lỗi thời. Nếu bạn biết cách cải thiện trang này hoặc xác nhận được rằng nó vẫn đúng, hãy gửi một pull request (bản tiếng Anh).

Tối ưu bằng MultiMesh

Với một lượng lớn instance (hàng nghìn) cần được xử lý liên tục (và cần giữ lại một mức độ kiểm soát nhất định), dùng trực tiếp server là cách tối ưu được khuyến nghị.

Khi số lượng đối tượng lên đến hàng trăm nghìn hoặc hàng triệu, không cách nào trong số này còn hiệu quả nữa. Dù vậy, tùy theo yêu cầu, vẫn còn một cách tối ưu khác.

MultiMesh

MultiMesh là một primitive vẽ duy nhất có thể vẽ tới hàng triệu đối tượng trong một lần. Nó cực kỳ hiệu quả vì dùng phần cứng GPU để thực hiện việc này.

Nhược điểm duy nhất là không thể thực hiện culling theo màn hình hay frustum cho từng instance riêng lẻ. Điều này nghĩa là hàng triệu đối tượng sẽ luôn luôn hoặc không bao giờ được vẽ, tùy thuộc vào khả năng hiển thị của toàn bộ MultiMesh. Có thể cung cấp một hình chữ nhật hiển thị tùy chỉnh cho chúng, nhưng khả năng hiển thị sẽ luôn là tất cả hoặc không có gì.

Nếu các đối tượng đủ đơn giản (chỉ vài vertex), điều này thường không phải vấn đề lớn vì hầu hết GPU hiện đại đều được tối ưu cho trường hợp sử dụng này. Một cách khắc phục là tạo nhiều MultiMesh cho các khu vực khác nhau của thế giới.

Cũng có thể thực thi một số logic bên trong vertex shader (dùng các hằng số tích hợp INSTANCE_ID hoặc INSTANCE_CUSTOM). Để xem ví dụ về tạo hoạt ảnh cho hàng nghìn đối tượng trong một MultiMesh, xem bài hướng dẫn Tạo hoạt ảnh cho hàng nghìn con cá. Thông tin cho shader có thể được cung cấp qua texture (có các định dạng Image dấu phẩy động rất lý tưởng cho việc này).

Một lựa chọn khác là dùng GDExtension và C++, cách này sẽ cực kỳ hiệu quả (có thể đặt toàn bộ trạng thái cho tất cả đối tượng bằng bộ nhớ tuyến tính qua hàm RenderingServer.multimesh_set_buffer()). Bằng cách này, mảng có thể được tạo bằng nhiều luồng, rồi được đặt trong một lần gọi, mang lại hiệu quả cache cao.

Cuối cùng, không bắt buộc tất cả instance của MultiMesh đều phải hiển thị. Số lượng instance hiển thị có thể được kiểm soát bằng thuộc tính MultiMesh.visible_instance_count. Quy trình điển hình là cấp phát số lượng instance tối đa sẽ dùng, rồi thay đổi số lượng hiển thị tùy theo số lượng hiện đang cần.

Ví dụ về MultiMesh

Đây là một ví dụ dùng MultiMesh từ code. Các ngôn ngữ khác ngoài GDScript có thể hiệu quả hơn với hàng triệu đối tượng, nhưng với vài nghìn đối tượng thì GDScript vẫn ổn.

extends MultiMeshInstance3D


func _ready():
    # Create the multimesh.
    multimesh = MultiMesh.new()
    # Set the format first.
    multimesh.transform_format = MultiMesh.TRANSFORM_3D
    # Set the mesh that will be duplicated.
    multimesh.mesh = BoxMesh.new()
    # Then resize (otherwise, changing the format is not allowed).
    multimesh.instance_count = 10000
    # Maybe not all of them should be visible at first.
    multimesh.visible_instance_count = 1000

    # Set the transform of the instances.
    for i in multimesh.visible_instance_count:
        multimesh.set_instance_transform(i, Transform3D(Basis(), Vector3(i * 20, 0, 0)))

using Godot;

public partial class MyMultiMeshInstance3D : MultiMeshInstance3D
{
    public override void _Ready()
    {
        // Create the multimesh.
        Multimesh = new MultiMesh();
        // Set the format first.
        Multimesh.TransformFormat = MultiMesh.TransformFormatEnum.Transform3D;
        // Then resize (otherwise, changing the format is not allowed)
        Multimesh.InstanceCount = 1000;
        // Maybe not all of them should be visible at first.
        Multimesh.VisibleInstanceCount = 1000;

        // Set the transform of the instances.
        for (int i = 0; i < Multimesh.VisibleInstanceCount; i++)
        {
            Multimesh.SetInstanceTransform(i, new Transform3D(Basis.Identity, new Vector3(i * 20, 0, 0)));
        }
    }
}
