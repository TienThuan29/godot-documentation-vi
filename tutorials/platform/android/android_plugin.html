Plugin Godot Android

Giới thiệu

Plugin Android là công cụ mạnh mẽ để mở rộng khả năng của Godot engine bằng cách khai thác các chức năng do nền tảng và hệ sinh thái Android cung cấp.

Ví dụ, trong Godot 4, plugin Android được dùng để hỗ trợ nhiều nền tảng XR chạy Android mà không làm nặng codebase lõi bằng mã hoặc tệp nhị phân riêng của từng nhà cung cấp.

Plugin Android

Phiên bản 1 (v1) của hệ thống plugin Android được giới thiệu trong Godot 3 và tương thích với Godot 4.0 và 4.1. Phiên bản đó cho phép nhà phát triển bổ sung cho Godot engine các chức năng Java, Kotlin và native.

Bắt đầu từ Godot 4.2, các plugin Android xây dựng trên kiến trúc v1 đã bị deprecated (không còn được khuyến khích dùng). Thay vào đó, Godot 4.2 giới thiệu kiến trúc Phiên bản 2 (v2) mới cho plugin Android.

Kiến trúc v2

Ghi chú

Plugin Godot Android tận dụng hệ thống build Gradle.

Kế thừa từ kiến trúc v1 trước đó, plugin Android tiếp tục được tạo ra từ thư viện lưu trữ Android (Android archive library).

Về cốt lõi, một plugin Godot Android v2 là một thư viện Android phụ thuộc vào thư viện Godot Android, kèm một manifest thư viện Android tùy chỉnh.

Kiến trúc này cho phép plugin Android mở rộng chức năng của engine với:

  • API nền tảng Android

  • Thư viện Android

  • Thư viện Kotlin và Java

  • Thư viện native (qua JNI)

  • Thư viện GDExtension

Mỗi plugin có một lớp init kế thừa từ lớp GodotPlugin do thư viện Godot Android cung cấp.

Lớp GodotPlugin cung cấp các API để truy cập instance Godot đang chạy và móc vào vòng đời của nó. Lớp này được Godot engine tải lúc chạy.

Định dạng đóng gói v2

Plugin Android v1 cần một tệp cấu hình gdap tùy chỉnh để trình chỉnh sửa Godot phát hiện và tải chúng. Tuy nhiên cách tiếp cận này có một số nhược điểm, chủ yếu là thiếu linh hoạt và đi lệch khỏi quy trình định dạng, phân phối và cài đặt EditorExportPlugin sẵn có của Godot.

Vấn đề này đã được giải quyết với plugin Android v2 bằng cách deprecate cơ chế đóng gói và cấu hình gdap, thay bằng định dạng đóng gói EditorExportPlugin sẵn có của Godot. Đồng thời, API EditorExportPlugin cũng đã được mở rộng để hỗ trợ đúng cách các plugin Android.

Build một plugin Android v2

Một template dự án github được cung cấp tại https://github.com/m4gr3d/Godot-Android-Plugin-Template để bắt đầu nhanh việc build plugin Godot Android cho Godot 4.2+. Bạn có thể làm theo README của template để thiết lập dự án plugin Godot Android của riêng mình.

Để bạn hiểu rõ hơn, đây là phân tích các bước dùng để tạo template dự án:

  1. Tạo một module thư viện Android theo hướng dẫn này.

  2. Thêm thư viện Godot Android làm dependency bằng cách cập nhật gradle tệp build của module:

    dependencies {
    implementation("org.godotengine:godot:4.2.0.stable")
}

Thư viện Godot Android được lưu trữ trên MavenCentral và được cập nhật cho mỗi bản phát hành.

  1. Tạo GodotAndroidPlugin, một lớp init cho plugin kế thừa GodotPlugin.

    • Nếu plugin cung cấp các phương thức Kotlin hoặc Java để gọi từ GDScript, chúng phải được chú thích bằng @UsedByGodot. Tên được gọi từ GDScript phải khớp chính xác với tên phương thức. Không có cơ chế tự chuyển snake_case sang camelCase. Ví dụ, từ GDScript:

      if Engine.has_singleton("MyPlugin"):
    var singleton = Engine.get_singleton("MyPlugin")
    print(singleton.myPluginFunction("World"))

    • Nếu plugin dùng signal, lớp init phải trả về tập signal được dùng bằng cách ghi đè GodotPlugin::getPluginSignals(). Để phát signal, plugin có thể dùng phương thức GodotPlugin::emitSignal(...).

  2. Cập nhật AndroidManifest.xml tệp của plugin với meta-data sau:

    <meta-data
    android:name="org.godotengine.plugin.v2.[PluginName]"
    android:value="[plugin.init.ClassFullName]" />

Trong đó:

  • PluginName là tên của plugin

  • plugin.init.ClassFullName là tên thành phần đầy đủ (package + tên lớp) của lớp init của plugin (ví dụ: org.godotengine.plugin.android.template.GodotAndroidPlugin).

  1. Tạo cấu hình EditorExportPlugin để đóng gói plugin. Các bước tạo cấu hình có thể xem trong phần Packaging a v2 Android plugin.

Build plugin Android v2 với khả năng GDExtension

Tương tự hỗ trợ GDNative trong plugin Android v1, plugin Android v2 hỗ trợ tích hợp các khả năng GDExtension.

Một template dự án github được cung cấp tại https://github.com/m4gr3d/GDExtension-Android-Plugin-Template để bắt đầu nhanh việc build plugin GDExtension Android cho Godot 4.2+. Bạn có thể làm theo README của template để thiết lập dự án plugin Godot Android của riêng mình.

Chuyển plugin Android v1 sang v2

Hãy làm theo các bước sau nếu bạn có một plugin Android v1 muốn chuyển sang v2:

  1. Cập nhật tệp manifest của plugin:

    • Đổi tiền tố org.godotengine.plugin.v1 thành org.godotengine.plugin.v2

  2. Cập nhật build dependency thư viện Godot Android:

    • Bạn có thể tiếp tục dùng tệp nhị phân godot-lib.<version>.<status>.aar từ trang tải xuống của Godot nếu muốn. Hãy đảm bảo nó được cập nhật lên phiên bản ổn định mới nhất.

    • Hoặc bạn có thể chuyển sang dependency do MavenCentral cung cấp:

dependencies {
    implementation("org.godotengine:godot:4.2.0.stable")
}

  1. Sau khi cập nhật dependency thư viện Godot Android, hãy sync hoặc build plugin và xử lý mọi lỗi biên dịch:

    • Instance Godot do GodotPlugin::getGodot() cung cấp không còn truy cập được tham chiếu android.content.Context. Hãy dùng GodotPlugin::getActivity() thay thế.

  2. Xóa (các) tệp cấu hình gdap và làm theo hướng dẫn trong phần Packaging a v2 Android plugin để thiết lập cấu hình plugin.

Đóng gói một plugin Android v2

Như đã nói, plugin Android v2 giờ được cung cấp cho trình chỉnh sửa Godot dưới dạng plugin EditorExportPlugin, nên nó có chung nhiều bước đóng gói.

  1. Thêm các tệp nhị phân đầu ra của plugin vào thư mục plugin (ví dụ: trong addons/<plugin_name>/)

  2. Thêm tool script cho chức năng xuất vào thư mục plugin (ví dụ: trong addons/<plugin_name>/)

    • Script được tạo phải là script @tool, nếu không nó sẽ không hoạt động đúng

    • Tool script cho việc xuất được dùng để cấu hình plugin Android và móc nó vào quá trình xuất của trình chỉnh sửa Godot. Nó sẽ trông giống như sau:

    @tool
extends EditorPlugin

# A class member to hold the editor export plugin during its lifecycle.
var export_plugin : AndroidExportPlugin

func _enter_tree():
    # Initialization of the plugin goes here.
    export_plugin = AndroidExportPlugin.new()
    add_export_plugin(export_plugin)


func _exit_tree():
    # Clean-up of the plugin goes here.
    remove_export_plugin(export_plugin)
    export_plugin = null


class AndroidExportPlugin extends EditorExportPlugin:
    # Plugin's name.
    var _plugin_name = "<plugin_name>"

    # Specifies which platform is supported by the plugin.
    func _supports_platform(platform):
        if platform is EditorExportPlatformAndroid:
            return true
        return false

    # Return the paths of the plugin's AAR binaries relative to the 'addons' directory.
    func _get_android_libraries(platform, debug):
        if debug:
            return PackedStringArray(["<paths_to_debug_android_plugin_aar_binaries>"])
        else:
            return PackedStringArray(["<paths_to_release_android_plugin_aar_binaries>"])

    # Return the plugin's name.
    func _get_name():
        return _plugin_name

    • Đây là tập API EditorExportPlugin liên quan nhất để dùng trong tool script này:

      • _supports_platform:
        Trả về true nếu plugin hỗ trợ nền tảng đã cho. Với plugin Android, phương thức này phải trả về true khi platform là EditorExportPlatformAndroid
      • _get_android_libraries:
        Lấy đường dẫn cục bộ của các tệp nhị phân thư viện Android (tệp AAR) do plugin cung cấp
      • _get_android_dependencies:
        Lấy tập maven dependency Android (ví dụ: org.godot.example:my-plugin:0.0.0) do plugin cung cấp
      • _get_android_dependencies_maven_repos:
        Lấy url của các maven repo cho các dependency Android do _get_android_dependencies cung cấp
      • _get_android_manifest_activity_element_contents:
        Cập nhật nội dung của phần tử <activity> trong Android manifest được tạo ra
      • _get_android_manifest_application_element_contents:
        Cập nhật nội dung của phần tử <application> trong Android manifest được tạo ra
      • _get_android_manifest_element_contents:
        Cập nhật nội dung của phần tử <manifest> trong Android manifest được tạo ra

      Các phương thức _get_android_manifest_* cho phép plugin tự động cung cấp các thay đổi cho manifest của ứng dụng, và các thay đổi này được giữ nguyên khi trình chỉnh sửa Godot được cập nhật, giải quyết một vấn đề tồn tại lâu nay của plugin Android v1.

  3. Tạo tệp plugin.cfg. Đây là tệp INI chứa metadata về plugin của bạn:

[plugin]

name="<plugin_name>"
description="<plugin_description>"
author="<plugin_author>"
version="<plugin_version>"
script="<relative_path_to_the_export_tool_script>"

Để tham khảo, đây là cấu trúc thư mục của template dự án plugin Godot Android. Khi build, nội dung của thư mục export_scripts_template cùng các tệp nhị phân plugin được tạo ra sẽ được sao chép vào thư mục addons/<plugin_name>:

export_scripts_template/
|
+--export_plugin.gd         # export plugin tool script
|
+--plugin.cfg               # plugin INI file

Đóng gói plugin Android v2 với khả năng GDExtension

Với GDExtension, chúng ta làm theo các bước giống như Packaging a v2 Android plugin và thêm tệp cấu hình GDExtension vào cùng vị trí với plugin.cfg.

Để tham khảo, đây là cấu trúc thư mục của template dự án plugin GDExtension Android. Khi build, nội dung của thư mục export_scripts_template cùng các tệp nhị phân plugin được tạo ra sẽ được sao chép vào thư mục addons/<plugin_name>:

export_scripts_template/
|
+--export_plugin.gd         # export plugin tool script
|
+--plugin.cfg               # plugin INI file
|
+--plugin.gdextension       # GDExtension config file

Đây là nội dung tệp cấu hình plugin.gdextension cần có:

[configuration]

entry_symbol = "plugin_library_init"
compatibility_minimum = "4.2"
android_aar_plugin = true

[libraries]

android.debug.arm64 = "res://addons/GDExtensionAndroidPluginTemplate/bin/debug/arm64-v8a/libGDExtensionAndroidPluginTemplate.so"
android.release.arm64 = "res://addons/GDExtensionAndroidPluginTemplate/bin/release/arm64-v8a/libGDExtensionAndroidPluginTemplate.so"
...

Đáng chú ý là trường android_aar_plugin, cho biết module GDExtension này được cung cấp như một phần của plugin Android v2. Trong quá trình xuất, trường này cho trình chỉnh sửa Godot biết rằng các thư viện chia sẻ native của GDExtension được xuất bởi các tệp nhị phân AAR của plugin Android.

Với plugin GDExtension Android, lớp init của plugin phải ghi đè GodotPlugin::getPluginGDExtensionLibrariesPaths() và trả về đường dẫn tới các tệp cấu hình thư viện GDExtension đi kèm (*.gdextension).

Các đường dẫn phải là tương đối so với thư mục assets của thư viện Android. Lúc chạy, plugin sẽ cung cấp các đường dẫn này cho Godot engine, engine sẽ dùng chúng để tải và khởi tạo các thư viện GDExtension đi kèm.

Sử dụng một plugin Android v2

Ghi chú

  • Yêu cầu Godot 4.2 trở lên

  • Plugin Android v2 yêu cầu dùng quy trình build Gradle.

  • Các template dự án github được cung cấp có kèm dự án Godot demo để thử nghiệm nhanh.

  1. Sao chép thư mục đầu ra của plugin (addons/<plugin_name>) vào thư mục của dự án Godot đích

  2. Mở dự án trong trình chỉnh sửa Godot; trình chỉnh sửa sẽ phát hiện plugin

  3. Vào Project -> Project Settings... -> Plugins và đảm bảo plugin đã được bật

  4. Cài đặt Android build template của Godot bằng cách nhấp vào Project -> Install Android Build Template...

  5. Vào Project -> Export...

  6. Trong cửa sổ Export, tạo một Android export preset

  7. Trong Android export preset, cuộn tới Gradle Build và đặt Use Gradle Build thành true

  8. Cập nhật các script của dự án khi cần để truy cập chức năng của plugin. Ví dụ:

if Engine.has_singleton("MyPlugin"):
        var singleton = Engine.get_singleton("MyPlugin")
        print(singleton.myPluginFunction("World"))

  1. Kết nối thiết bị Android với máy tính và chạy dự án trên đó

Sử dụng plugin Android v2 như một thư viện Android

Vì cũng là thư viện Android, plugin Godot Android v2 có thể được tách khỏi phần đóng gói EditorExportPlugin và cung cấp dưới dạng tệp nhị phân AAR thuần để các ứng dụng Android dùng làm thư viện cùng với thư viện Godot Android.

Nếu nhắm tới trường hợp sử dụng này, hãy nhớ kèm theo hướng dẫn bổ sung về cách đưa các tệp nhị phân AAR vào (ví dụ: các bổ sung tùy chỉnh cho manifest của ứng dụng Android).

Mẹo và hướng dẫn

Đơn giản hóa việc truy cập các API Java / Kotlin được cung cấp

Để việc truy cập các API Java / Kotlin được cung cấp trong trình chỉnh sửa Godot dễ dàng hơn, bạn nên cung cấp một (hoặc nhiều) lớp wrapper gdscript để người dùng plugin giao tiếp.

Ví dụ:

class_name PluginInterface extends Object

## Interface used to access the functionality provided by this plugin.

var _plugin_name = "GDExtensionAndroidPluginTemplate"
var _plugin_singleton

func _init():
    if Engine.has_singleton(_plugin_name):
        _plugin_singleton = Engine.get_singleton(_plugin_name)
    else:
        printerr("Initialization error: unable to access the java logic")

## Print a 'Hello World' message to the logcat.
func helloWorld():
    if _plugin_singleton:
        _plugin_singleton.helloWorld()
    else:
        printerr("Initialization error")

Hỗ trợ dùng chức năng GDExtension trong trình chỉnh sửa Godot

Nếu định dùng chức năng GDExtension trong trình chỉnh sửa Godot, bạn nên biên dịch các tệp nhị phân native của GDExtension không chỉ cho Android mà còn cho hệ điều hành mà nhà phát triển / người dùng định chạy trình chỉnh sửa Godot. Nếu không, nhà phát triển / người dùng có thể không viết được mã truy cập plugin từ bên trong trình chỉnh sửa Godot.

Việc này có thể bao gồm tạo các plugin giả (dummy) cho hệ điều hành host chỉ để API được công bố cho trình chỉnh sửa. Bạn có thể tham khảo template github godot-cpp-template để biết cách làm.

Các kiểu dữ liệu được hỗ trợ

Mọi kiểu dữ liệu đều được hỗ trợ. Các kiểu thông dụng được ánh xạ sang kiểu tương đương trong Godot (ví dụ, String[] được ánh xạ sang PackedStringArray()), còn với các kiểu khác, bạn có thể dùng JavaClassWrapper để truy cập.

Godot bị crash khi tải

Kiểm tra adb logcat để tìm các vấn đề có thể xảy ra.
