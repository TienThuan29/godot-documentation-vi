Xuất cho máy chủ chuyên dụng

Nếu bạn muốn chạy một máy chủ chuyên dụng (dedicated server) cho dự án trên một máy không có GPU hoặc display server, bạn sẽ cần chạy Godot với display server headless và audio driver Dummy.

Kể từ Godot 4.0, việc này có thể thực hiện bằng cách chạy tệp nhị phân Godot trên bất kỳ nền tảng nào với tham số dòng lệnh --headless, hoặc chạy một dự án đã được xuất dưới dạng máy chủ chuyên dụng. Bạn không cần dùng tệp nhị phân máy chủ chuyên biệt nữa, không giống như Godot 3.x.

Trình chỉnh sửa và export template

Bạn có thể dùng tệp nhị phân trình chỉnh sửa hoặc export template (debug hoặc release) ở chế độ headless. Nên dùng loại nào tùy thuộc vào trường hợp sử dụng của bạn:

  • Export template: Dùng loại này để chạy máy chủ chuyên dụng. Nó không chứa chức năng trình chỉnh sửa, do đó nhỏ hơn và được tối ưu hơn.

  • Editor: Tệp nhị phân này chứa chức năng trình chỉnh sửa và được dùng để xuất dự án. Tệp nhị phân này có thể dùng để chạy máy chủ chuyên dụng, nhưng không được khuyến nghị vì nó lớn hơn và kém tối ưu hơn.

Các cách xuất

Có hai cách để xuất dự án cho máy chủ:

  • Tạo một export preset riêng cho nền tảng sẽ chạy máy chủ, sau đó xuất dự án như bình thường.

  • Chỉ xuất tệp PCK, tốt nhất là cho nền tảng trùng với nền tảng sẽ chạy máy chủ. Đặt tệp PCK này vào cùng thư mục với một tệp nhị phân export template, đổi tên tệp nhị phân cho trùng với tên tệp PCK (không tính phần mở rộng), rồi chạy tệp nhị phân đó.

Cả hai cách đều cho kết quả giống hệt nhau. Phần còn lại của trang sẽ tập trung vào cách thứ nhất.

Xem Xuất dự án để biết thêm thông tin.

Xuất dự án cho dedicated server

Nếu bạn xuất dự án như bình thường khi nhắm đến máy chủ, bạn sẽ thấy tệp PCK lớn y như của client. Đó là vì nó bao gồm tất cả resource, kể cả những resource mà máy chủ không cần (chẳng hạn dữ liệu texture). Ngoài ra, chế độ headless sẽ không tự động được dùng; người dùng sẽ phải chỉ định --headless để đảm bảo không có cửa sổ nào được tạo ra.

Nhiều resource như texture có thể được loại bỏ khỏi tệp PCK để giảm đáng kể kích thước. Godot cung cấp cách làm điều này cho texture và material theo cách vẫn giữ nguyên các tham chiếu trong tệp scene hoặc resource (tích hợp sẵn hoặc bên ngoài).

Để bắt đầu, hãy đảm bảo bạn có một export preset riêng cho máy chủ, sau đó chọn nó, vào tab Resources và thay đổi chế độ xuất:

Khi chọn chế độ xuất này, feature tag dedicated_server sẽ tự động được thêm vào dự án đã xuất.

Ghi chú

Nếu bạn không muốn dùng chế độ xuất này nhưng vẫn muốn có feature tag, bạn có thể ghi tên dedicated_server vào tab Features của export preset. Điều này cũng sẽ bắt buộc dùng --headless khi chạy dự án đã xuất.

Sau khi chọn chế độ xuất này, bạn sẽ thấy danh sách các resource trong dự án:

Đánh dấu một ô cho phép bạn ghi đè các tùy chọn cho tệp hoặc thư mục được chỉ định. Việc đánh dấu các ô không ảnh hưởng đến những tệp nào được xuất; điều đó do các tùy chọn được chọn cho từng ô quyết định.

Theo mặc định, các tệp trong một thư mục được đánh dấu sẽ tự động dùng tùy chọn của thư mục cha, được biểu thị bằng hậu tố (Inherited) sau tên tùy chọn (và tên tùy chọn bị làm mờ). Để thay đổi tùy chọn cho một tệp có tùy chọn đang được kế thừa, trước tiên bạn phải đánh dấu ô bên cạnh nó.

  • Strip Visuals: Xuất resource này, với các tệp hình ảnh (texture và material) được thay bằng các lớp giữ chỗ (placeholder). Các lớp placeholder lưu kích thước ảnh (vì đôi khi nó được dùng để định vị các phần tử trong scene 2D), ngoài ra không lưu gì khác.

  • Keep: Xuất resource này như bình thường, giữ nguyên các tệp hình ảnh.

  • Remove: Tệp không được đưa vào PCK. Tùy chọn này hữu ích để bỏ qua các scene và resource mà chỉ client cần. Nếu làm vậy, hãy đảm bảo máy chủ không tham chiếu đến các scene và resource chỉ dành cho client này theo bất kỳ cách nào.

Khuyến nghị chung là dùng Strip Visuals bất cứ khi nào có thể, trừ khi máy chủ cần truy cập dữ liệu ảnh như màu của các pixel. Ví dụ, nếu máy chủ của bạn tạo dữ liệu va chạm dựa trên nội dung của một ảnh, bạn cần dùng Keep cho ảnh cụ thể đó.

Mẹo

Để kiểm tra cấu trúc file của PCK đã xuất, hãy dùng nút Export PCK/ZIP... với phần mở rộng .zip, rồi mở file ZIP thu được bằng trình quản lý file.

Cảnh báo

Hãy cẩn thận khi dùng chế độ Remove, vì các scene/resource tham chiếu tới file đã bị xóa sẽ không thể tải thành công nữa.

Nếu bạn muốn loại bỏ các resource cụ thể nhưng vẫn để các scene tải được khi thiếu chúng, bạn sẽ phải xóa tham chiếu trong file scene và tải các file vào thuộc tính của node bằng load() trong một script. Cách này có thể dùng để loại bỏ các resource mà Godot chưa hỗ trợ thay thế bằng placeholder, chẳng hạn như âm thanh.

Loại bỏ texture thường là việc có tác động lớn nhất tới kích thước PCK, vì vậy bạn nên dùng Strip Visuals trước tiên.

Khởi động dedicated server

Nếu cả client và server đều nằm trong cùng một dự án Godot, bạn sẽ phải thêm cách để khởi động server trực tiếp bằng một tham số dòng lệnh.

Nếu bạn đã xuất dự án bằng chế độ xuất Export as dedicated server (hoặc đã thêm dedicated_server làm feature tag tùy chỉnh), bạn có thể dùng feature tag dedicated_server để phát hiện liệu PCK dành cho dedicated server có đang được sử dụng hay không:

# Note: Feature tags are case-sensitive.
if OS.has_feature("dedicated_server"):
    # Run your server startup code here...
    pass

// Note: Feature tags are case-sensitive.
if (OS.HasFeature("dedicated_server"))
{
    // Run your server startup code here...
}

Nếu bạn cũng muốn chạy server khi dùng tham số dòng lệnh có sẵn --headless, hãy thêm đoạn code sau vào phương thức _ready() của scene chính (hoặc của một autoload):

if DisplayServer.get_name() == "headless":
    # Run your server startup code here...
    #
    # Using this check, you can start a dedicated server by running
    # a Godot binary (editor or export template) with the `--headless`
    # command-line argument.
    pass

using System.Linq;

if (DisplayServer.GetName() == "headless")
{
    // Run your server startup code here...
    //
    // Using this check, you can start a dedicated server by running
    // a Godot binary (editor or export template) with the `--headless`
    // command-line argument.
}

Nếu bạn muốn dùng một tham số dòng lệnh tùy chỉnh, hãy thêm đoạn code sau vào phương thức _ready() của scene chính (hoặc của một autoload):

if "--server" in OS.get_cmdline_user_args():
    # Run your server startup code here...
    #
    # Using this check, you can start a dedicated server by running
    # a Godot binary (editor or export template) with the `--server`
    # command-line argument.
    pass

using System.Linq;

if (OS.GetCmdlineUserArgs().Contains("--server"))
{
    // Run your server startup code here...
    //
    // Using this check, you can start a dedicated server by running
    // a Godot binary (editor or export template) with the `--server`
    // command-line argument.
}

Bạn nên thêm ít nhất một trong các tham số dòng lệnh trên để khởi động server, vì nó có thể dùng để kiểm thử chức năng server từ dòng lệnh mà không cần xuất dự án.

Nếu client và server là hai dự án Godot riêng biệt, server của bạn rất có thể nên được cấu hình sao cho việc chạy scene chính sẽ tự động khởi động server.

Các bước tiếp theo

Trên Linux, để dedicated server tự khởi động lại sau khi bị crash hoặc khi hệ thống khởi động lại, bạn có thể tạo một systemd service. Cách này cũng giúp bạn xem log của server thuận tiện hơn, với tính năng xoay vòng log tự động do systemd cung cấp. Khi làm cho dự án có thể chạy dưới dạng systemd service, bạn cũng nên bật cài đặt dự án application/run/flush_stdout_on_print. Nhờ vậy, journald (dịch vụ ghi log của systemd) có thể thu thập log trong khi tiến trình đang chạy.

Nếu đã có kinh nghiệm với container, bạn cũng có thể cân nhắc đóng gói dedicated server trong một container Docker. Nhờ vậy, nó có thể được dùng dễ dàng hơn trong một hệ thống tự động mở rộng quy mô (nằm ngoài phạm vi bài hướng dẫn này).
