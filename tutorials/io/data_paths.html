Đường dẫn file trong dự án Godot

Trang này giải thích cách hoạt động của đường dẫn file trong các dự án Godot. Bạn sẽ học cách truy cập đường dẫn trong dự án bằng ký hiệu res:// và user://, và nơi Godot lưu các file dự án và file trình chỉnh sửa trên hệ thống của bạn và của người dùng.

Dấu phân cách đường dẫn

Để hỗ trợ nhiều nền tảng dễ dàng hơn, Godot dùng dấu phân cách đường dẫn kiểu UNIX (dấu gạch chéo /). Chúng hoạt động trên mọi nền tảng, kể cả Windows.

Thay vì viết đường dẫn như C:\Projects\Game, trong Godot bạn nên viết C:/Projects/Game.

Dấu phân cách đường dẫn kiểu Windows (dấu gạch chéo ngược \) cũng được hỗ trợ trong một số phương thức liên quan đến đường dẫn, nhưng chúng cần được viết đôi (\\), vì \ thường được dùng làm ký tự escape cho các ký tự có ý nghĩa đặc biệt.

Điều này giúp bạn có thể làm việc với đường dẫn được trả về từ các ứng dụng Windows khác. Chúng tôi vẫn khuyên bạn chỉ dùng dấu gạch chéo xuôi trong code của mình để đảm bảo mọi thứ hoạt động như mong muốn.

Mẹo

Lớp String cung cấp hơn chục phương thức để làm việc với các chuỗi biểu diễn đường dẫn file:

  • String.filecasecmp_to()

  • String.filenocasecmp_to()

  • String.get_base_dir()

  • String.get_basename()

  • String.get_extension()

  • String.get_file()

  • String.is_absolute_path()

  • String.is_relative_path()

  • String.is_valid_filename()

  • String.path_join()

  • String.simplify_path()

  • String.validate_filename()

Truy cập file trong thư mục dự án (res://)

Godot coi một dự án tồn tại trong bất kỳ thư mục nào chứa file văn bản project.godot, ngay cả khi file đó rỗng. Thư mục chứa file này là thư mục gốc của dự án.

Bạn có thể truy cập bất kỳ file nào tương đối với nó bằng cách viết đường dẫn bắt đầu bằng res://, viết tắt của resources. Ví dụ, bạn có thể truy cập file ảnh character.png nằm trong thư mục gốc của dự án trong code bằng đường dẫn sau: res://character.png.

Truy cập dữ liệu người dùng lâu dài (user://)

Để lưu các file dữ liệu lâu dài, như file save hoặc cài đặt của người chơi, bạn nên dùng user:// thay vì res:// làm tiền tố đường dẫn. Đó là vì khi game đang chạy, hệ thống file của dự án nhiều khả năng sẽ ở chế độ chỉ đọc.

Tiền tố user:// trỏ tới một thư mục khác trên thiết bị của người dùng. Khác với res://, thư mục mà user:// trỏ tới được tạo tự động và đảm bảo có thể ghi được, ngay cả trong dự án đã xuất.

Vị trí của thư mục user:// phụ thuộc vào cấu hình trong Project Settings:

  • Theo mặc định, thư mục user:// được tạo trong đường dẫn dữ liệu trình chỉnh sửa của Godot, trong thư mục app_userdata/[project_name]. Đây là mặc định để các dự án prototype và thử nghiệm được giữ gọn trong thư mục dữ liệu của Godot.

  • Nếu application/config/use_custom_user_dir được bật trong Project Settings, thư mục user:// được tạo bên cạnh đường dẫn dữ liệu trình chỉnh sửa của Godot, tức là ở vị trí chuẩn cho dữ liệu ứng dụng.

    • Theo mặc định, tên thư mục sẽ được suy ra từ tên dự án, nhưng có thể tùy chỉnh thêm bằng application/config/custom_user_dir_name. Đường dẫn này có thể chứa dấu phân cách đường dẫn, nên bạn có thể dùng nó, ví dụ để nhóm các dự án của một studio theo cấu trúc Studio Name/Game Name.

Trên nền tảng desktop, đường dẫn thư mục thực tế của user:// là:

Kiểu

Location

Mặc định
Windows: %APPDATA%\Godot\app_userdata\[project_name]
macOS: ~/Library/Application Support/Godot/app_userdata/[project_name]
Linux: ~/.local/share/godot/app_userdata/[project_name]

Thư mục tùy chỉnh
Windows: %APPDATA%\[project_name]
macOS: ~/Library/Application Support/[project_name]
Linux: ~/.local/share/[project_name]

Thư mục và tên tùy chỉnh
Windows: %APPDATA%\[custom_user_dir_name]
macOS: ~/Library/Application Support/[custom_user_dir_name]
Linux: ~/.local/share/[custom_user_dir_name]

[project_name] dựa trên tên ứng dụng được định nghĩa trong Project Settings, nhưng bạn có thể ghi đè nó cho từng nền tảng bằng feature tag.

Trên nền tảng di động, đường dẫn này là duy nhất cho dự án và các ứng dụng khác không thể truy cập vì lý do bảo mật.

Trên bản xuất HTML5, user:// sẽ tham chiếu tới một hệ thống file ảo được lưu trên thiết bị qua IndexedDB. (Vẫn có thể tương tác với hệ thống file chính thông qua singleton JavaScriptBridge.)

Chuyển đổi đường dẫn thành đường dẫn tuyệt đối hoặc đường dẫn "cục bộ"

Bạn có thể dùng ProjectSettings.globalize_path() để chuyển một đường dẫn "cục bộ" như res://path/to/file.txt thành đường dẫn tuyệt đối của hệ điều hành. Ví dụ, ProjectSettings.globalize_path() có thể được dùng để mở các đường dẫn "cục bộ" trong trình quản lý file của hệ điều hành bằng OS.shell_open(), vì nó chỉ chấp nhận đường dẫn gốc của hệ điều hành.

Để chuyển một đường dẫn tuyệt đối của hệ điều hành thành đường dẫn "cục bộ" bắt đầu bằng res:// hoặc user://, hãy dùng ProjectSettings.localize_path(). Cách này chỉ hoạt động với đường dẫn tuyệt đối trỏ tới file hoặc thư mục trong thư mục gốc của dự án hoặc thư mục user://.

Đường dẫn dữ liệu trình chỉnh sửa

Trình chỉnh sửa dùng các đường dẫn khác nhau cho dữ liệu trình chỉnh sửa, cài đặt trình chỉnh sửa và cache, tùy theo nền tảng. Theo mặc định, các đường dẫn này là:

Kiểu

Location

Dữ liệu của trình chỉnh sửa
Windows: %APPDATA%\Godot\
macOS: ~/Library/Application Support/Godot/
Linux: ~/.local/share/godot/

Cài đặt trình chỉnh sửa
Windows: %APPDATA%\Godot\
macOS: ~/Library/Application Support/Godot/
Linux: ~/.config/godot/

Cache
Windows: %TEMP%\Godot\
macOS: ~/Library/Caches/Godot/
Linux: ~/.cache/godot/

  • Dữ liệu trình chỉnh sửa chứa export template và dữ liệu riêng của từng dự án.

  • Cài đặt trình chỉnh sửa chứa file cấu hình cài đặt chính của trình chỉnh sửa cùng nhiều tùy chỉnh riêng của người dùng khác (bố cục trình chỉnh sửa, feature profile, script template, v.v.).

  • Cache chứa dữ liệu do trình chỉnh sửa tạo ra hoặc được lưu tạm thời. Có thể xóa nó một cách an toàn khi Godot đã đóng.

Godot tuân thủ XDG Base Directory Specification trên Linux/*BSD. Bạn có thể ghi đè các biến môi trường XDG_DATA_HOME, XDG_CONFIG_HOME và XDG_CACHE_HOME để thay đổi đường dẫn dữ liệu trình chỉnh sửa và dự án.

Ghi chú

Nếu bạn dùng Godot đóng gói dạng Flatpak, đường dẫn dữ liệu trình chỉnh sửa sẽ nằm trong các thư mục con của ~/.var/app/org.godotengine.Godot/.

Chế độ tự chứa (self-contained)

Nếu bạn tạo một file tên ._sc_ hoặc _sc_ trong cùng thư mục với file nhị phân của trình chỉnh sửa (hoặc trong MacOS/Contents/ đối với gói .app của trình chỉnh sửa trên macOS), Godot sẽ bật chế độ tự chứa. Chế độ này khiến Godot ghi toàn bộ dữ liệu, cài đặt và cache của trình chỉnh sửa vào thư mục tên editor_data/ trong cùng thư mục với file nhị phân của trình chỉnh sửa. Bạn có thể dùng nó để tạo bản cài đặt portable của trình chỉnh sửa.

Bản phát hành Godot trên Steam dùng chế độ tự chứa theo mặc định.

Ghi chú

Chế độ tự chứa hiện chưa được hỗ trợ trong dự án đã xuất. Để đọc và ghi file tương đối với đường dẫn file thực thi, hãy dùng OS.get_executable_path(). Lưu ý rằng việc ghi file vào đường dẫn file thực thi chỉ hoạt động nếu file thực thi được đặt ở vị trí có thể ghi (tức là không phải Program Files hoặc thư mục khác chỉ đọc đối với người dùng thông thường).
