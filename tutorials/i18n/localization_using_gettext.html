Bản địa hóa bằng gettext (file PO)

Ngoài việc import bản dịch ở định dạng CSV, Godot cũng hỗ trợ tải các file bản dịch được viết theo định dạng GNU gettext (dạng văn bản .po và dạng đã biên dịch .mo).

Ghi chú

Để làm quen với gettext, hãy xem A Quick Gettext Tutorial. Bài này được viết cho các dự án C, nhưng phần lớn lời khuyên cũng áp dụng được cho Godot (trừ xgettext).

Để xem tài liệu đầy đủ, hãy tham khảo GNU Gettext.

Ưu điểm

  • gettext là một định dạng chuẩn, có thể chỉnh sửa bằng bất kỳ trình soạn thảo văn bản nào hoặc các trình chỉnh sửa có giao diện đồ họa như Poedit. Điều này có ý nghĩa vì nó cung cấp nhiều công cụ cho người dịch, chẳng hạn như đánh dấu các chuỗi đã lỗi thời, tìm các chuỗi chưa được dịch, v.v.

  • gettext được hỗ trợ bởi các nền tảng dịch thuật như Transifex và Weblate, giúp mọi người cộng tác bản địa hóa dễ dàng hơn.

  • So với CSV, các file gettext hoạt động tốt hơn với các hệ thống quản lý phiên bản như Git, vì mỗi locale có file message riêng.

  • Chuỗi nhiều dòng dễ chỉnh sửa trong file PO của gettext hơn so với file CSV.

Nhược điểm

  • File PO của gettext có định dạng phức tạp hơn CSV và có thể khó nắm bắt hơn với những người mới làm bản địa hóa phần mềm.

  • Những người duy trì các file bản địa hóa sẽ phải cài đặt công cụ gettext trên hệ thống của mình. Tuy nhiên, vì Godot hỗ trợ dùng file message dạng văn bản (.po), người dịch có thể kiểm tra công việc của mình mà không cần cài công cụ gettext.

  • File PO của gettext thường dùng tiếng Anh làm ngôn ngữ gốc. Người dịch sẽ dựa vào ngôn ngữ gốc này để dịch sang các ngôn ngữ khác. Bạn vẫn có thể dùng ngôn ngữ khác làm ngôn ngữ gốc, nhưng điều này không phổ biến.

Cài đặt công cụ gettext

Các công cụ gettext dòng lệnh là cần thiết để thực hiện các thao tác bảo trì, chẳng hạn như cập nhật file message. Vì vậy, bạn rất nên cài đặt chúng.

  • Windows: Tải trình cài đặt từ trang này. Mọi kiến trúc và kiểu binary (shared hoặc static) đều dùng được; nếu không chắc, hãy chọn trình cài đặt static 64-bit.

  • macOS: Cài đặt gettext bằng Homebrew với lệnh brew install gettext, hoặc bằng MacPorts với lệnh sudo port install gettext.

  • Linux: Trên hầu hết các bản phân phối, hãy cài gói gettext từ trình quản lý gói của bản phân phối.

Nếu muốn một công cụ có giao diện đồ họa, bạn có thể tải Poedit từ trang web chính thức. Phiên bản cơ bản là mã nguồn mở và được phát hành theo giấy phép MIT.

Tạo PO template

Tự động tạo bằng trình chỉnh sửa

Trình chỉnh sửa có thể tự động tạo PO template từ các file scene và GDScript được chỉ định. Việc tạo POT này cũng hỗ trợ ngữ cảnh dịch và dạng số nhiều nếu được dùng trong script, thông qua đối số thứ hai (tùy chọn) của tr() và phương thức tr_n().

Mở Project > Project Settings > Localization > Template Generation, rồi dùng nút Add… để chỉ định đường dẫn tới các scene và script trong dự án có chứa chuỗi cần bản địa hóa:

Sau khi thêm ít nhất một scene hoặc script, nhấp Generate ở góc trên bên phải, rồi chỉ định đường dẫn tới file đầu ra có phần mở rộng pot. File này có thể đặt ở bất kỳ đâu trong thư mục dự án, nhưng nên giữ nó trong một thư mục con như locale, vì mỗi locale sẽ được định nghĩa trong một file riêng.

Xem bên dưới để biết cách thêm chú thích cho người dịch hoặc loại trừ một số chuỗi khỏi PO template đối với các file GDScript.

Sau đó, bạn có thể chuyển sang tạo file message từ PO template.

Ghi chú

Hãy nhớ tạo lại PO template sau khi thay đổi bất kỳ chuỗi cần bản địa hóa nào, hoặc sau khi thêm scene hay script mới. Nếu không, các chuỗi mới thêm sẽ không thể bản địa hóa và người dịch sẽ không thể cập nhật bản dịch cho các chuỗi đã lỗi thời.

Tạo thủ công

Nếu cách tạo tự động không đáp ứng được nhu cầu của bạn, bạn có thể tạo PO template bằng tay trong trình soạn thảo văn bản. File này có thể đặt ở bất kỳ đâu trong thư mục dự án, nhưng nên giữ nó trong một thư mục con, vì mỗi locale sẽ được định nghĩa trong một file riêng.

Tạo một thư mục tên locale trong thư mục dự án. Trong thư mục này, lưu một file tên messages.pot với nội dung sau:

# Don't remove the two lines below, they're required for gettext to work correctly.
msgid ""
msgstr ""

# Example of a regular string.
msgid "Hello world!"
msgstr ""

# Example of a string with pluralization.
msgid "There is %d apple."
msgid_plural "There are %d apples."
msgstr[0] ""
msgstr[1] ""

# Example of a string with a translation context.
msgctxt "Actions"
msgid "Close"
msgstr ""

Message trong gettext được tạo thành từ các cặp msgid và msgstr. msgid là chuỗi nguồn (thường bằng tiếng Anh), msgstr sẽ là chuỗi đã dịch.

Cảnh báo

Giá trị msgstr trong các file PO template (.pot) phải luôn để trống. Việc bản địa hóa sẽ được thực hiện trong các file .po được tạo ra.

Tạo file message từ PO template

Lệnh msginit được dùng để chuyển PO template thành file message. Ví dụ, để tạo file bản địa hóa tiếng Pháp, hãy dùng lệnh sau khi đang ở trong thư mục locale:

msginit --no-translator --input=messages.pot --locale=fr

Lệnh trên sẽ tạo một file tên fr.po trong cùng thư mục với PO template.

Ngoài ra, bạn có thể làm việc này bằng giao diện đồ họa với Poedit, hoặc bằng cách tải file POT lên nền tảng web bạn chọn.

Tải file message trong Godot

Để đăng ký một file message làm bản dịch trong dự án, hãy mở Project Settings, rồi vào Localization > Translations, nhấp Add… rồi chọn file .po hoặc .mo trong hộp thoại chọn file. Locale sẽ được suy ra từ thuộc tính "Language: <code>\n" trong file message.

Ghi chú

Xem Quốc tế hóa game để biết thêm thông tin về việc import và kiểm tra bản dịch trong Godot.

Cập nhật file message theo PO template

Sau khi cập nhật PO template, bạn sẽ phải cập nhật các file message để chúng chứa các chuỗi mới, đồng thời loại bỏ các chuỗi không còn trong PO template. Việc này có thể thực hiện tự động bằng công cụ msgmerge:

# The order matters: specify the message file *then* the PO template!
msgmerge --update --backup=none fr.po messages.pot

Nếu bạn muốn giữ bản sao lưu của file message gốc (sẽ được lưu thành fr.po~ trong ví dụ này), hãy bỏ đối số --backup=none.

Ghi chú

Sau khi chạy msgmerge, các chuỗi đã bị thay đổi trong ngôn ngữ gốc sẽ được thêm chú thích "fuzzy" phía trước trong file .po. Chú thích này cho biết bản dịch cần được cập nhật để khớp với chuỗi nguồn mới, vì nhiều khả năng bản dịch sẽ không chính xác cho đến khi được cập nhật.

Các chuỗi có chú thích "fuzzy" sẽ không được Godot đọc cho đến khi bản dịch được cập nhật và chú thích "fuzzy" được gỡ bỏ.

Kiểm tra tính hợp lệ của file PO hoặc template

Bạn có thể kiểm tra xem cú pháp của một file gettext có hợp lệ hay không.

Nếu mở bằng Poeditor, nó sẽ hiển thị các cảnh báo phù hợp khi có lỗi cú pháp. Bạn cũng có thể kiểm tra bằng cách chạy lệnh gettext dưới đây:

msgfmt fr.po --check

Nếu có lỗi cú pháp hoặc cảnh báo, chúng sẽ được hiển thị trong console. Nếu không, msgfmt sẽ không xuất ra gì cả.

Dùng file MO nhị phân (chỉ hữu ích cho dự án lớn)

Với các dự án lớn có từ vài nghìn chuỗi cần dịch trở lên, việc dùng file message MO nhị phân (đã biên dịch) thay cho file PO dạng văn bản có thể đáng cân nhắc. File MO nhị phân nhỏ hơn và đọc nhanh hơn so với file PO tương đương.

Bạn có thể tạo file MO bằng lệnh dưới đây:

msgfmt fr.po --no-hash -o fr.mo

Nếu file PO hợp lệ, lệnh này sẽ tạo file fr.mo bên cạnh file PO. File MO này sau đó có thể được tải trong Godot như mô tả ở trên.

File PO gốc nên được giữ trong hệ thống quản lý phiên bản để bạn có thể cập nhật bản dịch sau này. Trong trường hợp bạn làm mất file PO gốc và muốn dịch ngược file MO thành file PO dạng văn bản, bạn có thể làm như sau:

msgunfmt fr.mo > fr.po

File được dịch ngược sẽ không có chú thích hay các chuỗi fuzzy, vì ngay từ đầu chúng không bao giờ được biên dịch vào file MO.

Trích xuất chuỗi cần bản địa hóa từ file GDScript

Editor plugin tích hợp sẵn nhận diện nhiều mẫu trong mã nguồn để trích xuất các chuỗi cần bản địa hóa từ file GDScript, bao gồm nhưng không giới hạn ở:

  • các lời gọi tr(), tr_n(), atr() và atr_n();

  • gán các thuộc tính text, placeholder_text và tooltip_text;

  • các lời gọi add_tab(), add_item(), set_tab_title() và các lời gọi khác;

  • bộ lọc FileDialog như "*.png ; PNG Images".

Ghi chú

Đối số hoặc toán hạng bên phải phải là một chuỗi hằng, nếu không plugin sẽ không thể đánh giá biểu thức và sẽ bỏ qua nó.

Nếu plugin trích xuất những chuỗi không cần thiết, bạn có thể bỏ qua chúng bằng chú thích NO_TRANSLATE. Bạn cũng có thể cung cấp thêm thông tin cho người dịch bằng chú thích TRANSLATORS:. Các chú thích này phải được đặt trên cùng dòng với mẫu được nhận diện hoặc ngay trước nó.

$CharacterName.text = "???" # NO_TRANSLATE

# NO_TRANSLATE: Language name.
$TabContainer.set_tab_title(0, "Python")

item.text = "Tool" # TRANSLATORS: Up to 10 characters.

# TRANSLATORS: This is a reference to Lewis Carroll's poem "Jabberwocky",
# make sure to keep this as it is important to the plot.
say(tr("He took his vorpal sword in hand. The end?"))

Dùng ngữ cảnh

Tham số context có thể dùng để phân biệt tình huống sử dụng một bản dịch, hoặc để phân biệt các từ đa nghĩa (từ có nhiều nghĩa).

Ví dụ:

tr("Start", "Main Menu")
tr("End", "Main Menu")
tr("Shop", "Main Menu")
tr("Shop", "In Game")

Trong file PO của gettext, một chuỗi có ngữ cảnh có thể được định nghĩa như sau:

# Example of a string with a translation context.
msgctxt "Main Menu"
msgid "Shop"
msgstr ""

# A different source string that is identical, but with a different context.
msgctxt "In Game"
msgid "Shop"
msgstr ""

Cập nhật file PO

Sớm hay muộn, bạn sẽ thêm nội dung mới vào trò chơi, và sẽ có các chuỗi mới cần được dịch. Khi đó, bạn sẽ cần cập nhật các file PO hiện có để bao gồm các chuỗi mới.

Đầu tiên, tạo một file POT mới chứa tất cả các chuỗi hiện có cùng với các chuỗi mới thêm. Sau đó, hợp nhất các file PO hiện có với file POT mới. Có hai cách để làm việc này:

  • Dùng một trình chỉnh sửa gettext; nó thường có tùy chọn cập nhật file PO từ file POT.

  • Dùng công cụ msgmerge của gettext:

# The order matters: specify the message file *then* the PO template!
msgmerge --update --backup=none fr.po messages.pot

Nếu bạn muốn giữ bản sao lưu của file message gốc (sẽ được lưu thành fr.po~ trong ví dụ này), hãy bỏ đối số --backup=none.

Plugin tùy chỉnh để tạo POT

Nếu bạn cần xử lý thêm định dạng file nào khác, bạn có thể viết một plugin tùy chỉnh để phân tích và trích xuất chuỗi từ file tùy chỉnh đó. Plugin tùy chỉnh này sẽ trích xuất các chuỗi và ghi vào file POT khi bạn nhấn Generate POT. Để tìm hiểu thêm về cách tạo plugin phân tích bản dịch, hãy xem EditorTranslationParserPlugin.
