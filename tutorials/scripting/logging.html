Ghi log

Godot đi kèm nhiều cách để tổ chức và thu thập các thông điệp log.

In thông báo

Xem thêm

Xem In thông báo để biết hướng dẫn in thông điệp. Kết quả được in ra nhìn chung giống hệt kết quả được ghi log.

Khi chạy dự án từ trình chỉnh sửa, trình chỉnh sửa sẽ hiển thị văn bản được ghi log trong Bảng Output.

Cài đặt dự án

Có một số cài đặt dự án để điều khiển hành vi ghi log trong Godot:

  • Application > Run > Disable stdout: Tắt hoàn toàn việc ghi log ra standard output. Điều này cũng ảnh hưởng đến những gì các logger tùy chỉnh nhận được. Có thể điều khiển cài đặt này lúc runtime bằng cách gán Engine.print_to_stdout.

  • Application > Run > Disable stderr: Tắt hoàn toàn việc ghi log ra standard error. Điều này cũng ảnh hưởng đến những gì các logger tùy chỉnh nhận được. Có thể điều khiển cài đặt này lúc runtime bằng cách gán Engine.print_error_messages.

  • Debug > Settings > stdout > Verbose stdout: Bật ghi log chi tiết (verbose) ra standard output. Các lệnh in từ print_verbose() chỉ hiển thị khi chế độ verbose được bật.

  • Debug > Settings > stdout > Print FPS: In số khung hình mỗi giây sau mỗi giây, cũng như trạng thái V-Sync khi khởi động (vì V-Sync có thể giới hạn framerate tối đa).

  • Debug > Settings > stdout > Print GPU Profile: In báo cáo mức sử dụng GPU mỗi giây, dùng cùng nguồn dữ liệu với Visual Profiler.

Một số cài đặt dự án này cũng có thể được ghi đè bằng đối số dòng lệnh như --quiet, --verbose và --print-fps.

Việc ghi log ra file của chính engine cũng có thể cấu hình được, như mô tả trong phần dưới đây.

Ghi log ra file tích hợp sẵn

Mặc định, trên các nền tảng desktop, Godot ghi file log vào user://logs/godot.log. Bạn có thể thay đổi vị trí này bằng cách sửa cài đặt dự án debug/file_logging/log_path. Các file log được xoay vòng (rotate) để giữ lại các file cũ phục vụ việc kiểm tra. Mỗi phiên tạo một file log mới, còn file cũ được đổi tên để chứa ngày nó được xoay vòng. Mặc định Godot giữ tối đa 5 file log, con số này có thể điều chỉnh bằng cài đặt dự án debug/file_logging/max_log_files.

Việc ghi log ra file cũng có thể tắt hoàn toàn bằng cài đặt dự án debug/file_logging/enable_file_logging.

Khi dự án bị crash, crash log được ghi vào cùng file với file log. Crash log chỉ chứa backtrace dùng được nếu binary được chạy có chứa debugging symbol, hoặc nếu nó tìm được file debug symbol khớp với binary. Các binary chính thức không cung cấp debugging symbol, nên cần một bản build tùy chỉnh để tính năng này hoạt động. Xem Debugging symbol để biết hướng dẫn biên dịch binary có bật debugging symbol.

Ghi chú

File log cho các câu lệnh print() được cập nhật khi standard output được engine flush. Standard output chỉ được flush sau mỗi lần in ở các bản build debug. Trong các dự án được xuất ở chế độ release, để cải thiện hiệu năng, standard output chỉ được flush khi dự án thoát hoặc bị crash, đặc biệt khi dự án thường xuyên in văn bản ra standard output.

Ngược lại, luồng standard error (được dùng bởi printerr(), push_error() và push_warning()) luôn được flush sau mỗi lần in, kể cả trong các dự án được xuất ở chế độ release.

Với một số trường hợp như dedicated server, có thể bạn muốn các bản build release luôn flush stdout sau mỗi lần in, để các dịch vụ ghi log như journald có thể thu thập log trong khi tiến trình đang chạy. Bạn có thể làm điều này bằng cách bật application/run/flush_stdout_on_print trong Project Settings.

Backtrace của script

Kể từ Godot 4.5, khi mã GDScript gặp lỗi, nó sẽ ghi log một backtrace trỏ đến nguồn gốc của lỗi, đồng thời chứa call stack dẫn đến lỗi đó. Hành vi này luôn được bật khi chạy trong trình chỉnh sửa, hoặc khi dự án được xuất ở chế độ debug.

Trong các dự án được xuất ở chế độ release, backtrace bị tắt theo mặc định vì lý do hiệu năng. Bạn có thể bật chúng bằng cách chọn Debug > Settings > GDScript > Always Track Call Stacks trong Project Settings. Nếu bạn dùng một hệ thống ghi log tùy chỉnh báo cáo exception đến một dịch vụ từ xa, bạn nên bật tùy chọn này để các lỗi được báo cáo dễ xử lý hơn.

Backtrace khi crash

Cảnh báo

Backtrace này cũng được ghi vào file log của phiên hiện tại, nhưng nó không hiển thị trong Output panel của trình chỉnh sửa. Vì hệ thống scripting của engine không còn chạy khi engine đang crash, bạn không thể truy cập nó từ script trong cùng phiên đó. Tuy nhiên, bạn vẫn có thể đọc backtrace khi crash ở phiên tiếp theo bằng cách tải các file log và tìm chuỗi backtrace khi crash (Program crashed with signal) bằng class_FileAccess. Cách này cho phép bạn truy cập thông tin backtrace ngay cả sau khi crash, miễn là người dùng khởi động lại dự án và việc ghi log ra file được bật:

# This script can be made an autoload, so that it runs when the project starts.
extends Node

func _ready() -> void:
  var log_dir: String = String(ProjectSettings.get_setting("debug/file_logging/log_path")).get_base_dir()
  # Get the last log file by alphabetical order.
  # Since the timestamp is featured in the file name, it should always be the most recent
  # log file that was rotated. The non-timestamped log file is for the current session,
  # so we don't want to read that one.
  var last_log_file: String = log_dir.path_join(DirAccess.get_files_at(log_dir)[-1])
  var last_long_contents: String = FileAccess.get_file_as_string(last_log_file)

  var crash_begin_idx: int = last_long_contents.find("Program crashed with signal")
  if crash_begin_idx != -1:
      print("The previous session has crashed with the following backtrace:\n")
      print(last_long_contents.substr(crash_begin_idx))

Bạn có thể tùy chỉnh thông điệp xuất hiện ở đầu backtrace bằng cài đặt dự án Debug > Settings > Crash Handler > Message. Bạn có thể dùng nó để trỏ đến một URL hoặc địa chỉ email mà người dùng có thể báo cáo sự cố.

Tạo logger tùy chỉnh

Kể từ Godot 4.5, bạn có thể tạo logger tùy chỉnh. Việc ghi log tùy chỉnh này có thể dùng cho nhiều mục đích:

  • Hiển thị một console trong game với cùng các thông điệp mà engine in ra, mà không cần sửa các script khác.

  • Báo cáo các lỗi được in ra từ máy của người chơi đến một server từ xa. Điều này giúp nhà phát triển sửa lỗi dễ hơn khi game đã phát hành, hoặc trong quá trình playtest.

  • Tích hợp bản export dedicated server với các nền tảng giám sát.

Có thể đăng ký một logger tùy chỉnh bằng cách tạo một lớp kế thừa từ class_logger, rồi truyền một instance của lớp này cho OS.add_logger, trong phương thức _init() của một script. Một nơi phù hợp để làm việc này là một autoload.

Lớp này phải định nghĩa hai phương thức: _log_message() và _log_error().

Đây là một ví dụ tối giản hoạt động được của một logger tùy chỉnh, với script được thêm làm autoload:

extends Node

class CustomLogger extends Logger:
    # Note that this method is not called for messages that use
    # `push_error()` and `push_warning()`, even though these are printed to stderr.
    func _log_message(message: String, error: bool) -> void:
        # Do something with `message`.
        # `error` is `true` for messages printed to the standard error stream (stderr) with `print_error()`.
        # Note that this method will be called from threads other than the main thread, possibly at the same
        # time, so you will need to have some kind of thread-safety as part of it, like a Mutex.
        pass

    func _log_error(
            function: String,
            file: String,
            line: int,
            code: String,
            rationale: String,
            editor_notify: bool,
            error_type: int,
            script_backtraces: Array[ScriptBacktrace]
    ) -> void:
        # Do something with the error. The error text is in `rationale`.
        # See the Logger class reference for details on other parameters.
        # Note that this method will be called from threads other than the main thread, possibly at the same
        # time, so you will need to have some kind of thread-safety as part of it, like a Mutex.
        pass

# Use `_init()` to initialize the logger as early as possible, which ensures that messages
# printed early are taken into account. However, even when using `_init()`, the engine's own
# initialization messages are not accessible.
func _init() -> void:
    OS.add_logger(CustomLogger.new())

Lưu ý rằng để tránh đệ quy vô hạn, bạn không thể dùng hiệu quả print() và các phương thức liên quan trong _log_message(). Bạn cũng không thể dùng hiệu quả push_error() hoặc push_warning() trong _log_error(). Nếu cố làm vậy, một thông điệp sẽ được in ra cùng luồng với thông điệp gốc. Thông điệp này không có trong logger tùy chỉnh, và chính điều đó ngăn đệ quy vô hạn xảy ra:

While attempting to print a message, another message was printed:
...

While attempting to print an error, another error was printed:
...
