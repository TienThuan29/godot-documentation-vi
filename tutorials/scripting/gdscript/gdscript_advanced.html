GDScript: Giới thiệu về ngôn ngữ động

Giới thiệu

Bài hướng dẫn này nhằm làm tài liệu tham khảo nhanh về cách dùng GDScript hiệu quả hơn. Nó tập trung vào các trường hợp phổ biến đặc thù của ngôn ngữ, đồng thời cũng đề cập nhiều thông tin về các ngôn ngữ kiểu động.

Bài viết đặc biệt hữu ích cho những lập trình viên có ít hoặc chưa có kinh nghiệm với các ngôn ngữ kiểu động.

Bản chất động

Ưu & nhược điểm của kiểu động

GDScript là một ngôn ngữ kiểu động (Dynamically Typed). Vì vậy, các ưu điểm chính của nó là:

  • Ngôn ngữ dễ làm quen.

  • Phần lớn code có thể được viết và thay đổi nhanh chóng, không rắc rối.

  • Code dễ đọc (ít rườm rà).

  • Không cần biên dịch để chạy thử.

  • Runtime rất nhỏ gọn.

  • Bản chất đã có duck-typing và đa hình.

Còn các nhược điểm chính là:

  • Hiệu năng thấp hơn các ngôn ngữ kiểu tĩnh.

  • Khó refactor hơn (không truy vết được symbol).

  • Một số lỗi thường được phát hiện lúc biên dịch ở các ngôn ngữ kiểu tĩnh chỉ xuất hiện khi chạy code (vì việc phân tích biểu thức chặt chẽ hơn).

  • Gợi ý hoàn thành code kém linh hoạt hơn (một số kiểu biến chỉ được biết lúc chạy).

Áp dụng vào thực tế, điều này có nghĩa là Godot dùng với GDScript là một sự kết hợp được thiết kế để tạo game nhanh chóng và hiệu quả. Với những game đòi hỏi tính toán rất nặng và không tận dụng được các công cụ dựng sẵn của engine (như các kiểu Vector, Physics Engine, thư viện Math, v.v.), bạn vẫn có thể dùng C++. Nhờ vậy, bạn vẫn có thể viết phần lớn game bằng GDScript và thêm một ít C++ vào những chỗ cần tăng hiệu năng.

Biến & phép gán

Mọi biến trong ngôn ngữ kiểu động đều giống "variant". Điều này có nghĩa là kiểu của chúng không cố định, và chỉ thay đổi thông qua phép gán. Ví dụ:

Tĩnh:

int a; // Value uninitialized.
a = 5; // This is valid.
a = "Hi!"; // This is invalid.

Động:

var a # 'null' by default.
a = 5 # Valid, 'a' becomes an integer.
a = "Hi!" # Valid, 'a' changed to a string.

Khi là đối số của hàm:

Hàm cũng có bản chất động, nghĩa là chúng có thể được gọi với các đối số khác nhau, ví dụ:

Tĩnh:

void print_value(int value) {

    printf("value is %i\n", value);
}

[..]

print_value(55); // Valid.
print_value("Hello"); // Invalid.

Động:

func print_value(value):
    print(value)

[..]

print_value(55) # Valid.
print_value("Hello") # Valid.

Con trỏ & tham chiếu:

Trong các ngôn ngữ tĩnh như C hoặc C++ (và ở mức độ nào đó là Java và C#), có sự phân biệt giữa một biến và một con trỏ/tham chiếu đến biến. Con trỏ/tham chiếu cho phép các hàm khác sửa đổi đối tượng bằng cách truyền một tham chiếu đến đối tượng gốc.

Trong C# hoặc Java, mọi thứ không phải kiểu dựng sẵn (int, float, đôi khi là String) luôn là con trỏ hoặc tham chiếu. Các tham chiếu cũng được thu gom rác tự động, nghĩa là chúng bị xóa khi không còn được dùng. Các ngôn ngữ kiểu động cũng thường dùng mô hình bộ nhớ này. Một vài ví dụ:

  • C++:

void use_class(SomeClass *instance) {

    instance->use();
}

void do_something() {

    SomeClass *instance = new SomeClass; // Created as pointer.
    use_class(instance); // Passed as pointer.
    delete instance; // Otherwise it will leak memory.
}

  • Java:

@Override
public final void use_class(SomeClass instance) {

    instance.use();
}

public final void do_something() {

    SomeClass instance = new SomeClass(); // Created as reference.
    use_class(instance); // Passed as reference.
    // Garbage collector will get rid of it when not in
    // use and freeze your game randomly for a second.
}

  • GDScript:

func use_class(instance): # Does not care about class type
    instance.use() # Will work with any class that has a ".use()" method.

func do_something():
    var instance = SomeClass.new() # Created as reference.
    use_class(instance) # Passed as reference.
    # Will be unreferenced and deleted.

Trong GDScript, chỉ các kiểu cơ bản (int, float, string và các kiểu vector) được truyền vào hàm theo giá trị (giá trị được sao chép). Mọi thứ khác (instance, mảng, dictionary, v.v.) được truyền theo tham chiếu. Các lớp kế thừa class_RefCounted (mặc định nếu không chỉ định gì) sẽ được giải phóng khi không còn dùng, nhưng bạn cũng có thể tự quản lý bộ nhớ nếu kế thừa thủ công từ class_Object.

Mảng

Mảng trong ngôn ngữ kiểu động có thể chứa nhiều kiểu dữ liệu khác nhau trộn lẫn và luôn động (có thể thay đổi kích thước bất cứ lúc nào). Hãy so sánh, ví dụ, với mảng trong ngôn ngữ kiểu tĩnh:

int *array = new int[4]; // Create array.
array[0] = 10; // Initialize manually.
array[1] = 20; // Can't mix types.
array[2] = 40;
array[3] = 60;
// Can't resize.
use_array(array); // Passed as pointer.
delete[] array; // Must be freed.

// or

std::vector<int> array;
array.resize(4);
array[0] = 10; // Initialize manually.
array[1] = 20; // Can't mix types.
array[2] = 40;
array[3] = 60;
array.resize(3); // Can be resized.
use_array(array); // Passed reference or value.
// Freed when stack ends.

Và trong GDScript:

var array = [10, "hello", 40, 60] # You can mix types.
array.resize(3) # Can be resized.
use_array(array) # Passed as reference.
# Freed when no longer in use.

Trong ngôn ngữ kiểu động, mảng cũng có thể kiêm luôn vai trò của các kiểu dữ liệu khác, chẳng hạn như danh sách:

var array = []
array.append(4)
array.append(5)
array.pop_front()

Hoặc tập hợp không thứ tự:

var a = 20
if a in [10, 20, 30]:
    print("We have a winner!")

Dictionary

Dictionary là một công cụ mạnh mẽ trong ngôn ngữ kiểu động. Trong GDScript, dictionary không định kiểu có thể được dùng trong nhiều trường hợp mà ngôn ngữ kiểu tĩnh thường dùng một cấu trúc dữ liệu khác.

Dictionary có thể ánh xạ bất kỳ giá trị nào sang bất kỳ giá trị nào khác, hoàn toàn không quan tâm đến kiểu dữ liệu dùng làm khóa hay giá trị. Trái với suy nghĩ phổ biến, chúng rất hiệu quả vì có thể được triển khai bằng bảng băm. Thực tế, chúng hiệu quả đến mức một số ngôn ngữ còn triển khai mảng dưới dạng dictionary.

Ví dụ về Dictionary:

var d = {"name": "John", "age": 22}
print("Name: ", d["name"], " Age: ", d["age"])

Dictionary cũng là động, có thể thêm hoặc xóa khóa bất cứ lúc nào với chi phí thấp:

d["mother"] = "Rebecca" # Addition.
d["age"] = 11 # Modification.
d.erase("name") # Removal.

Trong hầu hết trường hợp, mảng hai chiều thường có thể được triển khai dễ dàng hơn bằng dictionary. Đây là ví dụ về game bắn tàu (battleship):

# Battleship Game

const SHIP = 0
const SHIP_HIT = 1
const WATER_HIT = 2

var board = {}

func initialize():
    board[Vector2(1, 1)] = SHIP
    board[Vector2(1, 2)] = SHIP
    board[Vector2(1, 3)] = SHIP

func missile(pos):
    if pos in board: # Something at that position.
        if board[pos] == SHIP: # There was a ship! hit it.
            board[pos] = SHIP_HIT
        else:
            print("Already hit here!") # Hey dude you already hit here.
    else: # Nothing, mark as water.
        board[pos] = WATER_HIT

func game():
    initialize()
    missile(Vector2(1, 1))
    missile(Vector2(5, 8))
    missile(Vector2(2, 3))

Dictionary cũng có thể được dùng làm dữ liệu đánh dấu (markup) hoặc cấu trúc nhanh. Dù dictionary của GDScript giống dictionary của python, nó cũng hỗ trợ cú pháp và cách truy cập kiểu Lua, rất tiện cho việc viết trạng thái khởi tạo và struct nhanh:

# Same example, lua-style support.
# This syntax is a lot more readable and usable.
# Like any GDScript identifier, keys written in this form cannot start
# with a digit.

var d = {
    name = "John",
    age = 22
}

print("Name: ", d.name, " Age: ", d.age) # Used "." based indexing.

# Indexing

d["mother"] = "Rebecca"
d.mother = "Caroline" # This would work too to create a new key.

For & while

Lặp bằng vòng for kiểu C trong các ngôn ngữ dẫn xuất từ C có thể khá phức tạp:

const char** strings = new const char*[50];

[..]

for (int i = 0; i < 50; i++) {
    printf("Value: %c Index: %d\n", strings[i], i);
}

// Even in STL:
std::list<std::string> strings;

[..]

for (std::string::const_iterator it = strings.begin(); it != strings.end(); it++) {
    std::cout << *it << std::endl;
}

Vì vậy, GDScript chủ động chọn dùng vòng lặp for-in trên các đối tượng có thể lặp (iterable):

for s in strings:
    print(s)

Các kiểu dữ liệu container (mảng và dictionary) đều có thể lặp. Dictionary cho phép lặp qua các khóa:

for key in dict:
    print(key, " -> ", dict[key])

Cũng có thể lặp theo chỉ số:

for i in range(strings.size()):
    print(strings[i])

Hàm range() có thể nhận 3 đối số:

range(n) # Will count from 0 to n in steps of 1. The parameter n is exclusive.
range(b, n) # Will count from b to n in steps of 1. The parameters b is inclusive. The parameter n is exclusive.
range(b, n, s) # Will count from b to n, in steps of s. The parameters b is inclusive. The parameter n is exclusive.

Một vài ví dụ với vòng lặp for kiểu C:

for (int i = 0; i < 10; i++) {}

for (int i = 5; i < 10; i++) {}

for (int i = 5; i < 10; i += 2) {}

Chuyển thành:

for i in range(10):
    pass

for i in range(5, 10):
    pass

for i in range(5, 10, 2):
    pass

Và lặp ngược bằng bộ đếm âm:

for (int i = 10; i > 0; i--) {}

Trở thành:

for i in range(10, 0, -1):
    pass

While

Vòng lặp while() thì ở đâu cũng giống nhau:

var i = 0

while i < strings.size():
    print(strings[i])
    i += 1

Iterator tùy chỉnh

Bạn có thể tạo iterator tùy chỉnh trong trường hợp các iterator mặc định chưa đáp ứng đủ nhu cầu bằng cách override các hàm _iter_init(), _iter_next() và _iter_get() trong script. Dưới đây là ví dụ triển khai một forward iterator:

class ForwardIterator:
    var _start
    var _end
    var _increment

    func _init(start, end, increment):
        _start = start
        _end = end
        _increment = increment

    func _should_continue(current):
        return current < _end

    func _iter_init(iter):
        # Initialize the state to store the current value.
        iter[0] = _start
        return _should_continue(iter[0])

    func _iter_next(iter):
        iter[0] += _increment
        return _should_continue(iter[0])

    func _iter_get(iter):
        # The state is not wrapped in an array for `_iter_get()`.
        # The iteration value is the same as the state.
        return iter

Và nó có thể được dùng như mọi iterator khác:

var itr = ForwardIterator.new(0, 6, 2)
for i in itr:
    print(i) # Will print 0, 2, and 4.

Có thể lưu trạng thái trong một biến thành viên nhưng không khuyến khích. Cần nhiều trạng thái trong những trường hợp như vòng lặp lồng nhau, khi cùng một instance iterator được dùng đồng thời. Tham số iter trong _iter_init() và _iter_next() là một mảng một phần tử để các cập nhật được giữ lại. Còn trong _iter_get(), trạng thái không được bọc vì nó được coi là chỉ đọc.

Trả về true từ _iter_init() và _iter_next() cho biết iterator còn hợp lệ. Trả về false sẽ kết thúc vòng lặp.

Để biết thêm chi tiết, xem _iter_init(), _iter_next() và _iter_get().

Duck typing

Một trong những khái niệm khó nắm bắt nhất khi chuyển từ ngôn ngữ kiểu tĩnh sang ngôn ngữ kiểu động là duck typing. Duck typing giúp thiết kế code tổng thể đơn giản và dễ viết hơn nhiều, nhưng cách nó hoạt động lại không hiển nhiên.

Ví dụ, hãy tưởng tượng một tình huống trong đó một tảng đá lớn đang lăn xuống đường hầm, nghiền nát mọi thứ trên đường đi. Code cho tảng đá trong một ngôn ngữ kiểu tĩnh sẽ trông như sau:

void BigRollingRock::on_object_hit(Smashable *entity) {

    entity->smash();
}

Theo cách này, mọi thứ có thể bị tảng đá nghiền nát đều phải kế thừa Smashable. Nếu nhân vật, kẻ địch, đồ nội thất, hòn đá nhỏ đều có thể bị nghiền, chúng sẽ cần kế thừa lớp Smashable, có thể đòi hỏi đa kế thừa. Nếu không muốn đa kế thừa, chúng sẽ phải kế thừa một lớp chung như Entity. Tuy vậy, sẽ không thanh lịch lắm nếu thêm phương thức ảo smash() vào Entity chỉ vì một vài đối tượng có thể bị nghiền.

Với các ngôn ngữ kiểu động, đây không phải vấn đề. Duck typing đảm bảo bạn chỉ cần định nghĩa hàm smash() ở nơi cần thiết, vậy là xong. Không cần quan tâm đến kế thừa, lớp cơ sở, v.v.

func _on_object_hit(object):
    object.smash()

Vậy là xong. Nếu đối tượng va vào tảng đá lớn có phương thức smash(), phương thức đó sẽ được gọi. Không cần kế thừa hay đa hình. Ngôn ngữ kiểu động chỉ quan tâm instance có phương thức hoặc thành viên mong muốn hay không, chứ không quan tâm nó kế thừa từ đâu hay thuộc lớp nào. Định nghĩa của Duck Typing sẽ làm rõ điều này hơn:

"Khi tôi thấy một con chim đi như vịt, bơi như vịt và kêu quạc quạc như vịt, tôi gọi con chim đó là vịt"

Trong trường hợp này, nó được hiểu là:

"Nếu đối tượng có thể bị nghiền, đừng quan tâm nó là gì, cứ nghiền nó."

Đúng vậy, lẽ ra chúng ta nên gọi nó là Hulk typing.

Có thể đối tượng bị va vào không có hàm smash(). Một số ngôn ngữ kiểu động đơn giản là bỏ qua lời gọi phương thức không tồn tại, nhưng GDScript chặt chẽ hơn, vì vậy nên kiểm tra xem hàm có tồn tại hay không:

func _on_object_hit(object):
    if object.has_method("smash"):
        object.smash()

Sau đó, định nghĩa phương thức đó và mọi thứ tảng đá chạm vào đều có thể bị nghiền nát.
