Hướng dẫn phong cách GDScript

Hướng dẫn phong cách này liệt kê các quy ước để viết GDScript gọn gàng. Mục tiêu là khuyến khích viết mã sạch, dễ đọc và thúc đẩy sự nhất quán giữa các dự án, các cuộc thảo luận và các bài hướng dẫn. Hy vọng điều này cũng sẽ hỗ trợ việc phát triển các công cụ tự động định dạng mã.

Vì GDScript gần giống Python, hướng dẫn này lấy cảm hứng từ hướng dẫn phong cách lập trình PEP 8 của Python.

Hướng dẫn phong cách không phải là bộ quy tắc cứng nhắc. Đôi khi bạn có thể không áp dụng được một số nguyên tắc dưới đây. Khi đó, hãy tự cân nhắc kỹ và hỏi ý kiến các lập trình viên khác.

Nhìn chung, giữ mã nhất quán trong các dự án của bạn và trong nhóm quan trọng hơn việc tuân theo hướng dẫn này đến từng chi tiết.

Ghi chú

Trình soạn thảo script có sẵn của Godot mặc định áp dụng nhiều quy ước trong số này. Hãy để nó hỗ trợ bạn.

Dưới đây là ví dụ một lớp hoàn chỉnh dựa trên các nguyên tắc này:

class_name StateMachine
extends Node
## Hierarchical State machine for the player.
##
## Initializes states and delegates engine callbacks ([method Node._physics_process],
## [method Node._unhandled_input]) to the state.

signal state_changed(previous, new)

@export var initial_state: Node
var is_active = true:
    set = set_is_active

@onready var _state = initial_state:
    set = set_state
@onready var _state_name = _state.name


func _init():
    add_to_group("state_machine")


func _enter_tree():
    print("this happens before the ready method!")


func _ready():
    state_changed.connect(_on_state_changed)
    _state.enter()


func _unhandled_input(event):
    _state.unhandled_input(event)


func _physics_process(delta):
    _state.physics_process(delta)


func transition_to(target_state_path, msg={}):
    if not has_node(target_state_path):
        return

    var target_state = get_node(target_state_path)
    assert(target_state.is_composite == false)

    _state.exit()
    self._state = target_state
    _state.enter(msg)
    Events.player_state_changed.emit(_state.name)


func set_is_active(value):
    is_active = value
    set_physics_process(value)
    set_process_unhandled_input(value)
    set_block_signals(not value)


func set_state(value):
    _state = value
    _state_name = _state.name


func _on_state_changed(previous, new):
    print("state changed")
    state_changed.emit()


class State:
    var foo = 0

    func _init():
        print("Hello!")

Định dạng

Mã hóa ký tự và ký tự đặc biệt

  • Dùng ký tự line feed (LF) để xuống dòng, không dùng CRLF hay CR. (mặc định của trình chỉnh sửa)

  • Dùng một ký tự line feed ở cuối mỗi file. (mặc định của trình chỉnh sửa)

  • Dùng mã hóa UTF-8 không có byte order mark. (mặc định của trình chỉnh sửa)

  • Dùng Tab thay vì dấu cách để thụt lề. (mặc định của trình chỉnh sửa)

Thụt lề

Mỗi mức thụt lề nên lớn hơn một mức so với khối chứa nó.

Đúng:

for i in range(10):
    print("hello")

Sai:

for i in range(10):
  print("hello")

for i in range(10):
        print("hello")

Dùng 2 mức thụt lề để phân biệt các dòng tiếp nối với các khối mã thông thường.

Đúng:

effect.interpolate_property(sprite, "transform/scale",
        sprite.get_scale(), Vector2(2.0, 2.0), 0.3,
        Tween.TRANS_QUAD, Tween.EASE_OUT)

Sai:

effect.interpolate_property(sprite, "transform/scale",
    sprite.get_scale(), Vector2(2.0, 2.0), 0.3,
    Tween.TRANS_QUAD, Tween.EASE_OUT)

Ngoại lệ của quy tắc này là mảng, dictionary và enum. Hãy dùng một mức thụt lề để phân biệt các dòng tiếp nối:

Đúng:

var party = [
    "Godot",
    "Godette",
    "Steve",
]

var character_dict = {
    "Name": "Bob",
    "Age": 27,
    "Job": "Mechanic",
}

enum Tile {
    BRICK,
    FLOOR,
    SPIKE,
    TELEPORT,
}

Sai:

var party = [
        "Godot",
        "Godette",
        "Steve",
]

var character_dict = {
        "Name": "Bob",
        "Age": 27,
        "Job": "Mechanic",
}

enum Tile {
        BRICK,
        FLOOR,
        SPIKE,
        TELEPORT,
}

Dấu phẩy cuối

Dùng dấu phẩy cuối ở dòng cuối cùng trong mảng, dictionary và enum. Điều này giúp refactor dễ hơn và tạo diff gọn hơn trong hệ thống quản lý phiên bản, vì dòng cuối không cần sửa khi thêm phần tử mới.

Đúng:

var array = [
    1,
    2,
    3,
]

Sai:

var array = [
    1,
    2,
    3
]

Dấu phẩy cuối không cần thiết trong danh sách viết trên một dòng, vì vậy đừng thêm chúng trong trường hợp này.

Đúng:

var array = [1, 2, 3]

Sai:

var array = [1, 2, 3,]

Dòng trống

Bao quanh các định nghĩa hàm và lớp bằng hai dòng trống:

func heal(amount):
    health += amount
    health = min(health, max_health)
    health_changed.emit(health)


func take_damage(amount, effect=null):
    health -= amount
    health = max(0, health)
    health_changed.emit(health)

Dùng một dòng trống bên trong hàm để tách các phần logic.

Ghi chú

Trong tài liệu tham khảo lớp và các đoạn mã ngắn của tài liệu này, chúng tôi chỉ dùng một dòng trống giữa các định nghĩa lớp và hàm.

Độ dài dòng

Giữ mỗi dòng mã dưới 100 ký tự.

Nếu có thể, hãy cố giữ các dòng dưới 80 ký tự. Điều này giúp đọc mã trên màn hình nhỏ và khi mở hai script cạnh nhau trong một trình soạn thảo văn bản bên ngoài, ví dụ khi xem một bản sửa đổi dạng diff.

Mỗi dòng một câu lệnh

Tránh gộp nhiều câu lệnh trên một dòng, kể cả câu lệnh điều kiện, để tuân thủ các nguyên tắc phong cách GDScript về khả năng đọc.

Đúng:

if position.x > width:
    position.x = 0

if flag:
    print("flagged")

Sai:

if position.x > width: position.x = 0

if flag: print("flagged")

Ngoại lệ duy nhất của quy tắc đó là toán tử ba ngôi:

next_state = "idle" if is_on_floor() else "fall"

Định dạng câu lệnh nhiều dòng cho dễ đọc

Khi bạn có các câu lệnh if đặc biệt dài hoặc các biểu thức ba ngôi lồng nhau, việc ngắt chúng thành nhiều dòng giúp dễ đọc hơn. Vì các dòng tiếp nối vẫn là một phần của cùng một biểu thức, nên dùng 2 mức thụt lề thay vì một.

GDScript cho phép ngắt câu lệnh thành nhiều dòng bằng dấu ngoặc đơn hoặc dấu gạch chéo ngược. Hướng dẫn này ưu tiên dấu ngoặc đơn vì chúng giúp refactor dễ hơn. Với dấu gạch chéo ngược, bạn phải đảm bảo dòng cuối không bao giờ kết thúc bằng dấu gạch chéo ngược. Với dấu ngoặc đơn, bạn không cần lo về việc dòng cuối có dấu gạch chéo ngược ở cuối.

Khi ngắt một biểu thức điều kiện thành nhiều dòng, các từ khóa and/or nên được đặt ở đầu dòng tiếp nối, không phải ở cuối dòng trước.

Đúng:

var angle_degrees = 135
var quadrant = (
        "northeast" if angle_degrees <= 90
        else "southeast" if angle_degrees <= 180
        else "southwest" if angle_degrees <= 270
        else "northwest"
)

var position = Vector2(250, 350)
if (
        position.x > 200 and position.x < 400
        and position.y > 300 and position.y < 400
):
    pass

Sai:

var angle_degrees = 135
var quadrant = "northeast" if angle_degrees <= 90 else "southeast" if angle_degrees <= 180 else "southwest" if angle_degrees <= 270 else "northwest"

var position = Vector2(250, 350)
if position.x > 200 and position.x < 400 and position.y > 300 and position.y < 400:
    pass

Tránh dấu ngoặc đơn không cần thiết

Tránh dùng dấu ngoặc đơn trong biểu thức và câu lệnh điều kiện. Trừ khi cần thiết cho thứ tự phép tính hoặc để ngắt thành nhiều dòng, chúng chỉ làm giảm khả năng đọc.

Đúng:

if is_colliding():
    queue_free()

Sai:

if (is_colliding()):
    queue_free()

Toán tử boolean

Ưu tiên dùng dạng từ tiếng Anh của các toán tử boolean, vì chúng dễ tiếp cận nhất:

  • Dùng and thay vì &&.

  • Dùng or thay vì ||.

  • Dùng not thay vì !.

Bạn cũng có thể dùng dấu ngoặc đơn quanh các toán tử boolean để tránh mọi sự mơ hồ. Điều này có thể giúp các biểu thức dài dễ đọc hơn.

Đúng:

if (foo and bar) or not baz:
    print("condition is true")

Sai:

if foo && bar || !baz:
    print("condition is true")

Khoảng cách trong comment

Comment thông thường (#) và comment tài liệu (##) nên bắt đầu bằng một dấu cách, nhưng mã bị comment lại thì không. Ngoài ra, các comment vùng mã (#region/#endregion) phải tuân theo đúng cú pháp đó, vì vậy chúng không được bắt đầu bằng dấu cách.

Dùng dấu cách cho comment thông thường và comment tài liệu giúp phân biệt comment văn bản với mã bị vô hiệu hóa.

Đúng:

# This is a comment.
#print("This is disabled code")

Sai:

#This is a comment.
# print("This is disabled code")

Ghi chú

Trong trình soạn thảo script, để bật/tắt comment cho đoạn mã đang chọn, nhấn Ctrl + K. Phím tắt này thêm/xóa một dấu # trước mã trên các dòng được chọn.

Ưu tiên viết comment trên dòng riêng thay vì comment cùng dòng (comment viết trên cùng dòng với mã). Comment cùng dòng phù hợp nhất cho các comment ngắn, thường chỉ vài từ:

Đúng:

# This is a long comment that would make the line below too long if written inline.
print("Example") # Short comment.

Sai:

print("Example") # This is a long comment that would make this line too long if written inline.

Khoảng trắng

Luôn dùng một dấu cách quanh toán tử và sau dấu phẩy. Ngoài ra, tránh thêm dấu cách thừa khi truy cập dictionary và gọi hàm. Một ngoại lệ là khai báo dictionary trên một dòng, khi đó nên thêm một dấu cách sau dấu ngoặc nhọn mở và trước dấu ngoặc nhọn đóng. Điều này giúp dễ phân biệt dictionary với mảng bằng mắt, vì ký tự [] trông gần giống {} với hầu hết các font.

Đúng:

position.x = 5
position.y = target_position.y + 10
dict["key"] = 5
my_array = [4, 5, 6]
my_dictionary = { key = "value" }
print("foo")

Sai:

position.x=5
position.y = mpos.y+10
dict ["key"] = 5
myarray = [4,5,6]
my_dictionary = {key = "value"}
print ("foo")

Không dùng dấu cách để căn thẳng hàng các biểu thức theo chiều dọc:

x        = 100
y        = 100
velocity = 500

Dấu nháy

Dùng dấu nháy kép, trừ khi dấu nháy đơn giúp giảm số ký tự cần escape trong chuỗi. Xem các ví dụ bên dưới:

# Normal string.
print("hello world")

# Use double quotes as usual to avoid escapes.
print("hello 'world'")

# Use single quotes as an exception to the rule to avoid escapes.
print('hello "world"')

# Both quote styles would require 2 escapes; prefer double quotes if it's a tie.
print("'hello' \"world\"")

Số

Đừng bỏ số 0 ở đầu hoặc ở cuối trong số thực dấu phẩy động. Nếu không, chúng sẽ khó đọc hơn và khó phân biệt với số nguyên khi nhìn lướt.

Đúng:

var float_number = 0.234
var other_float_number = 13.0

Sai:

var float_number = .234
var other_float_number = 13.

Dùng chữ thường cho các chữ cái trong số thập lục phân, vì chiều cao thấp hơn của chúng giúp số dễ đọc hơn.

Đúng:

var hex_number = 0xfb8c0b

Sai:

var hex_number = 0xFB8C0B

Tận dụng dấu gạch dưới trong literal của GDScript để giúp các số lớn dễ đọc hơn.

Đúng:

var large_number = 1_234_567_890
var large_hex_number = 0xffff_f8f8_0000
var large_bin_number = 0b1101_0010_1010
# Numbers lower than 1000000 generally don't need separators.
var small_number = 12345

Sai:

var large_number = 1234567890
var large_hex_number = 0xfffff8f80000
var large_bin_number = 0b110100101010
# Numbers lower than 1000000 generally don't need separators.
var small_number = 12_345

Quy ước đặt tên

Các quy ước đặt tên này tuân theo phong cách của Godot Engine. Vi phạm chúng sẽ khiến mã của bạn xung đột với các quy ước đặt tên có sẵn, dẫn đến mã thiếu nhất quán. Bảng tóm tắt:

Kiểu

Quy ước

Ví dụ

Tên file

snake_case

yaml_parser.gd

Tên lớp

PascalCase

class_name YAMLParser

Tên node

PascalCase

Camera3D, Player

Hàm

snake_case

func load_level():

Biến

snake_case

var particle_effect

Signal

snake_case

signal door_opened

Hằng số

CONSTANT_CASE

const MAX_SPEED = 200

Tên enum

PascalCase

enum Element

Thành viên enum

CONSTANT_CASE

{EARTH, WATER, AIR, FIRE}

Tên file

Dùng snake_case cho tên file. Với các lớp có tên, hãy chuyển tên lớp dạng PascalCase sang snake_case:

# This file should be saved as `weapon.gd`.
class_name Weapon
extends Node

# This file should be saved as `yaml_parser.gd`.
class_name YAMLParser
extends Object

Điều này nhất quán với cách đặt tên file C++ trong mã nguồn Godot. Nó cũng tránh các vấn đề phân biệt chữ hoa/thường có thể phát sinh khi xuất (export) dự án từ Windows sang các nền tảng khác.

Lớp và node

Dùng PascalCase cho tên lớp và tên node:

extends CharacterBody3D

Cũng dùng PascalCase khi nạp một lớp vào hằng số hoặc biến:

const Weapon = preload("res://weapon.gd")

Hàm và biến

Dùng snake_case để đặt tên hàm và biến:

var particle_effect
func load_level():

Thêm một dấu gạch dưới (_) ở đầu tên các phương thức ảo mà người dùng phải override, các hàm private và các biến private:

var _counter = 0
func _recalculate_path():

Signal

Dùng thì quá khứ để đặt tên signal:

signal door_opened
signal score_changed

Hằng số và enum

Viết hằng số theo CONSTANT_CASE, tức là viết hoa toàn bộ và dùng dấu gạch dưới (_) để tách các từ:

const MAX_SPEED = 200

Dùng PascalCase cho tên enum và giữ chúng ở dạng số ít, vì chúng đại diện cho một kiểu. Dùng CONSTANT_CASE cho các thành viên của chúng, vì chúng là hằng số:

enum Element {
    EARTH,
    WATER,
    AIR,
    FIRE,
}

Viết enum với mỗi mục trên một dòng riêng. Điều này giúp dễ thêm comment tài liệu phía trên từng mục hơn, đồng thời tạo diff gọn hơn trong hệ thống quản lý phiên bản khi thêm hoặc xóa mục.

Đúng:

enum Element {
    EARTH,
    WATER,
    AIR,
    FIRE,
}

Sai:

enum Element { EARTH, WATER, AIR, FIRE }

Thứ tự mã

Phần này tập trung vào thứ tự mã. Về định dạng, xem Định dạng. Về quy ước đặt tên, xem Quy ước đặt tên.

Chúng tôi đề xuất tổ chức mã GDScript theo cách sau:

01. @tool, @icon, @static_unload
02. class_name
03. extends
04. ## doc comment

05. signals

Và sắp xếp các phương thức và biến của lớp theo thứ tự sau tùy theo access modifier của chúng:

1. public
2. private

Chúng tôi tối ưu thứ tự này để mã dễ đọc từ trên xuống dưới, giúp các lập trình viên đọc mã lần đầu hiểu cách nó hoạt động, và tránh các lỗi liên quan đến thứ tự khai báo biến.

Thứ tự mã này tuân theo bốn quy tắc kinh nghiệm:

  1. Thuộc tính và signal đứng trước, tiếp theo là các phương thức.

  2. Public đứng trước private.

  3. Các callback ảo đứng trước giao diện của lớp.

  4. Các hàm tạo và khởi tạo đối tượng, _init và _ready, đứng trước các hàm thay đổi đối tượng khi chạy.

Khai báo lớp

Nếu mã được dùng để chạy trong trình chỉnh sửa, hãy đặt annotation @tool ở dòng đầu tiên của script.

Tiếp theo là @icon (tùy chọn), rồi đến class_name nếu cần. Bạn có thể biến một file GDScript thành một kiểu toàn cục trong dự án bằng class_name. Để biết thêm thông tin, xem Đăng ký lớp có tên. Nếu lớp là một lớp trừu tượng, hãy thêm @abstract trước từ khóa class_name.

Sau đó, thêm từ khóa extends nếu lớp kế thừa một kiểu có sẵn.

Tiếp theo, bạn nên có các comment tài liệu (tùy chọn) của lớp. Ví dụ, bạn có thể dùng chúng để giải thích cho đồng đội vai trò của lớp, cách nó hoạt động và cách các lập trình viên khác nên sử dụng nó.

@abstract
class_name MyNode
extends Node
## A brief description of the class's role and functionality.
##
## The description of the script, what it can do,
## and any further detail.

Với các lớp bên trong (inner class), hãy dùng khai báo trên một dòng:

## A brief description of the class's role and functionality.
##
## The description of the script, what it can do,
## and any further detail.
@abstract class MyNode extends Node:
    pass

Signal và thuộc tính

Viết các khai báo signal, tiếp theo là thuộc tính, tức là các biến thành viên, sau docstring.

Enum nên đứng sau signal, vì bạn có thể dùng chúng làm export hint cho các thuộc tính khác.

Sau đó, viết hằng số, biến được export, biến public, private và onready, theo đúng thứ tự đó.

signal player_spawned(position)

enum Job {
    KNIGHT,
    WIZARD,
    ROGUE,
    HEALER,
    SHAMAN,
}

const MAX_LIVES = 3

@export var job: Job = Job.KNIGHT
@export var max_health = 50
@export var attack = 5

var health = max_health:
    set(new_health):
        health = new_health

var _speed = 300.0

@onready var sword = get_node("Sword")
@onready var gun = get_node("Gun")

Ghi chú

GDScript đánh giá các biến @onready ngay trước callback _ready. Bạn có thể dùng điều đó để cache các node phụ thuộc, tức là lấy các node con trong scene mà lớp của bạn phụ thuộc vào. Ví dụ ở trên minh họa điều này.

Biến thành viên

Đừng khai báo biến thành viên nếu chúng chỉ được dùng cục bộ trong một phương thức, vì điều đó làm mã khó theo dõi hơn. Thay vào đó, hãy khai báo chúng là biến cục bộ trong thân phương thức.

Biến cục bộ

Khai báo biến cục bộ càng gần nơi dùng lần đầu càng tốt. Điều này giúp dễ theo dõi mã hơn, không phải cuộn quá nhiều để tìm nơi biến được khai báo.

Phương thức và hàm static

Sau các thuộc tính của lớp là các phương thức.

Bắt đầu với phương thức callback _init(), được engine gọi khi tạo đối tượng trong bộ nhớ. Tiếp theo là callback _ready(), được Godot gọi khi thêm một node vào scene tree.

Các hàm này nên đứng đầu vì chúng cho thấy cách đối tượng được khởi tạo.

Các callback ảo có sẵn khác, như _unhandled_input() và _physics_process, nên đứng tiếp theo. Chúng điều khiển vòng lặp chính của đối tượng và các tương tác với game engine.

Phần còn lại của giao diện lớp, gồm các phương thức public và private, đứng sau đó, theo đúng thứ tự này.

func _init():
    add_to_group("state_machine")


func _ready():
    state_changed.connect(_on_state_changed)
    _state.enter()


func _unhandled_input(event):
    _state.unhandled_input(event)


func transition_to(target_state_path, msg={}):
    if not has_node(target_state_path):
        return

    var target_state = get_node(target_state_path)
    assert(target_state.is_composite == false)

    _state.exit()
    self._state = target_state
    _state.enter(msg)
    Events.player_state_changed.emit(_state.name)


func _on_state_changed(previous, new):
    print("state changed")
    state_changed.emit()

Kiểu tĩnh

GDScript hỗ trợ kiểu tĩnh tùy chọn.

Kiểu được khai báo

Để khai báo kiểu của một biến, dùng <variable>: <type>:

var health: int = 0

Để khai báo kiểu trả về của một hàm, dùng -> <type>:

func heal(amount: int) -> void:

Kiểu được suy luận

Trong hầu hết trường hợp, bạn có thể để trình biên dịch suy luận kiểu bằng :=. Ưu tiên := khi kiểu được viết trên cùng dòng với phép gán, nếu không thì ưu tiên viết kiểu một cách tường minh.

Đúng:

# The type can be int or float, and thus should be stated explicitly.
var health: int = 0

# The type is clearly inferred as Vector3.
var direction := Vector3(1, 2, 3)

Thêm type hint khi kiểu không rõ ràng, và bỏ type hint khi nó thừa.

Sai:

# Typed as int, but it could be that float was intended.
var health := 0

# The type hint has redundant information.
var direction: Vector3 = Vector3(1, 2, 3)

# What type is this? It's not immediately clear to the reader, so it's bad.
var value := complex_function()

Trong một số trường hợp, kiểu phải được khai báo tường minh, nếu không hành vi sẽ không như mong đợi vì trình biên dịch chỉ có thể dùng kiểu trả về của hàm. Ví dụ, get_node() không thể suy luận kiểu trừ khi scene hoặc file của node đã được nạp vào bộ nhớ. Trong trường hợp này, bạn nên đặt kiểu một cách tường minh.

Đúng:

@onready var health_bar: ProgressBar = get_node("UI/LifeBar")

Sai:

# The compiler can't infer the exact type and will use Node
# instead of ProgressBar.
@onready var health_bar := get_node("UI/LifeBar")

Ngoài ra, bạn có thể dùng từ khóa as để ép kiểu giá trị trả về, và kiểu đó sẽ được dùng để suy luận kiểu của biến.

@onready var health_bar := get_node("UI/LifeBar") as ProgressBar
# health_bar will be typed as ProgressBar

Ghi chú

Cách này được xem là an toàn kiểu hơn type hint, nhưng kém an toàn với null hơn vì nó âm thầm ép biến thành null khi kiểu không khớp lúc chạy, mà không có lỗi/cảnh báo nào.
