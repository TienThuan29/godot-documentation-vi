Signal trong C#

Để xem giải thích chi tiết về signal nói chung, hãy xem phần Sử dụng signal trong bài hướng dẫn từng bước.

Signal được triển khai bằng event của C#, cách biểu diễn mẫu observer chuẩn mực trong C#. Đây là cách được khuyến nghị để dùng signal trong C# và là trọng tâm của trang này.

Trong một số trường hợp, cần dùng các API cũ Connect() và Disconnect(). Xem Dùng Connect và Disconnect để biết thêm chi tiết.

Nếu gặp System.ObjectDisposedException khi xử lý một signal, có thể bạn đã quên ngắt kết nối signal. Xem Tự động ngắt kết nối khi đối tượng nhận bị giải phóng để biết thêm chi tiết.

Signal dưới dạng event C#

Để tăng tính an toàn kiểu, mọi signal của Godot cũng đều có sẵn dưới dạng event. Bạn có thể xử lý các event này như mọi event khác, bằng toán tử += và -=.

Timer myTimer = GetNode<Timer>("Timer");
myTimer.Timeout += () => GD.Print("Timeout!");

Ngoài ra, bạn luôn có thể truy cập tên signal gắn với một loại node thông qua lớp lồng SignalName của nó. Điều này hữu ích khi, ví dụ, bạn muốn await một signal (xem Từ khóa await).

await ToSignal(GetTree(), SceneTree.SignalName.ProcessFrame);

Signal tùy chỉnh dưới dạng event C#

Để khai báo một event tùy chỉnh trong script C#, hãy dùng attribute [Signal] trên một kiểu delegate public. Lưu ý rằng tên của delegate này cần kết thúc bằng EventHandler.

[Signal]
public delegate void MySignalEventHandler();

[Signal]
public delegate void MySignalWithArgumentEventHandler(string myString);

Sau khi làm xong, Godot sẽ tự động tạo các event phù hợp ở phía sau. Sau đó bạn có thể dùng các event đó như với mọi signal Godot khác. Lưu ý rằng các event được đặt tên theo tên delegate của bạn bỏ đi phần EventHandler ở cuối.

public override void _Ready()
{
    MySignal += () => GD.Print("Hello!");
    MySignalWithArgument += SayHelloTo;
}

private void SayHelloTo(string name)
{
    GD.Print($"Hello {name}!");
}

Cảnh báo

Nếu muốn kết nối tới các signal này trong trình chỉnh sửa, bạn cần build (lại) dự án để chúng xuất hiện.

Để làm vậy, bạn có thể nhấn nút Build ở góc trên bên phải của trình chỉnh sửa.

Phát signal

Để phát signal, hãy dùng phương thức EmitSignal. Lưu ý rằng, giống như signal do engine định nghĩa, tên signal tùy chỉnh của bạn được liệt kê trong lớp lồng SignalName.

public void MyMethodEmittingSignals()
{
    EmitSignal(SignalName.MySignal);
    EmitSignal(SignalName.MySignalWithArgument, "World");
}

Khác với các event C# khác, bạn không thể dùng Invoke để kích hoạt event gắn với signal Godot.

Signal hỗ trợ đối số thuộc bất kỳ kiểu tương thích Variant nào.

Do đó, mọi Node hoặc RefCounted sẽ tự động tương thích, nhưng các đối tượng dữ liệu tùy chỉnh sẽ cần kế thừa từ GodotObject hoặc một trong các lớp con của nó.

using Godot;

public partial class DataObject : GodotObject
{
    public string MyFirstString { get; set; }
    public string MySecondString { get; set; }
}

Giá trị ràng buộc

Đôi khi bạn sẽ muốn ràng buộc giá trị vào signal khi thiết lập kết nối, thay vì (hoặc bên cạnh) khi signal được phát. Để làm vậy, bạn có thể dùng hàm ẩn danh như trong ví dụ sau.

Ở đây, signal Button.Pressed không nhận đối số nào. Nhưng chúng ta muốn dùng cùng một ModifyValue cho cả nút "cộng" và "trừ". Vì vậy chúng ta ràng buộc giá trị điều chỉnh tại thời điểm kết nối signal.

public int Value { get; private set; } = 1;

public override void _Ready()
{
    Button plusButton = GetNode<Button>("PlusButton");
    plusButton.Pressed += () => ModifyValue(1);

    Button minusButton = GetNode<Button>("MinusButton");
    minusButton.Pressed += () => ModifyValue(-1);
}

private void ModifyValue(int modifier)
{
    Value += modifier;
}

Tạo signal lúc chạy

Cuối cùng, bạn có thể tạo signal tùy chỉnh trực tiếp trong khi game đang chạy. Hãy dùng phương thức AddUserSignal cho việc này. Lưu ý rằng nó cần được thực thi trước bất kỳ lần sử dụng nào của các signal đó (kết nối hoặc phát chúng). Ngoài ra, signal tạo theo cách này sẽ không hiển thị qua lớp lồng SignalName.

public override void _Ready()
{
    AddUserSignal("MyCustomSignal");
    EmitSignal("MyCustomSignal");
}

Dùng Connect và Disconnect

Nhìn chung, không khuyến khích dùng Connect() và Disconnect(). Các API này không cung cấp nhiều an toàn kiểu như event. Tuy nhiên, chúng cần thiết để kết nối tới signal được định nghĩa bằng GDScript và để truyền ConnectFlags.

Trong ví dụ sau, nhấn nút lần đầu sẽ in ra Greetings!. OneShot ngắt kết nối signal, nên nhấn nút lần nữa sẽ không làm gì.

public override void _Ready()
{
    Button button = GetNode<Button>("GreetButton");
    button.Connect(Button.SignalName.Pressed, Callable.From(OnButtonPressed), (uint)GodotObject.ConnectFlags.OneShot);
}

public void OnButtonPressed()
{
    GD.Print("Greetings!");
}

Tự động ngắt kết nối khi đối tượng nhận bị giải phóng

Thông thường, khi bất kỳ GodotObject nào bị giải phóng (chẳng hạn bất kỳ Node nào), Godot tự động ngắt mọi kết nối gắn với đối tượng đó. Điều này xảy ra với cả bên phát signal lẫn bên nhận signal.

Ví dụ, một node với đoạn mã này sẽ in "Hello!" khi nút được nhấn, rồi tự giải phóng. Giải phóng node sẽ ngắt kết nối signal, nên nhấn nút lần nữa sẽ không làm gì:

public override void _Ready()
{
    Button myButton = GetNode<Button>("../MyButton");
    myButton.Pressed += SayHello;
}

private void SayHello()
{
    GD.Print("Hello!");
    Free();
}

Khi bên nhận signal bị giải phóng trong khi bên phát signal vẫn còn tồn tại, trong một số trường hợp việc tự động ngắt kết nối sẽ không xảy ra:

  • Signal được kết nối với một biểu thức lambda có capture biến.

  • Signal là signal tùy chỉnh.

Các phần sau giải thích chi tiết hơn những trường hợp này và đưa ra gợi ý về cách ngắt kết nối thủ công.

Ghi chú

Việc tự động ngắt kết nối hoàn toàn đáng tin cậy nếu bên phát signal được giải phóng trước bất kỳ bên nhận nào của nó. Với phong cách dự án ưu tiên mẫu này, các giới hạn trên có thể không đáng lo.

Không tự động ngắt kết nối: biểu thức lambda có capture biến

Nếu bạn kết nối tới một biểu thức lambda có capture biến, Godot không thể biết lambda đó gắn với instance đã tạo ra nó. Điều này khiến ví dụ sau có thể có hành vi không mong muốn:

Timer myTimer = GetNode<Timer>("../Timer");
int x = 0;
myTimer.Timeout += () =>
{
    x++; // This lambda expression captures x.
    GD.Print($"Tick {x} my name is {Name}");
    if (x == 3)
    {
        GD.Print("Time's up!");
        Free();
    }
};

Tick 1, my name is ExampleNode
Tick 2, my name is ExampleNode
Tick 3, my name is ExampleNode
Time's up!
[...] System.ObjectDisposedException: Cannot access a disposed object.

Ở tick 4, biểu thức lambda cố truy cập thuộc tính Name của node, nhưng node đã bị giải phóng. Điều này gây ra ngoại lệ.

Để ngắt kết nối, hãy giữ tham chiếu tới delegate được tạo bởi biểu thức lambda và truyền nó cho -=. Ví dụ, node này kết nối và ngắt kết nối bằng các phương thức vòng đời _EnterTree và _ExitTree:

[Export]
public Timer MyTimer { get; set; }

private Action _tick;

public override void _EnterTree()
{
    int x = 0;
    _tick = () =>
    {
        x++;
        GD.Print($"Tick {x} my name is {Name}");
        if (x == 3)
        {
            GD.Print("Time's up!");
            Free();
        }
    };
    MyTimer.Timeout += _tick;
}

public override void _ExitTree()
{
    MyTimer.Timeout -= _tick;
}

Trong ví dụ này, Free khiến node rời khỏi cây, điều này gọi _ExitTree. _ExitTree ngắt kết nối signal, nên _tick không bao giờ được gọi lại nữa.

Phương thức vòng đời nào nên dùng tùy thuộc vào việc node làm gì. Một lựa chọn khác là kết nối signal trong _Ready và ngắt kết nối trong Dispose.

Ghi chú

Godot dùng Delegate.Target để xác định delegate gắn với instance nào. Khi biểu thức lambda không capture biến, Target của delegate được sinh ra là instance đã tạo delegate. Khi có biến được capture, Target lại trỏ tới một kiểu được sinh ra để lưu biến được capture. Đây chính là điều làm mất liên kết. Nếu muốn biết một delegate có được tự động dọn dẹp hay không, hãy thử kiểm tra Target của nó.

Callable.From không ảnh hưởng tới Delegate.Target, nên kết nối một lambda có capture biến bằng Connect cũng không tốt hơn +=.

Không tự động ngắt kết nối: signal tùy chỉnh

Kết nối tới một signal tùy chỉnh bằng += sẽ không tự động ngắt kết nối khi node nhận bị giải phóng.

Để ngắt kết nối, hãy dùng -= vào thời điểm thích hợp. Ví dụ:

[Export]
public MyClass Target { get; set; }

public override void _EnterTree()
{
    Target.MySignal += OnMySignal;
}

public override void _ExitTree()
{
    Target.MySignal -= OnMySignal;
}

Một giải pháp khác là dùng Connect, phương thức này có tự động ngắt kết nối với signal tùy chỉnh:

[Export]
public MyClass Target { get; set; }

public override void _EnterTree()
{
    Target.Connect(MyClass.SignalName.MySignal, Callable.From(OnMySignal));
}
