Cơ bản về C#

Giới thiệu

Trang này giới thiệu ngắn gọn về C#, cả C# là gì và cách dùng nó trong Godot. Sau đó, bạn có thể muốn xem cách dùng các tính năng cụ thể, đọc về khác biệt giữa API C# và GDScript, và xem (lại) phần Scripting của bài hướng dẫn từng bước.

C# là một ngôn ngữ lập trình bậc cao do Microsoft phát triển. Trong Godot, nó được triển khai với runtime .NET hiện đại.

Chú ý

Hiện chưa thể xuất các dự án viết bằng C# với Godot 4 sang nền tảng web. Để dùng C# trên nền tảng web, hãy cân nhắc dùng Godot 3. Hỗ trợ nền tảng Android và iOS có từ Godot 4.2, nhưng vẫn đang thử nghiệm và có một số hạn chế.

Ghi chú

Đây không phải là bài hướng dẫn đầy đủ về toàn bộ ngôn ngữ C#. Nếu bạn chưa quen với cú pháp hay tính năng của nó, hãy xem hướng dẫn C# của Microsoft hoặc tìm một tài liệu nhập môn phù hợp ở nơi khác.

Yêu cầu trước

Godot đóng gói sẵn các phần của .NET cần thiết để chạy game đã biên dịch. Tuy nhiên, Godot không đóng gói các công cụ cần để build và biên dịch game, như MSBuild và trình biên dịch C#. Chúng có trong .NET SDK và cần được cài riêng.

Tóm lại, bạn phải cài .NET SDK và phiên bản Godot có hỗ trợ .NET.

Tải và cài phiên bản ổn định mới nhất của SDK từ trang tải .NET. Godot 4.5 yêu cầu .NET 8 trở lên, nhưng xuất sang Android yêu cầu .NET 9 trở lên.

Quan trọng

Hãy đảm bảo cài phiên bản 64-bit của SDK nếu bạn đang dùng Godot bản 64-bit.

Nếu bạn build Godot từ mã nguồn, hãy làm theo các bước bật hỗ trợ .NET trong bản build như mô tả ở trang Biên dịch với .NET.

Cấu hình trình chỉnh sửa bên ngoài

Hỗ trợ C# trong trình chỉnh sửa script tích hợp của Godot còn rất hạn chế. Hãy cân nhắc dùng một IDE hoặc trình chỉnh sửa bên ngoài, như Visual Studio Code hoặc Visual Studio. Chúng cung cấp tự động hoàn thành, gỡ lỗi và các tính năng hữu ích khác cho C#. Để chọn trình chỉnh sửa bên ngoài trong Godot, nhấp vào Editor → Editor Settings và cuộn xuống Dotnet. Trong Dotnet, nhấp vào Editor và chọn trình chỉnh sửa bên ngoài bạn muốn. Godot hiện hỗ trợ các trình chỉnh sửa bên ngoài sau:

  • Visual Studio 2022

  • Visual Studio Code

  • MonoDevelop

  • Visual Studio for Mac

  • JetBrains Rider

Xem các phần sau để biết cách cấu hình trình chỉnh sửa bên ngoài:

JetBrains Rider

Sau khi đọc phần "Prerequisites", bạn có thể tải và cài JetBrains Rider.

Trong menu Editor → Editor Settings của Godot:

  • Đặt Dotnet -> Editor -> External Editor thành JetBrains Rider.

Trong Rider:

  • Đặt MSBuild version thành .NET Core.

  • Nếu bạn dùng Rider phiên bản thấp hơn 2024.2, hãy cài plugin Godot support. Chức năng này hiện đã được tích hợp sẵn trong Rider.

Visual Studio Code

Sau khi đọc phần "Prerequisites", bạn có thể tải và cài Visual Studio Code (còn gọi là VS Code).

Trong menu Editor → Editor Settings của Godot:

  • Đặt Dotnet -> Editor -> External Editor thành Visual Studio Code.

Trong Visual Studio Code:

  • Cài extension C#.

Để cấu hình dự án cho việc gỡ lỗi, bạn cần file tasks.json và launch.json trong thư mục .vscode với cấu hình cần thiết.

Đây là ví dụ launch.json:

{
    "version": "0.2.0",
    "configurations": [
        {
            "name": "Play",
            "type": "coreclr",
            "request": "launch",
            "preLaunchTask": "build",
            "program": "${env:GODOT4}",
            "args": [],
            "cwd": "${workspaceFolder}",
            "stopAtEntry": false,
        }
    ]
}

Để cấu hình khởi chạy này hoạt động, bạn cần thiết lập biến môi trường GODOT4 trỏ tới file thực thi Godot, hoặc thay tham số program bằng đường dẫn tới file thực thi Godot.

Đây là ví dụ tasks.json:

{
    "version": "2.0.0",
    "tasks": [
        {
            "label": "build",
            "command": "dotnet",
            "type": "process",
            "args": [
                "build"
            ],
            "problemMatcher": "$msCompile"
        }
    ]
}

Giờ đây, khi bạn khởi động trình gỡ lỗi trong Visual Studio Code, dự án Godot của bạn sẽ chạy.

Visual Studio (chỉ Windows)

Tải và cài phiên bản mới nhất của Visual Studio. Visual Studio sẽ bao gồm các SDK cần thiết nếu bạn chọn đúng workload, nên bạn không cần cài thủ công những thứ liệt kê trong phần "Prerequisites".

Khi cài Visual Studio, hãy chọn workload này:

  • .NET desktop development

Trong menu Editor → Editor Settings của Godot:

  • Đặt Dotnet -> Editor -> External Editor thành Visual Studio.

Ghi chú

Nếu bạn thấy lỗi như "Unable to find package Godot.NET.Sdk", có thể cấu hình NuGet của bạn bị sai và cần sửa.

Một cách đơn giản để sửa file cấu hình NuGet là tạo lại nó. Trong cửa sổ trình quản lý file, vào %AppData%\NuGet. Đổi tên hoặc xóa file NuGet.Config. Khi bạn build lại dự án Godot, file sẽ tự động được tạo với các giá trị mặc định.

Để gỡ lỗi script C# bằng Visual Studio, hãy mở file .sln được tạo ra sau khi mở script C# đầu tiên trong trình chỉnh sửa. Trong menu Debug, vào mục Debug Properties cho dự án của bạn. Nhấp nút Create a new profile và chọn Executable. Trong trường Executable, duyệt tới đường dẫn của trình chỉnh sửa Godot bản C#, hoặc gõ %GODOT4% nếu bạn đã tạo biến môi trường cho đường dẫn file thực thi Godot. Đó phải là đường dẫn tới file thực thi Godot chính, không phải bản 'console'. Ở Working Directory, gõ một dấu chấm, ., nghĩa là thư mục hiện tại. Đồng thời đánh dấu ô Enable native code debugging. Giờ bạn có thể đóng cửa sổ này, nhấp mũi tên xuống ở danh sách thả xuống debug profile và chọn launch profile mới. Nhấn nút start màu xanh lá, game của bạn sẽ bắt đầu chạy ở chế độ debug.

Tạo script C#

Sau khi thiết lập thành công C# cho Godot, bạn sẽ thấy tùy chọn sau khi chọn Attach Script trong menu ngữ cảnh của một node trong scene:

Lưu ý rằng dù một số chi tiết thay đổi, hầu hết khái niệm vẫn hoạt động như nhau khi dùng C# để viết script. Nếu bạn mới làm quen với Godot, lúc này bạn có thể muốn theo các bài hướng dẫn trong Ngôn ngữ script. Dù một số trang tài liệu vẫn thiếu ví dụ C#, hầu hết khái niệm có thể chuyển từ GDScript sang.

Thiết lập dự án và quy trình làm việc

Khi bạn tạo script C# đầu tiên, Godot khởi tạo các file dự án C# cho dự án Godot của bạn. Việc này bao gồm tạo một C# solution (.sln) và một file dự án (.csproj), cũng như một số file và thư mục tiện ích (.godot/mono). Tất cả trừ .godot/mono đều quan trọng và nên được commit vào hệ thống quản lý phiên bản. Mọi thứ trong .godot có thể an toàn thêm vào danh sách ignore của VCS. Khi khắc phục sự cố, đôi khi xóa thư mục .godot/mono và để nó tự tạo lại sẽ có ích.

Ví dụ

Đây là một script C# trống với vài chú thích để minh họa cách nó hoạt động.

using Godot;

public partial class YourCustomClass : Node
{
    // Member variables here, example:
    private int _a = 2;
    private string _b = "textvar";

    public override void _Ready()
    {
        // Called every time the node is added to the scene.
        // Initialization here.
        GD.Print("Hello from C# to Godot :)");
    }

    public override void _Process(double delta)
    {
        // Called every frame. Delta is time since the last frame.
        // Update game logic here.
    }
}

Như bạn thấy, các hàm thường nằm ở phạm vi toàn cục trong GDScript, như hàm print của Godot, có trong lớp tĩnh GD thuộc namespace Godot. Để xem danh sách đầy đủ các phương thức trong lớp GD, hãy xem các trang tham chiếu lớp @GDScript và @GlobalScope.

Ghi chú

Hãy nhớ rằng lớp bạn muốn gắn vào node phải có cùng tên với file .cs. Nếu không, bạn sẽ gặp lỗi sau:

"Cannot find class XXX for script res://XXX.cs"

Khác biệt chung giữa C# và GDScript

API C# dùng PascalCase thay vì snake_case như trong GDScript/C++. Khi có thể, các field và getter/setter đã được chuyển thành property. Nhìn chung, API Godot cho C# cố gắng viết theo phong cách chuẩn của C# nhiều nhất có thể.

Để biết thêm thông tin, xem trang Khác biệt API giữa C# và GDScript.

Cảnh báo

Bạn cần build (lại) các assembly của dự án mỗi khi muốn thấy biến hoặc signal export mới trong trình chỉnh sửa. Có thể kích hoạt build thủ công bằng cách nhấp nút Build ở góc trên bên phải của trình chỉnh sửa.

Bạn cũng cần build lại các assembly của dự án để áp dụng thay đổi trong các script "tool".

Những điểm cần lưu ý và vấn đề đã biết

Vì hỗ trợ C# còn khá mới trong Godot, vẫn còn một số khó khăn ban đầu và những điểm cần hoàn thiện. Dưới đây là danh sách các vấn đề quan trọng nhất bạn nên biết khi bắt đầu với C# trong Godot, nhưng nếu còn nghi ngờ, hãy xem thêm trình theo dõi issue chính thức cho các vấn đề .NET.

  • Có thể viết plugin cho trình chỉnh sửa, nhưng hiện khá rắc rối.

  • Hiện trạng thái không được lưu và khôi phục khi hot-reload, ngoại trừ các biến được export.

  • Script C# được gắn phải tham chiếu tới một lớp có tên trùng với tên file.

  • Có một số phương thức như Get()/Set(), Call()/CallDeferred() và phương thức kết nối signal Connect() phụ thuộc vào quy ước đặt tên snake_case của API Godot. Vì vậy, khi dùng ví dụ CallDeferred("AddChild"), AddChild sẽ không hoạt động vì API đang chờ phiên bản snake_case gốc là add_child. Tuy nhiên, bạn có thể dùng mọi property hoặc phương thức tùy chỉnh mà không bị giới hạn này. Nên dùng các StringName được cung cấp trong PropertyName, MethodName và SignalName để tránh cấp phát StringName thừa và không phải lo về cách đặt tên snake_case.

Từ Godot 4.0, việc xuất dự án .NET được hỗ trợ trên các nền tảng desktop (Linux, Windows và macOS). Các nền tảng khác sẽ được hỗ trợ trong các bản phát hành 4.x sau.

Những lỗi thường gặp

Bạn có thể gặp lỗi sau khi cố sửa một số giá trị trong đối tượng Godot, ví dụ khi cố đổi tọa độ X của một Node2D:

public partial class MyNode2D : Node2D
{
    public override void _Ready()
    {
        Position.X = 100.0f;
        // CS1612: Cannot modify the return value of 'Node2D.Position' because
        // it is not a variable.
    }
}

Điều này hoàn toàn bình thường. Struct (trong ví dụ này là Vector2) trong C# được sao chép khi gán, nghĩa là khi bạn lấy một đối tượng như vậy từ property hoặc indexer, bạn nhận được bản sao của nó chứ không phải chính đối tượng đó. Sửa bản sao đó mà không gán lại sau đó sẽ không có tác dụng gì.

Cách khắc phục rất đơn giản: lấy toàn bộ struct, sửa giá trị bạn muốn, rồi gán lại property.

var newPosition = Position;
newPosition.X = 100.0f;
Position = newPosition;

Từ C# 10, bạn cũng có thể dùng biểu thức with trên struct, cho phép làm điều tương tự trong một dòng.

Position = Position with { X = 100.0f };

Bạn có thể đọc thêm về lỗi này trong tài liệu tham khảo ngôn ngữ C#.

Hiệu năng của C# trong Godot

Xem thêm

Để so sánh hiệu năng giữa các ngôn ngữ Godot hỗ trợ, xem Ngôn ngữ lập trình nào nhanh nhất?.

Hầu hết property của các đối tượng C# trong Godot dựa trên GodotObject (ví dụ mọi Node như Control hoặc Node3D như Camera3D) đều cần lời gọi native (interop) vì chúng giao tiếp với lõi C++ của Godot. Hãy cân nhắc gán giá trị của các property đó vào biến cục bộ nếu bạn cần sửa hoặc đọc chúng nhiều lần tại cùng một vị trí trong code:

using Godot;

public partial class YourCustomClass : Node3D
{
    private void ExpensiveReposition()
    {
        for (var i = 0; i < 10; i++)
        {
            // Position is read and set 10 times which incurs native interop.
            // Furthermore the object is repositioned 10 times in 3D space which
            // takes additional time.
            Position += new Vector3(i, i);
        }
    }

    private void Reposition()
    {
        // A variable is used to avoid native interop for Position on every loop.
        var newPosition = Position;
        for (var i = 0; i < 10; i++)
        {
            newPosition += new Vector3(i, i);
        }
        // Setting Position only once avoids native interop and repositioning in 3D space.
        Position = newPosition;
    }
}

Truyền mảng thô (như byte[]) hoặc string vào API C# của Godot cần marshalling, vốn tương đối tốn kém.

Chuyển đổi ngầm định từ string sang NodePath hoặc StringName chịu cả chi phí interop native lẫn marshalling, vì string phải được marshal và truyền vào constructor native tương ứng.

Dùng package NuGet trong Godot

Có thể cài và dùng các package NuGet với Godot, như với bất kỳ dự án C# nào. Nhiều IDE có thể thêm package trực tiếp. Bạn cũng có thể thêm thủ công bằng cách thêm tham chiếu package vào file .csproj nằm ở thư mục gốc của dự án:

    <ItemGroup>
        <PackageReference Include="Newtonsoft.Json" Version="11.0.2" />
    </ItemGroup>
    ...
</Project>

Godot tự động tải và thiết lập các package NuGet mới thêm vào ở lần build dự án tiếp theo.

Profiling code C#

Có thể dùng các công cụ sau để profiling hiệu năng và bộ nhớ cho managed code của bạn:

  • JetBrains Rider với plugin dotTrace/dotMemory.

  • JetBrains dotTrace/dotMemory bản độc lập.

  • Visual Studio.

Có thể profiling managed code và unmanaged code cùng lúc bằng cả công cụ của JetBrains và Visual Studio, nhưng chỉ trên Windows.
