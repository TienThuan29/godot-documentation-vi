Tính năng ngôn ngữ C#

Trang này giới thiệu tổng quan các tính năng thường dùng của cả C# và Godot, cũng như cách chúng được dùng cùng nhau.

Chuyển đổi kiểu và ép kiểu

C# là ngôn ngữ định kiểu tĩnh. Vì vậy, bạn không thể làm như sau:

var mySprite = GetNode("MySprite");
mySprite.SetFrame(0);

Phương thức GetNode() trả về một instance Node. Bạn phải chuyển đổi tường minh nó sang kiểu dẫn xuất mong muốn, trong trường hợp này là Sprite2D.

Để làm điều này, C# cho bạn nhiều lựa chọn.

Ép kiểu và kiểm tra kiểu

Ném ra InvalidCastException nếu node trả về không thể ép kiểu sang Sprite2D. Bạn sẽ dùng cách này thay cho toán tử as nếu khá chắc chắn rằng nó sẽ không thất bại.

Sprite2D mySprite = (Sprite2D)GetNode("MySprite");
mySprite.SetFrame(0);

Dùng toán tử AS

Toán tử as trả về null nếu node không thể ép kiểu sang Sprite2D, và vì lý do đó, nó không thể dùng với kiểu giá trị.

Sprite2D mySprite = GetNode("MySprite") as Sprite2D;
// Only call SetFrame() if mySprite is not null
mySprite?.SetFrame(0);

Dùng các phương thức generic

Godot cũng cung cấp các phương thức generic để việc chuyển đổi kiểu này diễn ra trong suốt.

GetNode<T>() ép kiểu node trước khi trả về. Nó sẽ ném ra InvalidCastException nếu node không thể ép sang kiểu mong muốn.

Sprite2D mySprite = GetNode<Sprite2D>("MySprite");
mySprite.SetFrame(0);

GetNodeOrNull<T>() dùng toán tử as và sẽ trả về null nếu node không thể ép sang kiểu mong muốn.

Sprite2D mySprite = GetNodeOrNull<Sprite2D>("MySprite");
// Only call SetFrame() if mySprite is not null
mySprite?.SetFrame(0);

Kiểm tra kiểu bằng toán tử IS

Để kiểm tra node có thể ép kiểu sang Sprite2D hay không, bạn có thể dùng toán tử is. Toán tử is trả về false nếu node không thể ép sang Sprite2D, ngược lại trả về true. Lưu ý rằng khi dùng toán tử is với null, kết quả luôn là false.

if (GetNode("MySprite") is Sprite2D)
{
    // Yup, it's a Sprite2D!
}

if (null is Sprite2D)
{
    // This block can never happen.
}

Bạn cũng có thể khai báo một biến mới để lưu có điều kiện kết quả ép kiểu nếu toán tử is trả về true.

if (GetNode("MySprite") is Sprite2D mySprite)
{
    // The mySprite variable only exists inside this block, and it's never null.
    mySprite.SetFrame(0);
}

Để kiểm tra kiểu nâng cao hơn, bạn có thể tìm hiểu về Pattern Matching.

Các define của preprocessor

Godot có một tập các define cho phép bạn thay đổi mã C# tùy theo môi trường mà bạn đang biên dịch tới.

Ví dụ

Ví dụ, bạn có thể thay đổi mã dựa trên nền tảng:

    public override void _Ready()
    {
#if (GODOT_MOBILE || GODOT_WEB)
        // Use simple objects when running on less powerful systems.
        SpawnSimpleObjects();
#else
        SpawnComplexObjects();
#endif
    }

Hoặc bạn có thể phát hiện mã của mình đang chạy trong engine nào, hữu ích khi tạo thư viện dùng chung cho nhiều engine:

    public void MyPlatformPrinter()
    {
#if GODOT
        GD.Print("This is Godot.");
#elif UNITY_5_3_OR_NEWER
        print("This is Unity.");
#else
        throw new NotSupportedException("Only Godot and Unity are supported.");
#endif
    }

Hoặc bạn có thể viết script nhắm tới nhiều phiên bản Godot và tận dụng các tính năng chỉ có ở một số phiên bản trong đó:

    public void UseCoolFeature()
    {
#if GODOT4_3_OR_GREATER || GODOT4_2_2_OR_GREATER
        // Use CoolFeature, that was added to Godot in 4.3 and cherry-picked into 4.2.2, here.
#else
        // Use a workaround for the absence of CoolFeature here.
#endif
    }

Danh sách đầy đủ các define

  • GODOT luôn được định nghĩa cho các dự án Godot.

  • TOOLS được định nghĩa khi build với cấu hình Debug (trình chỉnh sửa và editor player).

  • GODOT_REAL_T_IS_DOUBLE được định nghĩa khi thuộc tính GodotFloat64 được đặt thành true.

  • Một trong GODOT_LINUXBSD, GODOT_WINDOWS, GODOT_OSX, GODOT_ANDROID, GODOT_IOS, GODOT_WEB tùy theo hệ điều hành. Các tên này có thể thay đổi trong tương lai. Chúng được tạo từ phương thức get_name() của singleton OS, nhưng không phải mọi hệ điều hành mà phương thức này trả về đều là hệ điều hành mà Godot với .NET chạy được.

  • GODOTX, GODOTX_Y, GODOTX_Y_Z, GODOTx_OR_GREATER, GODOTX_y_OR_GREATER và GODOTX_Y_z_OR_GREATER, trong đó X, Y và Z được thay bằng phiên bản major, minor và patch hiện tại của Godot. x, y và z được thay bằng mọi giá trị từ 0 đến số phiên bản hiện tại của thành phần đó.

    Ghi chú

    Các define này được thêm lần đầu trong Godot 4.0.4 và 4.1. Không tồn tại define phiên bản cho các phiên bản trước đó, bất kể phiên bản Godot hiện tại là gì.

    Ví dụ: Godot 4.0.5 định nghĩa GODOT4, GODOT4_OR_GREATER, GODOT4_0, GODOT4_0_OR_GREATER, GODOT4_0_5, GODOT4_0_4_OR_GREATER và GODOT4_0_5_OR_GREATER. Godot 4.3.2 định nghĩa GODOT4, GODOT4_OR_GREATER, GODOT4_3, GODOT4_0_OR_GREATER, GODOT4_1_OR_GREATER, GODOT4_2_OR_GREATER, GODOT4_3_OR_GREATER, GODOT4_3_2, GODOT4_3_0_OR_GREATER, GODOT4_3_1_OR_GREATER và GODOT4_3_2_OR_GREATER.

Khi xuất (export), các define sau cũng có thể được định nghĩa tùy theo các export feature:

  • Một trong GODOT_PC, GODOT_MOBILE hoặc GODOT_WEB tùy theo loại nền tảng.

  • Một trong GODOT_WINDOWS, GODOT_LINUXBSD, GODOT_MACOS, GODOT_ANDROID, GODOT_IOS hoặc GODOT_WEB tùy theo nền tảng.

Để xem dự án ví dụ, hãy xem demo kiểm thử OS: https://github.com/godotengine/godot-demo-projects/tree/master/misc/os_test
