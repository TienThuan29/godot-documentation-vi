Hướng dẫn phong cách C#

Có quy ước viết mã rõ ràng và nhất quán là điều quan trọng với mọi dự án, và Godot cũng không ngoại lệ.

Trang này chứa hướng dẫn phong cách viết mã mà các nhà phát triển và người đóng góp cho chính Godot tuân theo. Vì vậy, nó chủ yếu dành cho những ai muốn đóng góp cho dự án, nhưng vì các quy ước và hướng dẫn nêu trong bài này là những gì được người dùng ngôn ngữ áp dụng rộng rãi nhất, chúng tôi khuyến khích bạn làm theo, nhất là khi bạn chưa có hướng dẫn nào như vậy.

Ghi chú

Bài viết này hoàn toàn không phải là hướng dẫn đầy đủ về cách tuân theo các quy ước viết mã tiêu chuẩn hay best practice. Nếu không chắc chắn về một khía cạnh chưa được đề cập ở đây, hãy tham khảo tài liệu toàn diện hơn, chẳng hạn C# Coding Conventions hoặc Framework Design Guidelines.

Đặc tả ngôn ngữ

Godot hiện dùng C# phiên bản 12.0 trong engine và mã nguồn ví dụ, vì đây là phiên bản được .NET 8.0 hỗ trợ (yêu cầu tối thiểu hiện tại). Vì vậy, trước khi chuyển sang phiên bản mới hơn, cần cẩn thận để không dùng lẫn các tính năng ngôn ngữ chỉ có trong C# 13.0 trở lên.

Để biết thông tin chi tiết về các tính năng C# ở các phiên bản khác nhau, vui lòng xem What's New in C#.

Định dạng

Hướng dẫn chung

  • Dùng ký tự line feed (LF) để xuống dòng, không dùng CRLF hay CR.

  • Dùng một ký tự line feed ở cuối mỗi file, trừ các file csproj.

  • Dùng mã hóa UTF-8 không có byte order mark.

  • Dùng 4 dấu cách thay vì tab để thụt lề (còn gọi là "soft tab").

  • Cân nhắc ngắt một dòng thành nhiều dòng nếu nó dài hơn 100 ký tự.

Xuống dòng và dòng trống

Về quy tắc thụt lề chung, hãy theo "Allman Style", phong cách khuyến nghị đặt dấu ngoặc nhọn của một câu lệnh điều khiển ở dòng tiếp theo, thụt lề cùng mức:

// Use this style:
if (x > 0)
{
    DoSomething();
}

// NOT this:
if (x > 0) {
    DoSomething();
}

Tuy nhiên, bạn có thể chọn bỏ xuống dòng bên trong dấu ngoặc:

  • Với accessor thuộc tính đơn giản.

  • Với initializer đơn giản cho đối tượng, mảng hoặc collection.

  • Với khai báo auto property, indexer hoặc event trừu tượng.

// You may put the brackets in a single line in following cases:
public interface MyInterface
{
    int MyProperty { get; set; }
}

public class MyClass : ParentClass
{
    public int Value
    {
        get { return 0; }
        set
        {
            ArrayValue = new [] {value};
        }
    }
}

Chèn một dòng trống:

  • Sau danh sách các câu lệnh using.

  • Giữa các khai báo phương thức, thuộc tính và kiểu lồng bên trong.

  • Ở cuối mỗi file.

Các khai báo field và hằng số có thể được nhóm lại theo mức liên quan. Khi đó, hãy cân nhắc chèn một dòng trống giữa các nhóm để dễ đọc hơn.

Tránh chèn dòng trống:

  • Sau {, dấu ngoặc nhọn mở.

  • Trước }, dấu ngoặc nhọn đóng.

  • Sau một khối comment hoặc một comment một dòng.

  • Liền kề một dòng trống khác.

using System;
using Godot;
                                          // Blank line after `using` list.
public class MyClass
{                                         // No blank line after `{`.
    public enum MyEnum
    {
        Value,
        AnotherValue                      // No blank line before `}`.
    }
                                          // Blank line around inner types.
    public const int SomeConstant = 1;
    public const int AnotherConstant = 2;

    private Vector3 _x;                  // Related constants or fields can be
    private Vector3 _y;                  // grouped together.

    private float _width;
    private float _height;

    public int MyProperty { get; set; }
                                          // Blank line around properties.
    public void MyMethod()
    {
        // Some comment.
        AnotherMethod();                  // No blank line after a comment.
    }
                                          // Blank line around methods.
    public void AnotherMethod()
    {
    }
}

Dùng dấu cách

Chèn một dấu cách:

  • Quanh toán tử hai ngôi và ba ngôi.

  • Giữa dấu ngoặc tròn mở và các từ khóa if, for, foreach, catch, while, lock hoặc using.

  • Trước và bên trong một khối accessor một dòng.

  • Giữa các accessor trong một khối accessor một dòng.

  • Sau dấu phẩy không nằm ở cuối dòng.

  • Sau dấu chấm phẩy trong câu lệnh for.

  • Sau dấu hai chấm trong câu lệnh case một dòng.

  • Quanh dấu hai chấm trong khai báo kiểu.

  • Quanh mũi tên lambda.

  • Sau ký hiệu comment một dòng (//), và trước nó nếu dùng ở cuối dòng.

  • Sau dấu ngoặc nhọn mở và trước dấu ngoặc nhọn đóng trong initializer một dòng.

Không dùng dấu cách:

  • Sau dấu ngoặc ép kiểu.

Ví dụ sau cho thấy cách dùng dấu cách đúng, theo một số quy ước nêu trên:

public class MyClass<A, B> : Parent<A, B>
{
    public float MyProperty { get; set; }

    public float AnotherProperty
    {
        get { return MyProperty; }
    }

    public void MyMethod()
    {
        int[] values = { 1, 2, 3, 4 };
        int sum = 0;

        // Single line comment.
        for (int i = 0; i < values.Length; i++)
        {
            switch (i)
            {
                case 3: return;
                default:
                    sum += i > 2 ? 0 : 1;
                    break;
            }
        }

        i += (int)MyProperty; // No space after a type cast.
    }
}

Quy ước đặt tên

Dùng PascalCase cho mọi namespace, tên kiểu và định danh cấp thành viên (tức phương thức, thuộc tính, hằng số, event), trừ field private:

namespace ExampleProject
{
    public class PlayerCharacter
    {
        public const float DefaultSpeed = 10f;

        public float CurrentSpeed { get; set; }

        protected int HitPoints;

        private void CalculateWeaponDamage()
        {
        }
    }
}

Dùng camelCase cho mọi định danh khác (tức biến cục bộ, đối số phương thức), và dùng dấu gạch dưới (_) làm tiền tố cho field private (nhưng không dùng cho phương thức hay thuộc tính, như đã giải thích ở trên):

private Vector3 _aimingAt; // Use an `_` prefix for private fields.

private void Attack(float attackStrength)
{
    Enemy targetFound = FindTarget(_aimingAt);

    targetFound?.Hit(attackStrength);
}

Có một ngoại lệ với từ viết tắt gồm hai chữ cái, như UI, cần được viết hoa toàn bộ ở chỗ dùng PascalCase, và viết thường ở các chỗ khác.

Lưu ý rằng id không phải là từ viết tắt, nên cần được xử lý như một định danh bình thường:

public string Id { get; }

public UIManager UI
{
    get { return uiManager; }
}

Nhìn chung không khuyến khích dùng tên kiểu làm tiền tố cho định danh, ví dụ như string strText hay float fPower. Tuy nhiên, có một ngoại lệ cho interface, vốn nên có chữ hoa I làm tiền tố trong tên, như IInventoryHolder hay IDamageable.

Cuối cùng, hãy chọn tên có tính mô tả và đừng cố rút gọn quá mức nếu điều đó ảnh hưởng đến khả năng đọc.

Chẳng hạn, nếu bạn muốn viết mã tìm một kẻ địch ở gần và tấn công nó bằng vũ khí, hãy ưu tiên:

FindNearbyEnemy()?.Damage(weaponDamage);

Thay vì:

FindNode()?.Change(wpnDmg);

Biến thành viên

Đừng khai báo biến thành viên nếu chúng chỉ được dùng cục bộ trong một phương thức, vì điều đó làm mã khó theo dõi hơn. Thay vào đó, hãy khai báo chúng là biến cục bộ trong thân phương thức.

Biến cục bộ

Khai báo biến cục bộ càng gần nơi dùng lần đầu càng tốt. Điều này giúp dễ theo dõi mã hơn, không phải cuộn quá nhiều để tìm nơi biến được khai báo.

Biến cục bộ định kiểu ngầm

Cân nhắc dùng định kiểu ngầm (var) khi khai báo biến cục bộ, nhưng chỉ khi kiểu đã rõ ràng từ vế phải của phép gán:

// You can use `var` for these cases:

var direction = new Vector2(1, 0);

var value = (int)speed;

var text = "Some value";

for (var i = 0; i < 10; i++)
{
}

// But not for these:

var value = GetValue();

var velocity = direction * 1.5;

// It's generally a better idea to use explicit typing for numeric values, especially with
// the existence of the `real_t` alias in Godot, which can either be double or float
// depending on the build configuration.

var value = 1.5;

Các lưu ý khác

  • Dùng access modifier tường minh.

  • Dùng thuộc tính thay vì field không private.

  • Dùng modifier theo thứ tự này: public/protected/private/internal/virtual/override/abstract/new/static/readonly.

  • Tránh dùng tên đầy đủ (fully-qualified) hoặc tiền tố this. cho thành viên khi không cần thiết.

  • Xóa các câu lệnh using không dùng tới và dấu ngoặc tròn không cần thiết.

  • Cân nhắc bỏ giá trị khởi tạo mặc định của một kiểu.

  • Cân nhắc dùng toán tử null-conditional hoặc type initializer để mã gọn hơn.

  • Dùng ép kiểu an toàn khi có khả năng giá trị thuộc kiểu khác, và dùng ép kiểu trực tiếp trong các trường hợp còn lại.
