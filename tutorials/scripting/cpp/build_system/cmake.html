Hệ thống build phụ: Làm việc với CMake

Xem thêm

Trang này hướng dẫn cách biên dịch godot-cpp. Nếu bạn muốn biên dịch Godot, hãy xem Giới thiệu về hệ thống build.

Bên cạnh hệ thống build dựa trên SCons, godot-cpp còn cung cấp file CMakeLists.txt để hỗ trợ những người dùng thích dùng CMake thay vì SCons làm hệ thống build.

Dù được hỗ trợ tích cực, hệ thống CMake được xem là thứ yếu so với hệ thống build SCons. Điều này có nghĩa là nó có thể thiếu một số tính năng có sẵn cho các dự án dùng SCons.

Giới thiệu

Việc biên dịch godot-cpp độc lập với một dự án extension chủ yếu dành cho các nhà phát triển godot-cpp, người bảo trì gói (package) và CI/CD.

Các ví dụ về cách dùng CMake để sử dụng thư viện godot-cpp như một phần của dự án extension:

  • godot-cpp-template

  • godot_roguelite

  • godot-orchestrator

Các ví dụ cấu hình godot-cpp được liệt kê ở cuối trang, nhiều ví dụ trong số đó có thể giúp bạn cấu hình dự án của mình.

Debug của CMake và template_debug của Godot

Một điều thường xuất hiện trong nhiều cuộc thảo luận là sự nhầm lẫn giữa việc biên dịch mã nguồn C++ có bật debug symbol và việc biên dịch một Godot extension có bật các tính năng debug. Hai khái niệm này không loại trừ lẫn nhau.

Tính năng debug

Bật một định nghĩa tiền xử lý (pre-processor) để biên dịch có chọn lọc phần mã giúp người dùng Godot extension làm việc với dự án của họ.

Các tính năng debug được bật trong bản build editor và template_debug, có thể chỉ định trong giai đoạn configure như sau:

cmake -S godot-cpp -B cmake-build -DGODOTCPP_TARGET=<target choice>

Gỡ lỗi

Thiết lập các cờ trình biên dịch để tạo debug symbol, giúp nhà phát triển Godot extension debug extension của họ.

Debug là kiểu build mặc định của các dự án CMake; cách chọn kiểu khác phụ thuộc vào generator được dùng:

  • Với generator đơn cấu hình, thêm -DCMAKE_BUILD_TYPE=<type> vào lệnh configure.

  • Với generator đa cấu hình, thêm --config <type> vào lệnh build.

Trong đó <type> là một trong Debug, Release, RelWithDebInfo và MinSizeRel.

Khác biệt so với SCons

Không phải mọi đoạn mã của hệ thống SCons đều có thể biểu diễn hoàn hảo trong CMake; dưới đây là các khác biệt đáng chú ý:

  • debug_symbols

    Không còn là một tùy chọn tường minh, và được bật khi dùng các cấu hình build CMake; Debug, RelWithDebInfo.

  • dev_build

    Không định nghĩa NDEBUG khi bị tắt; NDEBUG được đặt khi dùng các cấu hình build CMake; Release, MinSizeRel.

  • arch

    CMake thiết lập kiến trúc thông qua các file toolchain; macOS universal được điều khiển qua thuộc tính CMAKE_OSX_ARCHITECTURES, thuộc tính này được sao chép sang các target khi chúng được định nghĩa.

  • debug_crt

    CMake điều khiển việc liên kết với các thư viện runtime của Windows bằng cách sao chép giá trị của CMAKE_MSVC_RUNTIME_LIBRARIES sang các target khi chúng được định nghĩa. godot-cpp sẽ đặt biến này nếu nó chưa được đặt. Vì vậy, hãy include nó trước các dependency khác để giá trị được lan truyền qua các dự án.

Hướng dẫn cơ bản

Clone kho git

git clone https://github.com/godotengine/godot-cpp.git
Cloning into 'godot-cpp'...
...

Cấu hình bản build

cmake -S godot-cpp -B cmake-build -G Ninja

  • -S Chỉ định thư mục nguồn là godot-cpp

  • -B Chỉ định thư mục build là cmake-build

  • -G Chỉ định Generator là Ninja

Thư mục nguồn trong ví dụ này là thư mục gốc mã nguồn của godot-cpp vừa clone. CMake cũng sẽ hiểu đường dẫn đầu tiên trong lệnh là đường dẫn nguồn, hoặc nếu một đường dẫn build có sẵn được chỉ định, nó sẽ suy ra đường dẫn nguồn từ build cache.

Ba lệnh sau là tương đương:

# Current working directory is the godot-cpp source root.
cmake . -B build-dir

# Current working directory is an empty godot-cpp/build-dir.
cmake ../

# Current working directory is an existing build path.
cmake .

Thư mục build được chỉ định để các file được tạo ra không làm lộn xộn cây mã nguồn bằng các sản phẩm build.

CMake không build mã, nó tạo ra các file mà một công cụ build sử dụng; trong trường hợp này generator Ninja tạo ra các file build Ninja.

Để xem danh sách generator, chạy cmake --help.

Tùy chọn build

Để liệt kê các tùy chọn có sẵn, dùng các cờ lệnh -L[AH]. A là nâng cao (advanced), và H là chuỗi trợ giúp (help):

cmake -S godot-cpp -LH

Các tùy chọn được chỉ định trên dòng lệnh khi configure, ví dụ:

cmake -S godot-cpp -DGODOTCPP_USE_HOT_RELOAD:BOOL=ON \
    -DGODOTCPP_PRECISION:STRING=double \
    -DCMAKE_BUILD_TYPE:STRING=Debug

Xem setting-build-variables và build-configurations để biết thêm thông tin.

Danh sách tùy chọn (chưa đầy đủ):

// Path to a custom GDExtension API JSON file.
// (takes precedence over GODOTCPP_GDEXTENSION_DIR)
// ( /path/to/custom_api_file )
GODOTCPP_CUSTOM_API_FILE:FILEPATH=

// Force disabling exception handling code. (ON|OFF)
GODOTCPP_DISABLE_EXCEPTIONS:BOOL=ON

// Path to a custom directory containing the GDExtension interface
// header and API JSON file. ( /path/to/gdextension_dir )
GODOTCPP_GDEXTENSION_DIR:PATH=gdextension

// Set the floating-point precision level. (single|double)
GODOTCPP_PRECISION:STRING=single

// Enable the extra accounting required to support hot reload. (ON|OFF)
GODOTCPP_USE_HOT_RELOAD:BOOL=

Biên dịch

Yêu cầu CMake gọi hệ thống build mà nó đã tạo trong thư mục được chỉ định. Target mặc định là template_debug và cấu hình build mặc định là Debug.

cmake --build cmake-build

Ví dụ

Các ví dụ này, dù dành cho nhà phát triển godot-cpp, người bảo trì gói và CI/CD, vẫn có thể giúp bạn cấu hình dự án extension của riêng mình.

Các ví dụ thực tế về cách sử dụng thư viện godot-cpp như một phần của dự án extension được liệt kê trong Introduction.

Bật kiểm thử tích hợp

Target kiểm thử godot-cpp-test được điều khiển bởi GODOTCPP_ENABLE_TESTING, mặc định bị tắt.

Để configure và build dự án godot-cpp với các target kiểm thử tích hợp được bật, lệnh sẽ trông giống như sau:

cmake -S godot-cpp -B cmake-build -DGODOTCPP_ENABLE_TESTING=YES
cmake --build cmake-build --target godot-cpp-test

Windows và MSVC - Release

Miễn là CMake được cài từ trang CMake Downloads và có trong PATH, và Microsoft Visual Studio được cài kèm hỗ trợ C++, CMake sẽ phát hiện trình biên dịch MSVC.

Lưu ý rằng Visual Studio là Multi-Config Generator nên cấu hình build cần được chỉ định lúc build, ví dụ --config Release.

cmake -S godot-cpp -B cmake-build -DGODOTCPP_ENABLE_TESTING=YES
cmake --build cmake-build -t godot-cpp-test --config Release

MSys2/clang64, "Ninja" - Debug

Giả định toolchain ming-w64-clang-x86_64 đã được cài đặt.

Lưu ý rằng Ninja là Single-Config Generator nên kiểu build cần được chỉ định lúc configure.

Dùng shell msys2/clang64:

cmake -S godot-cpp -B cmake-build -G"Ninja" \
    -DGODOTCPP_ENABLE_TESTING=YES -DCMAKE_BUILD_TYPE=Release
cmake --build cmake-build -t godot-cpp-test

MSys2/clang64, "Ninja Multi-Config" - dev_build, Debug Symbols

Giả định toolchain ming-w64-clang-x86_64 đã được cài đặt.

Lần này chúng ta chọn generator 'Ninja Multi-Config', nên kiểu build được chỉ định lúc build.

Dùng shell msys2/clang64:

cmake -S godot-cpp -B cmake-build -G"Ninja Multi-Config" \
    -DGODOTCPP_ENABLE_TESTING=YES -DGODOTCPP_DEV_BUILD:BOOL=ON
cmake --build cmake-build -t godot-cpp-test --config Debug

Emscripten cho nền tảng web

Cách này mới chỉ được thử nghiệm trên Windows. Bạn có thể dùng quy trình ví dụ sau:

  • Clone và cài đặt các công cụ Emscripten mới nhất vào c:\emsdk.

  • Dùng C:\emsdk\emsdk.ps1 activate latest để kích hoạt môi trường từ powershell trong shell hiện tại.

  • Tiện ích emcmake.bat thêm toolchain emscripten vào lệnh CMake. Bạn cũng có thể thêm thủ công; vị trí được ghi trong file emcmake.bat

C:\emsdk\emsdk.ps1 activate latest
emcmake.bat cmake -S godot-cpp -B cmake-build-web -DCMAKE_BUILD_TYPE=Release
cmake --build cmake-build-web

Biên dịch chéo cho Android từ Windows

Có hai hướng riêng biệt mà bạn có thể chọn khi cấu hình cho Android.

Dùng các biến CMAKE_ANDROID_* được chỉ định trên dòng lệnh hoặc trong file toolchain của riêng bạn như được liệt kê trong tài liệu cmake-toolchains.

Hoặc dùng toolchain và các script do Android SDK cung cấp, rồi thay đổi bằng các biến ANDROID_* được liệt kê ở đó. Trong đó <version> là phiên bản NDK bạn đã cài (đã thử với 28.1.13356709) và <platform> là nền tảng Android SDK (đã thử với android-29).

Cảnh báo

website của Android SDK nêu rõ rằng họ không hỗ trợ dùng phương thức tích hợp sẵn của CMake, và khuyên bạn nên dùng các file toolchain của họ.

Dùng file toolchain của riêng bạn

Như mô tả trong tài liệu CMake:

cmake -S godot-cpp -B cmake-build --toolchain my_toolchain.cmake
cmake --build cmake-build -t template_release

Làm tương tự chỉ bằng dòng lệnh:

cmake -S godot-cpp -B cmake-build \
    -DCMAKE_SYSTEM_NAME=Android \
    -DCMAKE_SYSTEM_VERSION=<platform> \
    -DCMAKE_ANDROID_ARCH_ABI=<arch> \
    -DCMAKE_ANDROID_NDK=/path/to/android-ndk
cmake --build cmake-build

Dùng file toolchain của Android SDK

Mặc định dùng phiên bản thấp nhất được hỗ trợ và armv7-a:

cmake -S godot-cpp -B cmake-build \
    --toolchain $ANDROID_HOME/ndk/<version>/build/cmake/android.toolchain.cmake
cmake --build cmake-build

Chỉ định nền tảng Android và ABI:

cmake -S godot-cpp -B cmake-build \
    --toolchain $ANDROID_HOME/ndk/<version>/build/cmake/android.toolchain.cmake \
    -DANDROID_PLATFORM:STRING=android-29 \
    -DANDROID_ABI:STRING=armeabi-v7a
cmake --build cmake-build
