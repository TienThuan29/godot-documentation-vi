Bắt đầu

Tổng quan quy trình làm việc

Là một GDExtension, godot-cpp phức tạp hơn khi sử dụng so với GDScript và C#. Nếu bạn quyết định làm việc với nó, quy trình làm việc của bạn sẽ trông như sau:

  • Tạo một dự án godot-cpp mới (từ template, hoặc từ đầu, như được giải thích dưới đây).

  • Phát triển mã cục bộ với IDE yêu thích của bạn.

  • Build và kiểm thử mã với phiên bản Godot tương thích sớm nhất.

  • Tạo bản build cho mọi nền tảng bạn muốn hỗ trợ (ví dụ dùng GitHub Actions).

  • Tùy chọn: Phát hành trên Godot Asset Store.

Dự án ví dụ

Với dự án godot-cpp đầu tiên, chúng tôi khuyên bạn bắt đầu với hướng dẫn này để hiểu công nghệ liên quan đến godot-cpp. Sau khi hoàn thành, bạn có thể dùng godot-cpp template, vốn bao quát tính năng tốt hơn, chẳng hạn như pipeline GitHub action và mã boilerplate SConstruct hữu ích. Tuy nhiên, template không tự giải thích chi tiết, đó là lý do chúng tôi khuyên bạn nên đi qua hướng dẫn này trước.

Thiết lập dự án

Bạn cần một vài điều kiện tiên quyết:

  • Một bản thực thi Godot 4.

  • Một trình biên dịch C++.

  • SCons làm công cụ build.

  • Một bản sao của kho godot-cpp.

Xem thêm Cấu hình IDE và Biên dịch vì các công cụ build giống hệt với những công cụ bạn cần để biên dịch Godot từ mã nguồn.

Bạn có thể tải kho godot-cpp từ GitHub hoặc để Git làm việc đó cho bạn. Lưu ý rằng kho này có các nhánh khác nhau cho các phiên bản Godot khác nhau. GDExtension sẽ không hoạt động trên các phiên bản Godot cũ hơn (chỉ Godot 4 trở lên) và ngược lại, vì vậy hãy đảm bảo bạn tải đúng nhánh.

Ghi chú

Để dùng GDExtension, bạn cần dùng nhánh godot-cpp khớp với phiên bản Godot mà bạn nhắm đến. Ví dụ, nếu bạn nhắm đến Godot 4.1, hãy dùng nhánh 4.1. Trong suốt bài hướng dẫn này chúng ta dùng 4.x, bạn cần thay bằng phiên bản Godot mà bạn nhắm đến.

Nhánh master là nhánh phát triển, được cập nhật thường xuyên để hoạt động với nhánh master của Godot.

Cảnh báo

GDExtension nhắm đến một phiên bản Godot cũ hơn sẽ hoạt động được ở các phiên bản minor mới hơn, nhưng không có chiều ngược lại. Ví dụ, một GDExtension nhắm đến Godot 4.2 sẽ chạy tốt trên Godot 4.3, nhưng một GDExtension nhắm đến Godot 4.3 sẽ không chạy được trên Godot 4.2.

Có một ngoại lệ: các extension nhắm đến Godot 4.0 sẽ không chạy được với Godot 4.1 trở lên (xem Cập nhật GDExtension của bạn cho 4.1).

Nếu bạn quản lý phiên bản dự án bằng Git, nên thêm nó dưới dạng Git submodule:

mkdir gdextension_cpp_example
cd gdextension_cpp_example
git init
git submodule add -b 4.x https://github.com/godotengine/godot-cpp
cd godot-cpp
git submodule update --init

Hoặc bạn cũng có thể clone nó vào thư mục dự án:

mkdir gdextension_cpp_example
cd gdextension_cpp_example
git clone -b 4.x https://github.com/godotengine/godot-cpp

Ghi chú

Nếu bạn quyết định tải kho về hoặc clone vào thư mục của mình, hãy đảm bảo giữ cấu trúc thư mục giống như chúng tôi đã thiết lập ở đây. Phần lớn mã chúng tôi trình bày ở đây giả định dự án có cấu trúc này.

Nếu bạn clone ví dụ từ liên kết được nêu trong phần giới thiệu, các submodule sẽ không được khởi tạo tự động. Bạn cần chạy các lệnh sau:

cd gdextension_cpp_example
git submodule update --init

Lệnh này sẽ khởi tạo kho trong thư mục dự án của bạn.

Tạo một plugin đơn giản

Giờ là lúc build một plugin thực sự. Chúng ta sẽ bắt đầu bằng việc tạo một dự án Godot trống, nơi sẽ đặt một vài file.

Mở Godot và tạo một dự án mới. Trong ví dụ này, chúng ta sẽ đặt nó trong một thư mục tên project bên trong cấu trúc thư mục của GDExtension.

Trong dự án, chúng ta sẽ tạo một scene chứa một Node tên "Main" và lưu nó thành main.tscn. Chúng ta sẽ quay lại phần này sau.

Quay lại thư mục module GDExtension cấp cao nhất, chúng ta cũng sẽ tạo một thư mục con tên src để đặt các file mã nguồn.

Giờ bạn sẽ có các thư mục project, godot-cpp và src trong module GDExtension của mình.

Cấu trúc thư mục của bạn giờ sẽ trông như sau:

gdextension_cpp_example/
|
+--project/                  # game example/demo to test the extension
|
+--godot-cpp/             # C++ bindings
|
+--src/                   # source code of the extension we are building

Trong thư mục src, chúng ta sẽ bắt đầu bằng việc tạo file header cho node GDExtension mà chúng ta sẽ tạo. Chúng ta đặt tên nó là gdexample.h:

gdextension_cpp_example/src/gdexample.h
#pragma once

#include <godot_cpp/classes/sprite2d.hpp>

namespace godot {

class GDExample : public Sprite2D {
    GDCLASS(GDExample, Sprite2D)

private:
    double time_passed;

protected:
    static void _bind_methods();

public:
    GDExample();
    ~GDExample();

    void _process(double delta) override;
};

} // namespace godot

Có một vài điểm đáng chú ý ở trên. Chúng ta include sprite2d.hpp, file chứa binding tới lớp Sprite2D. Chúng ta sẽ mở rộng lớp này trong module của mình.

Chúng ta dùng namespace godot, vì mọi thứ trong GDExtension đều được định nghĩa trong namespace này.

Tiếp theo là định nghĩa lớp, kế thừa từ Sprite2D thông qua một lớp container. Chúng ta sẽ thấy một vài tác dụng phụ của việc này sau. Macro GDCLASS thiết lập một vài thứ nội bộ cho chúng ta.

Sau đó, chúng ta khai báo một biến thành viên duy nhất tên time_passed.

Trong khối tiếp theo, chúng ta định nghĩa các phương thức: có constructor và destructor, nhưng còn hai hàm khác có lẽ sẽ quen thuộc với một số người, và một phương thức mới.

Hàm đầu tiên là _bind_methods, một hàm static mà Godot sẽ gọi để biết những phương thức nào có thể được gọi và những thuộc tính nào được cung cấp. Hàm thứ hai là _process, hoạt động giống hệt hàm _process mà bạn đã quen dùng trong GDScript.

Hãy triển khai các hàm bằng cách tạo file gdexample.cpp:

gdextension_cpp_example/src/gdexample.cpp
#include "gdexample.h"
#include <godot_cpp/core/class_db.hpp>

using namespace godot;

void GDExample::_bind_methods() {
}

GDExample::GDExample() {
    // Initialize any variables here.
    time_passed = 0.0;
}

GDExample::~GDExample() {
    // Add your cleanup here.
}

void GDExample::_process(double delta) {
    time_passed += delta;

    Vector2 new_position = Vector2(10.0 + (10.0 * sin(time_passed * 2.0)), 10.0 + (10.0 * cos(time_passed * 1.5)));

    set_position(new_position);
}

Phần này khá đơn giản. Chúng ta triển khai từng phương thức của lớp đã định nghĩa trong file header.

Hãy chú ý hàm _process, hàm này theo dõi lượng thời gian đã trôi qua và tính vị trí mới cho sprite bằng hàm sin và cos.

Chúng ta cần thêm một file C++ nữa; đặt tên là register_types.cpp. Plugin GDExtension của chúng ta có thể chứa nhiều lớp, mỗi lớp có file header và file mã nguồn riêng, giống như cách chúng ta đã triển khai GDExample ở trên. Giờ chúng ta cần một đoạn mã nhỏ để báo cho Godot biết về mọi lớp trong plugin GDExtension.

gdextension_cpp_example/src/register_types.cpp
#include "register_types.h"

#include "gdexample.h"

#include <gdextension_interface.h>
#include <godot_cpp/core/defs.hpp>
#include <godot_cpp/godot.hpp>

using namespace godot;

void initialize_example_module(ModuleInitializationLevel p_level) {
    if (p_level != MODULE_INITIALIZATION_LEVEL_SCENE) {
        return;
    }

    GDREGISTER_CLASS(GDExample);
}

void uninitialize_example_module(ModuleInitializationLevel p_level) {
    if (p_level != MODULE_INITIALIZATION_LEVEL_SCENE) {
        return;
    }
}

extern "C" {
// Initialization.
GDExtensionBool GDE_EXPORT example_library_init(GDExtensionInterfaceGetProcAddress p_get_proc_address, const GDExtensionClassLibraryPtr p_library, GDExtensionInitialization *r_initialization) {
    godot::GDExtensionBinding::InitObject init_obj(p_get_proc_address, p_library, r_initialization);

    init_obj.register_initializer(initialize_example_module);
    init_obj.register_terminator(uninitialize_example_module);
    init_obj.set_minimum_library_initialization_level(MODULE_INITIALIZATION_LEVEL_SCENE);

    return init_obj.init();
}
}

Các hàm initialize_example_module và uninitialize_example_module lần lượt được gọi khi Godot nạp plugin và khi gỡ nạp nó. Ở đây chúng ta chỉ duyệt qua các hàm trong module binding để khởi tạo chúng, nhưng bạn có thể phải thiết lập thêm nhiều thứ tùy theo nhu cầu. Chúng ta gọi macro GDREGISTER_CLASS cho mỗi lớp trong thư viện.

Ghi chú

Bạn có thể tìm thông tin về GDREGISTER_CLASS (và các lựa chọn thay thế) tại Lớp Object.

Hàm quan trọng là hàm thứ ba tên example_library_init. Trước tiên chúng ta gọi một hàm trong thư viện binding để tạo một đối tượng khởi tạo. Đối tượng này đăng ký các hàm khởi tạo và kết thúc của GDExtension. Ngoài ra, nó thiết lập cấp độ khởi tạo (core, servers, scene, editor, level).

Cuối cùng, chúng ta cần file header cho register_types.cpp có tên register_types.h.

gdextension_cpp_example/src/register_types.h
#pragma once

#include <godot_cpp/core/class_db.hpp>

using namespace godot;

void initialize_example_module(ModuleInitializationLevel p_level);
void uninitialize_example_module(ModuleInitializationLevel p_level);

Biên dịch plugin

Để biên dịch dự án, chúng ta cần định nghĩa cách SCons biên dịch nó bằng một file SConstruct tham chiếu tới file trong godot-cpp. Viết file này từ đầu nằm ngoài phạm vi của bài hướng dẫn này, nhưng bạn có thể tải file SConstruct chúng tôi đã chuẩn bị. Chúng ta sẽ đề cập đến một ví dụ chi tiết, tùy biến được nhiều hơn về cách dùng các file build này trong một bài hướng dẫn sau.

Ghi chú

File SConstruct này được viết để dùng với godot-cpp master mới nhất; bạn có thể cần thay đổi nhỏ khi dùng nó với các phiên bản cũ hơn hoặc tham khảo file SConstruct trong tài liệu Godot 4.x.

Sau khi tải file SConstruct, hãy đặt nó trong cấu trúc thư mục GDExtension cạnh godot-cpp, src và project, rồi chạy:

scons platform=<platform>

Bạn có thể bỏ qua tùy chọn platform nếu đang biên dịch cho nền tảng bạn đang dùng. Danh sách các tùy chọn platform có sẵn phụ thuộc vào những dependency nền tảng nào đã được thiết lập (dùng platform=list để xem mọi nền tảng có sẵn). Xem Giới thiệu về hệ thống build để biết chi tiết.

Giờ bạn sẽ tìm thấy thư viện đã biên dịch trong project/bin/.

Ghi chú

Ở đây, chúng ta đã biên dịch cả godot-cpp và thư viện gdexample dưới dạng bản build debug, là mặc định. Để có bản build tối ưu, bạn nên biên dịch chúng với tùy chọn target=template_release.

Sử dụng module GDExtension

Trước khi quay lại Godot, chúng ta cần tạo thêm một file nữa trong project/bin/.

File này cho Godot biết những thư viện động nào cần được nạp cho mỗi nền tảng và hàm entry của module. Nó có tên gdexample.gdextension.

[configuration]

entry_symbol = "example_library_init"
compatibility_minimum = "4.1"
reloadable = true

[libraries]

macos.debug = "./libgdexample.macos.template_debug.dylib"
macos.release = "./libgdexample.macos.template_release.dylib"
windows.debug.x86_32 = "./gdexample.windows.template_debug.x86_32.dll"
windows.release.x86_32 = "./gdexample.windows.template_release.x86_32.dll"
windows.debug.x86_64 = "./gdexample.windows.template_debug.x86_64.dll"
windows.release.x86_64 = "./gdexample.windows.template_release.x86_64.dll"
linux.debug.x86_64 = "./libgdexample.linux.template_debug.x86_64.so"
linux.release.x86_64 = "./libgdexample.linux.template_release.x86_64.so"
linux.debug.arm64 = "./libgdexample.linux.template_debug.arm64.so"
linux.release.arm64 = "./libgdexample.linux.template_release.arm64.so"
linux.debug.rv64 = "./libgdexample.linux.template_debug.rv64.so"
linux.release.rv64 = "./libgdexample.linux.template_release.rv64.so"

File này chứa phần configuration điều khiển hàm entry của module. Bạn cũng nên đặt phiên bản Godot tương thích tối thiểu bằng compatibility_minimum, giúp ngăn các phiên bản Godot cũ hơn cố nạp extension của bạn. Cờ reloadable bật tính năng tự động nạp lại extension trong trình chỉnh sửa mỗi khi bạn biên dịch lại, mà không cần khởi động lại trình chỉnh sửa. Tính năng này chỉ hoạt động khi bạn biên dịch extension ở chế độ debug (mặc định).

Phần libraries là phần quan trọng: nó cho Godot biết vị trí của thư viện động trong hệ thống file của dự án cho mỗi nền tảng được hỗ trợ. Nó cũng khiến chỉ file đó được xuất khi bạn xuất dự án, nghĩa là data pack sẽ không chứa các thư viện không tương thích với nền tảng mục tiêu.

Bạn có thể tìm hiểu thêm về file .gdextension tại File .gdextension.

Đây là một cái nhìn tổng quan khác để kiểm tra cấu trúc file đúng:

gdextension_cpp_example/
|
+--project/                  # game example/demo to test the extension
|   |
|   +--main.tscn
|   |
|   +--bin/
|       |
|       +--gdexample.gdextension
|
+--godot-cpp/             # C++ bindings
|
+--src/                   # source code of the extension we are building
|   |
|   +--register_types.cpp
|   +--register_types.h
|   +--gdexample.cpp
|   +--gdexample.h

Thêm thuộc tính

GDScript cho phép bạn thêm thuộc tính vào script bằng từ khóa export. Trong GDExtension, bạn phải đăng ký thuộc tính với một hàm getter và setter, hoặc triển khai trực tiếp các phương thức _get_property_list, _get và _set của một object (nhưng điều đó vượt xa phạm vi của bài hướng dẫn này).

Hãy thêm một thuộc tính cho phép điều khiển biên độ của sóng.

Trong file gdexample.h, chúng ta cần thêm một biến thành viên và các hàm getter, setter:

...
private:
    double time_passed;
    double amplitude;

public:
    void set_amplitude(const double p_amplitude);
    double get_amplitude() const;
...

Trong file gdexample.cpp, chúng ta cần thực hiện một số thay đổi; chúng tôi sẽ chỉ hiển thị các phương thức được thay đổi, đừng xóa những dòng chúng tôi lược bỏ:

void GDExample::_bind_methods() {
    ClassDB::bind_method(D_METHOD("get_amplitude"), &GDExample::get_amplitude);
    ClassDB::bind_method(D_METHOD("set_amplitude", "p_amplitude"), &GDExample::set_amplitude);

    ADD_PROPERTY(PropertyInfo(Variant::FLOAT, "amplitude"), "set_amplitude", "get_amplitude");
}

GDExample::GDExample() {
    // Initialize any variables here.
    time_passed = 0.0;
    amplitude = 10.0;
}

void GDExample::_process(double delta) {
    time_passed += delta;

    Vector2 new_position = Vector2(
        amplitude + (amplitude * sin(time_passed * 2.0)),
        amplitude + (amplitude * cos(time_passed * 1.5))
    );

    set_position(new_position);
}

void GDExample::set_amplitude(const double p_amplitude) {
    amplitude = p_amplitude;
}

double GDExample::get_amplitude() const {
    return amplitude;
}

Sau khi biên dịch module với những thay đổi này, bạn sẽ thấy một thuộc tính đã được thêm vào giao diện. Giờ bạn có thể thay đổi thuộc tính này, và khi chạy dự án, bạn sẽ thấy biểu tượng Godot di chuyển theo một quỹ đạo lớn hơn.

Hãy làm tương tự cho tốc độ hoạt ảnh và dùng một hàm setter và getter. File header gdexample.h một lần nữa chỉ cần thêm vài dòng mã:

...
    double amplitude;
    double speed;
...
    void _process(double delta) override;
    void set_speed(const double p_speed);
    double get_speed() const;
...

Việc này yêu cầu thêm vài thay đổi trong file gdexample.cpp; một lần nữa chúng tôi chỉ hiển thị các phương thức đã thay đổi, vì vậy đừng xóa bất cứ phần nào chúng tôi lược bỏ:

void GDExample::_bind_methods() {
    ...
    ClassDB::bind_method(D_METHOD("get_speed"), &GDExample::get_speed);
    ClassDB::bind_method(D_METHOD("set_speed", "p_speed"), &GDExample::set_speed);

    ADD_PROPERTY(PropertyInfo(Variant::FLOAT, "speed", PROPERTY_HINT_RANGE, "0,20,0.01"), "set_speed", "get_speed");
}

GDExample::GDExample() {
    time_passed = 0.0;
    amplitude = 10.0;
    speed = 1.0;
}

void GDExample::_process(double delta) {
    time_passed += speed * delta;

    Vector2 new_position = Vector2(
        amplitude + (amplitude * sin(time_passed * 2.0)),
        amplitude + (amplitude * cos(time_passed * 1.5))
    );

    set_position(new_position);
}

...

void GDExample::set_speed(const double p_speed) {
    speed = p_speed;
}

double GDExample::get_speed() const {
    return speed;
}

Giờ khi biên dịch dự án, chúng ta sẽ thấy một thuộc tính khác tên speed. Thay đổi giá trị của nó sẽ làm hoạt ảnh nhanh hơn hoặc chậm hơn. Ngoài ra, chúng ta đã thêm một khoảng giá trị (range) cho thuộc tính, mô tả giá trị có thể nằm trong khoảng nào. Hai đối số đầu là giá trị nhỏ nhất và lớn nhất, đối số thứ ba là bước nhảy.

Ghi chú

Để đơn giản, chúng ta chỉ dùng hint_range của phương thức property. Còn rất nhiều lựa chọn khác. Chúng có thể được dùng để cấu hình thêm cách thuộc tính được hiển thị và thiết lập ở phía Godot. Bạn có thể tìm thêm thông tin về property hint tại @GlobalScope.

Signal

Cuối cùng nhưng không kém phần quan trọng, signal cũng hoạt động đầy đủ trong GDExtension. Để extension của bạn phản hồi một signal do object khác phát ra, bạn cần gọi connect trên object đó. Chúng tôi chưa nghĩ ra ví dụ hay nào cho biểu tượng Godot lắc lư của chúng ta; khi đó cần trình bày một ví dụ hoàn chỉnh hơn nhiều.

Đây là cú pháp bắt buộc:

some_other_node->connect("the_signal", Callable(this, "my_method"));

Để kết nối signal the_signal từ một node khác với phương thức my_method của chúng ta, cần cung cấp cho phương thức connect tên của signal và một Callable. Callable chứa thông tin về một object mà trên đó một phương thức có thể được gọi. Trong trường hợp này, nó liên kết instance object hiện tại this với phương thức my_method của object. Sau đó phương thức connect sẽ thêm nó vào danh sách observer của the_signal. Từ giờ mỗi khi the_signal được phát ra, Godot biết cần gọi phương thức nào của object nào.

Lưu ý rằng bạn chỉ có thể gọi my_method nếu trước đó đã đăng ký nó trong phương thức _bind_methods. Nếu không, Godot sẽ không biết đến sự tồn tại của my_method.

Để tìm hiểu thêm về Callable, hãy xem tài liệu tham khảo lớp tại đây: Callable.

Việc object của bạn phát ra signal thì phổ biến hơn. Với biểu tượng Godot lắc lư của chúng ta, chúng ta sẽ làm một việc ngớ ngẩn chỉ để minh họa cách hoạt động. Chúng ta sẽ phát một signal mỗi khi một giây trôi qua và truyền kèm vị trí mới.

Trong file header gdexample.h, chúng ta cần định nghĩa một thành viên mới time_emit:

...
    double time_passed;
    double time_emit;
    double amplitude;
...

Lần này, các thay đổi trong gdexample.cpp phức tạp hơn. Trước tiên, bạn cần đặt time_emit = 0.0; trong phương thức _init hoặc trong constructor. Chúng ta sẽ lần lượt xem xét 2 thay đổi cần thiết còn lại.

Trong phương thức _bind_methods, chúng ta cần khai báo signal. Việc này được thực hiện như sau:

void GDExample::_bind_methods() {
    ...
    ADD_PROPERTY(PropertyInfo(Variant::FLOAT, "speed", PROPERTY_HINT_RANGE, "0,20,0.01"), "set_speed", "get_speed");

    ADD_SIGNAL(MethodInfo("position_changed", PropertyInfo(Variant::OBJECT, "node"), PropertyInfo(Variant::VECTOR2, "new_pos")));
}

Ở đây, macro ADD_SIGNAL có thể là một lời gọi duy nhất với đối số MethodInfo. Tham số đầu tiên của MethodInfo là tên của signal, và các tham số còn lại là các kiểu PropertyInfo mô tả những thông tin cốt lõi của từng tham số của phương thức. Các tham số PropertyInfo được định nghĩa với kiểu dữ liệu của tham số, rồi đến tên mặc định của tham số đó.

Vậy ở đây, chúng ta thêm một signal, với một MethodInfo đặt tên signal là "position_changed". Các tham số PropertyInfo mô tả hai đối số cốt lõi, một kiểu Object, một kiểu Vector2, lần lượt có tên "node" và "new_pos".

Tiếp theo, chúng ta cần thay đổi phương thức _process:

void GDExample::_process(double delta) {
    time_passed += speed * delta;

    Vector2 new_position = Vector2(
        amplitude + (amplitude * sin(time_passed * 2.0)),
        amplitude + (amplitude * cos(time_passed * 1.5))
    );

    set_position(new_position);

    time_emit += delta;
    if (time_emit > 1.0) {
        emit_signal("position_changed", this, new_position);

        time_emit = 0.0;
    }
}

Sau khi một giây trôi qua, chúng ta phát signal và đặt lại bộ đếm. Chúng ta có thể thêm trực tiếp các giá trị tham số vào emit_signal.

Sau khi thư viện GDExtension được biên dịch, chúng ta có thể vào Godot và chọn node sprite. Trong dock Node, chúng ta có thể tìm thấy signal mới và kết nối nó bằng cách nhấn nút Connect hoặc nhấp đúp vào signal. Chúng ta đã thêm một script vào node chính và triển khai signal như sau:

extends Node

func _on_Sprite2D_position_changed(node, new_pos):
    print("The position of " + node.get_class() + " is now " + str(new_pos))

Mỗi giây, chúng ta in vị trí ra console.

Các bước tiếp theo

Chúng tôi hy vọng ví dụ trên đã cho bạn thấy những điều cơ bản. Bạn có thể phát triển tiếp từ ví dụ này để tạo các script hoàn chỉnh điều khiển node trong Godot bằng C++!

Thay vì xây dựng dự án dựa trên thiết lập ví dụ ở trên, chúng tôi khuyên bạn bắt đầu lại ngay bây giờ bằng cách clone godot-cpp template và xây dựng dự án dựa trên đó. Template này bao quát tính năng tốt hơn, chẳng hạn như GitHub build action và thêm các boilerplate SConstruct hữu ích.
