Định dạng file TSCN

Định dạng file TSCN (text scene) biểu diễn một cây scene duy nhất trong Godot. Khác với file SCN nhị phân, file TSCN có ưu điểm là phần lớn con người đọc được và dễ quản lý bằng hệ thống quản lý phiên bản.

Định dạng file ESCN (exported scene) giống hệt định dạng TSCN, nhưng được dùng để báo cho Godot biết file đã được xuất từ một chương trình khác và người dùng không nên chỉnh sửa nó trong Godot. Khác với file SCN và TSCN, trong quá trình import, file ESCN được biên dịch thành file SCN nhị phân lưu trong thư mục .godot/imported/. Điều này giảm kích thước dữ liệu và tăng tốc độ tải, vì định dạng nhị phân tải nhanh hơn định dạng dạng văn bản.

Để file gọn hơn, các thuộc tính có giá trị bằng giá trị mặc định sẽ không được lưu trong file scene/resource. Bạn có thể tự viết chúng vào, nhưng chúng sẽ bị loại bỏ khi lưu file.

Nếu bạn muốn xem mô tả đầy đủ, việc phân tích cú pháp được xử lý trong file resource_format_text.cpp, ở lớp ResourceFormatLoaderText.

Ghi chú

Định dạng file scene và resource đã thay đổi đáng kể trong Godot 4, với việc đưa vào UID dạng chuỗi để thay thế ID số nguyên tăng dần.

Dữ liệu mesh, skeleton và hoạt ảnh cũng được lưu khác so với Godot 3. Bạn có thể đọc về một số thay đổi trong bài viết này: Làm lại dữ liệu hoạt ảnh cho 4.0

Scene và resource được lưu bằng Godot 4.x chứa format=3 trong header, còn Godot 3.x dùng format=2.

Cấu trúc file

Có năm phần chính trong file TSCN:

  1. Phần mô tả file

  2. Resource bên ngoài

  3. Resource nội bộ

  4. Node

  5. Kết nối

Phần mô tả file trông như [gd_scene format=3 uid="uid://cecaux1sm7mo0"] và phải là mục đầu tiên trong file. Lưu ý rằng các scene được lưu trước Godot 4.6 còn có thuộc tính load_steps=<int> trong phần mô tả file. Thuộc tính này hiện đã bị deprecated và nên được bỏ qua nếu có.

uid là một định danh duy nhất dạng chuỗi đại diện cho scene. Engine dùng nó để theo dõi các file bị di chuyển, kể cả khi trình chỉnh sửa đang đóng. Script cũng có thể tải resource dựa trên UID bằng tiền tố đường dẫn uid:// để không phụ thuộc vào đường dẫn hệ thống file. Nhờ đó, bạn có thể di chuyển file trong dự án mà vẫn tải được nó trong script mà không cần sửa script. Godot không dùng file bên ngoài để theo dõi ID, nghĩa là dự án không cần một nơi lưu trữ metadata tập trung. Xem pull request này để biết thông tin chi tiết.

Các phần này phải xuất hiện theo thứ tự, nhưng có thể khó phân biệt chúng. Điểm khác biệt duy nhất giữa chúng là phần tử đầu tiên trong tiêu đề của tất cả các mục trong phần. Ví dụ, tiêu đề của mọi resource bên ngoài phải bắt đầu bằng [ext_resource ...].

File TSCN có thể chứa chú thích một dòng bắt đầu bằng dấu chấm phẩy (;). Tuy nhiên, chú thích sẽ bị loại bỏ khi lưu file bằng trình chỉnh sửa Godot. Khoảng trắng trong file TSCN không có ý nghĩa (trừ trong chuỗi), nhưng khoảng trắng thừa sẽ bị loại bỏ khi lưu file.

Các mục trong file

Một tiêu đề có dạng [<resource_type> key1=value1 key2=value2 key3=value3 ...], trong đó resource_type là một trong các giá trị:

  • ext_resource

  • sub_resource

  • node

  • connection

Bên dưới mỗi tiêu đề là không hoặc nhiều cặp key = value. Giá trị có thể là kiểu dữ liệu phức tạp như Array, Transform, Color, v.v. Ví dụ, một Node3D trông như sau:

[node name="Cube" type="Node3D" unique_id=224283918]
transform = Transform3D(1, 0, 0, 0, 1, 0, 0, 0, 1, 1, 2, 3)

Scene tree

Cây scene được tạo nên từ… các node! Tiêu đề của mỗi node gồm tên, node cha, một ID duy nhất (dùng để theo dõi node ngay cả khi bị di chuyển hoặc đổi tên), và trong hầu hết trường hợp là kiểu. Ví dụ: [node name="PlayerCamera" type="Camera" parent="Player/Head" unique_id=1697057368]

Lưu ý rằng unique_id chỉ có trong các scene được lưu bằng Godot 4.6 trở lên. Vì vậy, không đảm bảo là nó luôn có mặt.

Các từ khóa hợp lệ khác gồm:

  • instance

  • instance_placeholder

  • owner

  • index (đặt thứ tự xuất hiện trong cây; nếu không có, các node kế thừa sẽ được ưu tiên hơn các node thường)

  • groups

  • node_paths (liệt kê tên các thuộc tính được export dưới kiểu Node nhưng được tham chiếu dưới dạng NodePath trong file)

Node đầu tiên trong file, cũng là gốc của scene, không được có mục parent="Path/To/Node" trong tiêu đề. Mọi file scene phải có đúng một gốc scene. Nếu không, Godot sẽ không import được file. Đường dẫn cha của các node khác phải là đường dẫn tuyệt đối, nhưng không được chứa tên của gốc scene. Nếu node là con trực tiếp của gốc scene, đường dẫn phải là ".". Đây là một ví dụ về cây scene (nhưng không có nội dung node):

[node name="Player" type="Node3D" unique_id=1155673912]                    ; The scene root
[node name="Arm" type="Node3D" parent="." unique_id=1010797352]            ; Parented to the scene root
[node name="Hand" type="Node3D" parent="Arm" unique_id=536436825]          ; Child of "Arm"
[node name="Finger" type="Node3D" parent="Arm/Hand" unique_id=1732647084]  ; Child of "Hand"

Mẹo

Để dễ nắm bắt cấu trúc file, bạn có thể lưu một file với node hoặc resource bất kỳ rồi tự xem nó bằng một trình soạn thảo bên ngoài. Bạn cũng có thể thay đổi dần dần trong trình chỉnh sửa Godot, đồng thời mở file .tscn hoặc .tres trong một trình soạn thảo văn bản bên ngoài có bật tự động tải lại để xem những gì thay đổi.

Đây là ví dụ về một scene chứa quả bóng dựa trên RigidBody3D có va chạm, phần hiển thị (mesh + đèn) và một camera là con của RigidBody3D:

[gd_scene format=3 uid="uid://cecaux1sm7mo0"]

[sub_resource type="SphereShape3D" id="SphereShape3D_tj6p1"]

[sub_resource type="SphereMesh" id="SphereMesh_4w3ye"]

[sub_resource type="StandardMaterial3D" id="StandardMaterial3D_k54se"]
albedo_color = Color(1, 0.639216, 0.309804, 1)

[node name="Ball" type="RigidBody3D" unique_id=1358867382]

[node name="CollisionShape3D" type="CollisionShape3D" parent="." unique_id=1279975976]
shape = SubResource("SphereShape3D_tj6p1")

[node name="MeshInstance3D" type="MeshInstance3D" parent="." unique_id=558852834]
mesh = SubResource("SphereMesh_4w3ye")
surface_material_override/0 = SubResource("StandardMaterial3D_k54se")

[node name="OmniLight3D" type="OmniLight3D" parent="." unique_id=1581292810 node_paths=PackedStringArray("follow_node")]
light_color = Color(1, 0.698039, 0.321569, 1)
omni_range = 10.0
follow_node = NodePath("..")

[node name="Camera3D" type="Camera3D" parent="." unique_id=795715540]
transform = Transform3D(1, 0, 0, 0, 0.939693, 0.34202, 0, -0.34202, 0.939693, 0, 1, 3)

NodePath

Cấu trúc cây là không đủ để biểu diễn toàn bộ scene. Godot dùng cấu trúc NodePath(Path/To/Node) để tham chiếu đến một node khác hoặc thuộc tính của node ở bất kỳ đâu trong cây scene. Đường dẫn là tương đối so với node hiện tại, với NodePath(".") trỏ đến node hiện tại và NodePath("") không trỏ đến node nào cả.

Ví dụ, MeshInstance3D dùng NodePath() để trỏ đến skeleton của nó. Tương tự, các track Animation dùng NodePath() để trỏ đến các thuộc tính node cần tạo hoạt ảnh.

NodePath cũng có thể trỏ đến một thuộc tính bằng hậu tố :property_name, và thậm chí trỏ đến một thành phần cụ thể đối với các kiểu vector, transform và color. Resource Animation dùng cách này để trỏ đến các thuộc tính cụ thể cần tạo hoạt ảnh. Ví dụ, NodePath("MeshInstance3D:scale.x") trỏ đến thành phần x của thuộc tính Vector3 scale trong MeshInstance3D.

Ví dụ, thuộc tính skeleton trong node MeshInstance3D tên mesh trỏ đến node cha của nó, Armature01:

[node name="mesh" type="MeshInstance3D" parent="Armature01" unique_id=1638249225]
skeleton = NodePath("..")

Skeleton3D

Node class_Skeleton3D kế thừa node Node3D, nhưng cũng có thể có danh sách xương được mô tả bằng các cặp khóa-giá trị theo định dạng bones/<id>/<attribute> = value. Các thuộc tính của xương gồm:

  • position: Vector3

  • rotation: Quaternion

  • scale: Vector3

Các thuộc tính này đều là tùy chọn. Ví dụ, một xương có thể chỉ định nghĩa position hoặc rotation mà không định nghĩa các thuộc tính còn lại.

Đây là ví dụ về một node skeleton có hai xương:

[node name="Skeleton3D" type="Skeleton3D" parent="PlayerModel/Robot_Skeleton" index="0" unique_id=542985694]
bones/1/position = Vector3(0.114471, 2.19771, -0.197845)
bones/1/rotation = Quaternion(0.191422, -0.0471201, -0.00831942, 0.980341)
bones/2/position = Vector3(-2.59096e-05, 0.236002, 0.000347473)
bones/2/rotation = Quaternion(-0.0580488, 0.0310587, -0.0085914, 0.997794)
bones/2/scale = Vector3(0.9276, 0.9276, 0.9276)

BoneAttachment3D

Node class_BoneAttachment3D là một node trung gian để mô tả một node được gắn làm con của một xương duy nhất trong node Skeleton. BoneAttachment có thuộc tính bone_name = "name of bone", cùng với một thuộc tính cho chỉ số xương tương ứng.

Ví dụ về một node class_Marker3D được gắn làm con của một xương trong Skeleton:

[node name="GunBone" type="BoneAttachment3D" parent="PlayerModel/Robot_Skeleton/Skeleton3D" index="5" unique_id=63481392]
transform = Transform3D(0.333531, 0.128981, -0.933896, 0.567174, 0.763886, 0.308015, 0.753209, -0.632331, 0.181604, -0.323915, 1.07098, 0.0497144)
bone_name = "hand.R"
bone_idx = 55

[node name="ShootFrom" type="Marker3D" parent="PlayerModel/Robot_Skeleton/Skeleton3D/GunBone" unique_id=679926736]
transform = Transform3D(1, 0, 0, 0, 1, 0, 0, 0, 1, 0, 0.4, 0)

AnimationPlayer

Node class_AnimationPlayer làm việc với một hoặc nhiều thư viện hoạt ảnh được lưu trong resource class_AnimationLibrary. Một thư viện hoạt ảnh là tập hợp các resource class_Animation riêng lẻ, có cấu trúc được mô tả tại đây.

Việc tách riêng hoạt ảnh và thư viện hoạt ảnh được thực hiện trong Godot 4, để hoạt ảnh có thể được import riêng biệt với mesh 3D, vốn là quy trình phổ biến trong các phần mềm hoạt ảnh 3D. Xem pull request gốc để biết chi tiết.

Nếu tên thư viện để trống, nó sẽ đóng vai trò là nguồn hoạt ảnh duy nhất cho AnimationPlayer này. Điều này cho phép dùng trực tiếp <animation_name> để phát hoạt ảnh từ script. Nếu bạn đặt tên cho thư viện, bạn phải phát nó dưới dạng <library_name>/<animation_name>. Cách này đảm bảo khả năng tương thích ngược và giữ nguyên quy trình làm việc hiện có nếu bạn không muốn dùng nhiều thư viện hoạt ảnh.

Tài nguyên

Resource là các thành phần tạo nên node. Ví dụ, một node MeshInstance3D sẽ đi kèm một resource ArrayMesh. Resource ArrayMesh có thể nằm bên trong hoặc bên ngoài file TSCN.

Tham chiếu đến resource được xử lý bằng ID duy nhất dạng chuỗi trong tiêu đề của resource. Điều này khác với thuộc tính uid, mà mỗi resource bên ngoài cũng có (nhưng subresource thì không).

Resource bên ngoài và resource nội bộ lần lượt được tham chiếu bằng ExtResource("id") và SubResource("id"). Vì có các cách khác nhau để tham chiếu resource nội bộ và bên ngoài, bạn có thể dùng cùng một ID cho cả resource nội bộ lẫn resource bên ngoài.

Ví dụ, để tham chiếu đến resource [ext_resource type="Material" uid="uid://c4cp0al3ljsjv" path="res://material.tres" id="1_7bt6s"], bạn sẽ dùng ExtResource("1_7bt6s").

Resource bên ngoài

Resource bên ngoài là liên kết đến các resource không nằm trong chính file TSCN. Một resource bên ngoài gồm đường dẫn, kiểu, UID (dùng để ánh xạ vị trí trong hệ thống file sang một định danh duy nhất) và ID (dùng để tham chiếu đến resource trong file scene).

Godot luôn sinh đường dẫn tuyệt đối tính từ thư mục resource, do đó có tiền tố res://, nhưng đường dẫn tương đối so với vị trí của file TSCN cũng hợp lệ.

Một số ví dụ về resource bên ngoài:

[ext_resource type="Texture2D" uid="uid://ccbm14ebjmpy1" path="res://gradient.tres" id="2_eorut"]
[ext_resource type="Material" uid="uid://c4cp0al3ljsjv" path="material.tres" id="1_7bt6s"]

Giống file TSCN, file TRES có thể chứa chú thích một dòng bắt đầu bằng dấu chấm phẩy (;). Tuy nhiên, chú thích sẽ bị loại bỏ khi lưu resource bằng trình chỉnh sửa Godot. Khoảng trắng trong file TRES không có ý nghĩa (trừ trong chuỗi), nhưng khoảng trắng thừa sẽ bị loại bỏ khi lưu file.

Resource nội bộ

File TSCN có thể chứa mesh, material và dữ liệu khác. Chúng nằm trong phần resource nội bộ của file. Tiêu đề của resource nội bộ trông giống tiêu đề của resource bên ngoài, ngoại trừ việc không có đường dẫn. Resource nội bộ cũng có các cặp key=value bên dưới mỗi tiêu đề. Ví dụ, một collision shape hình capsule trông như sau:

[sub_resource type="CapsuleShape3D" id="CapsuleShape3D_fdxgg"]
radius = 1.0
height = 3.0

Một số resource nội bộ chứa liên kết đến các resource nội bộ khác (chẳng hạn một mesh có material). Trong trường hợp này, resource được tham chiếu phải xuất hiện trước chỗ tham chiếu đến nó. Điều này có nghĩa là thứ tự rất quan trọng trong phần resource nội bộ của file.

ArrayMesh

Một ArrayMesh gồm nhiều bề mặt (surface) chứa trong mảng _surfaces (chú ý dấu gạch dưới ở đầu). Dữ liệu của mỗi surface được lưu trong một dictionary với các khóa sau:

  • aabb: Hộp bao căn theo trục (AABB) đã được tính toán, dùng cho việc xác định khả năng hiển thị.

  • attribute_data: Dữ liệu thuộc tính đỉnh, chẳng hạn normal, tangent, màu đỉnh, UV1, UV2 và dữ liệu đỉnh tùy chỉnh.

  • bone_aabbs: Hộp bao căn theo trục của từng xương, dùng cho việc xác định khả năng hiển thị.

  • format: Định dạng buffer của surface.

  • index_count: Số lượng chỉ số (index) trong surface. Giá trị này phải khớp với kích thước của index_data.

  • index_data: Dữ liệu chỉ số, xác định những đỉnh nào trong vertex_data được vẽ.

  • lods: Các biến thể mức độ chi tiết (LOD), được lưu dưới dạng mảng. Mỗi mức LOD tương ứng với hai giá trị trong mảng. Giá trị đầu tiên là tỷ lệ phần trăm không gian màn hình mà mức LOD đó phù hợp nhất (độ dài cạnh); giá trị thứ hai là danh sách các chỉ số cần được vẽ ở mức LOD đó.

  • material: Material được dùng khi vẽ surface.

  • name: Tên của surface. Tên này có thể dùng trong script và được import từ các phần mềm DCC 3D.

  • primitive: Kiểu primitive của surface, khớp với enum Mesh.PrimitiveType của Godot. 0 = điểm, 1 = đường, 2 = dải đường, 3 = tam giác (phổ biến nhất), 4 = dải tam giác.

  • skin_data: Dữ liệu trọng số xương.

  • vertex_count: Số lượng đỉnh trong surface. Giá trị này phải khớp với kích thước của vertex_data.

  • vertex_data: Dữ liệu vị trí đỉnh.

Hoạt ảnh

Mỗi hoạt ảnh có các thuộc tính sau:

  • length: Độ dài của hoạt ảnh tính bằng giây. Lưu ý rằng keyframe có thể được đặt bên ngoài khoảng [0; length], nhưng chúng có thể không có tác dụng tùy theo chế độ nội suy được chọn.

  • loop_mode: 0 = không lặp, 1 = lặp quay vòng, 2 = lặp có kẹp (clamped).

  • step: Kích thước bước dùng khi chỉnh sửa hoạt ảnh này trong trình chỉnh sửa. Giá trị này chỉ dùng trong trình chỉnh sửa; nó hoàn toàn không ảnh hưởng đến việc phát hoạt ảnh.

Mỗi track được mô tả bằng danh sách các cặp khóa-giá trị theo định dạng tracks/<id>/<attribute>. Mỗi track bao gồm:

  • type: Kiểu của track. Kiểu này xác định loại thuộc tính nào có thể được tạo hoạt ảnh bằng track này, và cách nó được hiển thị cho người dùng trong trình chỉnh sửa. Các kiểu hợp lệ là value (track thuộc tính chung), position_3d, rotation_3d, scale_3d, blend_shape (các track hoạt ảnh 3D được tối ưu), method (track gọi phương thức), bezier (track đường cong Bezier), audio (track phát âm thanh), animation (track phát các hoạt ảnh khác).

  • imported: true nếu track được tạo từ một scene 3D được import, false nếu người dùng tạo thủ công trong trình chỉnh sửa Godot hoặc bằng script.

  • enabled: true nếu track đang có hiệu lực, false nếu track đã bị tắt trong trình chỉnh sửa.

  • path: Đường dẫn đến thuộc tính node chịu tác động của track. Thuộc tính được viết sau đường dẫn node, phân tách bằng dấu :.

  • interp: Chế độ nội suy được dùng. 0 = gần nhất, 1 = tuyến tính, 2 = bậc ba, 3 = góc tuyến tính, 4 = góc bậc ba.

  • loop_wrap: true nếu track được thiết kế để quay vòng khi hoạt ảnh lặp lại, false nếu track bị kẹp vào keyframe đầu/cuối.

  • keys: Các giá trị của track hoạt ảnh. Cấu trúc của thuộc tính này phụ thuộc vào type.

Đây là một scene chứa AnimationPlayer thu nhỏ dần một khối lập phương theo thời gian bằng track thuộc tính chung. Quy trình AnimationLibrary không được dùng, nên thư viện hoạt ảnh có tên trống (nhưng hoạt ảnh vẫn được đặt tên scale_down). Lưu ý rằng track RESET không được tạo trong AnimationPlayer này cho ngắn gọn:

Với các track thuộc tính chung value, keys là một dictionary chứa 3 mảng: vị trí trong times (PackedFloat32Array), giá trị easing trong transitions (PackedFloat32Array) và giá trị trong values (Array). Ngoài ra còn có thuộc tính update, là một số nguyên với các giá trị 0 = liên tục, 1 = rời rạc, 2 = capture.

Đây là một resource Animation thứ hai sử dụng các track 3D Position và 3D Rotation. Các track này (cùng với track 3D Scale) thay thế track Transform của Godot 3. Chúng được tối ưu để phát nhanh và có thể được nén tùy chọn.

Nhược điểm của các kiểu track được tối ưu này là chúng không thể dùng giá trị easing tùy chỉnh. Thay vào đó, mọi keyframe đều dùng nội suy tuyến tính. Dù vậy, bạn vẫn có thể chọn dùng nội suy gần nhất hoặc bậc ba cho mọi keyframe trong một track bằng cách thay đổi chế độ nội suy của track.

[sub_resource type="Animation" id="Animation_r2qdp"]
resource_name = "move_and_rotate"
length = 1.5
loop_mode = 2
step = 0.05
tracks/0/type = "position_3d"
tracks/0/imported = false
tracks/0/enabled = true
tracks/0/path = NodePath("Box")
tracks/0/interp = 1
tracks/0/loop_wrap = true
tracks/0/keys = PackedFloat32Array(0, 1, 0, 0, 0, 1.5, 1, 1.5, 1, 0)
tracks/1/type = "rotation_3d"
tracks/1/imported = false
tracks/1/enabled = true
tracks/1/path = NodePath("Box")
tracks/1/interp = 1
tracks/1/loop_wrap = true
tracks/1/keys = PackedFloat32Array(0, 1, 0.211, -0.047, 0.211, 0.953, 1.5, 1, 0.005, 0.976, -0.216, 0.022)

Với các track vị trí, xoay và tỷ lệ 3D, keys là một PackedFloat32Array với mọi giá trị được lưu theo trình tự.

Trong hình minh họa bên dưới, T là thời điểm của keyframe tính bằng giây kể từ đầu hoạt ảnh, E là transition của keyframe (hiện luôn là 1). Với các track vị trí và tỷ lệ 3D, X, Y, Z là tọa độ của Vector3. Với track xoay 3D, X, Y, Z và W là tọa độ của Quaternion.

# For 3D position and scale, which use Vector3:
tracks/<id>/keys = PackedFloat32Array(T, E,   X, Y, Z,      T, E,   X, Y, Z, ...)

# For 3D rotation, which use Quaternion:
tracks/<id>/keys = PackedFloat32Array(T, E,   X, Y, Z, W,      T, E,   X, Y, Z, W, ...)
