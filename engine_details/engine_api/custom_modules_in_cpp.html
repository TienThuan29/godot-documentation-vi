Module tùy chỉnh bằng C++

Module

Godot cho phép mở rộng engine theo cách module hóa. Các module mới có thể được tạo rồi bật/tắt. Điều này cho phép thêm chức năng mới cho engine ở mọi cấp độ mà không cần sửa phần lõi, và có thể tách ra để dùng và tái sử dụng trong các module khác nhau.

Các module nằm trong thư mục con modules/ của hệ thống build. Mặc định có hàng chục module được bật, chẳng hạn GDScript (đúng vậy, nó không phải là một phần của engine cơ sở), hỗ trợ GridMap, module biểu thức chính quy và nhiều module khác. Bạn có thể tạo và kết hợp bao nhiêu module mới tùy thích. Hệ thống build SCons sẽ xử lý việc đó một cách trong suốt.

Để làm gì?

Mặc dù nên viết phần lớn game bằng script (vì nó tiết kiệm rất nhiều thời gian), hoàn toàn có thể dùng C++ thay thế. Thêm module C++ có thể hữu ích trong các tình huống sau:

  • Liên kết một thư viện bên ngoài vào Godot (như PhysX, FMOD, v.v.).

  • Tối ưu các phần quan trọng của game.

  • Thêm chức năng mới cho engine và/hoặc trình chỉnh sửa.

  • Port một game có sẵn sang Godot.

  • Viết toàn bộ một game mới bằng C++ vì bạn không thể sống thiếu C++.

Ghi chú

Mặc dù có thể dùng module cho logic game tùy chỉnh, GDExtension thường phù hợp hơn vì nó không yêu cầu biên dịch lại engine sau mỗi lần thay đổi mã.

Module C++ chủ yếu cần thiết khi GDExtension không đủ và cần tích hợp sâu hơn với engine.

Tạo một module mới

Trước khi tạo module, hãy nhớ tải mã nguồn Godot và biên dịch nó.

Để tạo module mới, bước đầu tiên là tạo một thư mục bên trong modules/. Nếu muốn duy trì module riêng biệt, bạn có thể checkout một VCS khác vào modules và sử dụng nó.

Module ví dụ sẽ có tên "summator" (godot/modules/summator). Bên trong, chúng ta sẽ tạo một lớp summator:

godot/modules/summator/summator.h
#pragma once

#include "core/object/ref_counted.h"

class Summator : public RefCounted {
    GDCLASS(Summator, RefCounted);

    int count;

protected:
    static void _bind_methods();

public:
    void add(int p_value);
    void reset();
    int get_total() const;

    Summator();
};

Sau đó là file cpp.

godot/modules/summator/summator.cpp
#include "summator.h"

#include "core/object/class_db.h"

void Summator::add(int p_value) {
    count += p_value;
}

void Summator::reset() {
    count = 0;
}

int Summator::get_total() const {
    return count;
}

void Summator::_bind_methods() {
    ClassDB::bind_method(D_METHOD("add", "value"), &Summator::add);
    ClassDB::bind_method(D_METHOD("reset"), &Summator::reset);
    ClassDB::bind_method(D_METHOD("get_total"), &Summator::get_total);
}

Summator::Summator() {
    count = 0;
}

Tiếp theo, lớp mới cần được đăng ký bằng cách nào đó, nên cần tạo thêm hai file nữa:

register_types.h
register_types.cpp

Quan trọng

Các file này phải nằm ở thư mục cấp cao nhất của module (cạnh các file SCsub và config.py) để module được đăng ký đúng cách.

Các file này nên chứa nội dung sau:

godot/modules/summator/register_types.h
#include "modules/register_module_types.h"

void initialize_summator_module(ModuleInitializationLevel p_level);
void uninitialize_summator_module(ModuleInitializationLevel p_level);
/* yes, the word in the middle must be the same as the module folder name */
godot/modules/summator/register_types.cpp
#include "register_types.h"

#include "core/object/class_db.h"
#include "summator.h"

void initialize_summator_module(ModuleInitializationLevel p_level) {
    if (p_level != MODULE_INITIALIZATION_LEVEL_SCENE) {
        return;
    }
    ClassDB::register_class<Summator>();
}

void uninitialize_summator_module(ModuleInitializationLevel p_level) {
    if (p_level != MODULE_INITIALIZATION_LEVEL_SCENE) {
        return;
    }
   // Nothing to do here in this example.
}

Tiếp theo, chúng ta cần tạo file SCsub để hệ thống build biên dịch module này:

godot/modules/summator/SCsub
# SCsub

Import('env')

env.add_source_files(env.modules_sources, "*.cpp") # Add all cpp files to the build

Với nhiều file nguồn, bạn cũng có thể thêm từng file riêng lẻ vào một danh sách chuỗi Python:

src_list = ["summator.cpp", "other.cpp", "etc.cpp"]
env.add_source_files(env.modules_sources, src_list)

Điều này mở ra nhiều khả năng mạnh mẽ khi dùng Python để xây dựng danh sách file bằng vòng lặp và câu lệnh logic. Hãy xem một số module đi kèm Godot mặc định để có ví dụ.

Để thêm các thư mục include cho trình biên dịch tìm kiếm, bạn có thể nối chúng vào các đường dẫn của environment:

env.Append(CPPPATH=["mylib/include"]) # this is a relative path
env.Append(CPPPATH=["#myotherlib/include"]) # this is an 'absolute' path

Nếu bạn muốn thêm các cờ trình biên dịch tùy chỉnh khi build module, bạn cần clone env trước, để nó không thêm các cờ đó vào toàn bộ bản build Godot (có thể gây lỗi). Ví dụ SCsub với cờ tùy chỉnh:

godot/modules/summator/SCsub
Import('env')

module_env = env.Clone()
module_env.add_source_files(env.modules_sources, "*.cpp")
# Append CCFLAGS flags for both C and C++ code.
module_env.Append(CCFLAGS=['-O2'])
# If you need to, you can:
# - Append CFLAGS for C code only.
# - Append CXXFLAGS for C++ code only.

Và cuối cùng là file cấu hình của module, đây là một script Python phải có tên config.py:

godot/modules/summator/config.py
# config.py

def can_build(env, platform):
    return True

def configure(env):
    pass

Module được hỏi liệu có thể build cho một nền tảng cụ thể hay không (trong trường hợp này, True nghĩa là nó sẽ build cho mọi nền tảng).

Vậy là xong. Hy vọng nó không quá phức tạp! Module của bạn sẽ trông như sau:

godot/modules/summator/config.py
godot/modules/summator/summator.h
godot/modules/summator/summator.cpp
godot/modules/summator/register_types.h
godot/modules/summator/register_types.cpp
godot/modules/summator/SCsub

Sau đó bạn có thể nén nó lại và chia sẻ module với mọi người. Khi build cho mọi nền tảng (hướng dẫn ở các phần trước), module của bạn sẽ được đưa vào.

Sử dụng module

Giờ bạn có thể dùng module vừa tạo từ bất kỳ script nào:

var s = Summator.new()
s.add(10)
s.add(20)
s.add(30)
print(s.get_total())
s.reset()

Kết quả đầu ra sẽ là 60.

Cảnh báo

Nếu module của bạn cần được truy cập từ dự án đang chạy (không chỉ từ trình chỉnh sửa), bạn cũng phải biên dịch lại mọi export template định dùng, rồi chỉ định đường dẫn tới template tùy chỉnh trong từng export preset. Nếu không, bạn sẽ gặp lỗi khi chạy dự án vì module không được biên dịch vào export template. Xem các trang Biên dịch để biết thêm thông tin.

Biên dịch module từ bên ngoài

Biên dịch module đòi hỏi di chuyển mã nguồn của module trực tiếp vào thư mục modules/ của engine. Mặc dù đây là cách đơn giản nhất để biên dịch module, có một vài lý do khiến cách này có thể không thực tế:

  1. Phải sao chép thủ công mã nguồn module mỗi khi muốn biên dịch engine có hoặc không có module, hoặc phải làm thêm các bước để tắt module thủ công khi biên dịch bằng một tùy chọn build tương tự module_summator_enabled=no. Tạo symbolic link cũng có thể là một giải pháp, nhưng bạn có thể cần vượt qua thêm các hạn chế của hệ điều hành, như cần quyền tạo symbolic link nếu làm việc này bằng script.

  2. Tùy vào việc bạn có phải làm việc với mã nguồn engine hay không, các file module thêm trực tiếp vào modules/ sẽ thay đổi working tree đến mức việc dùng VCS (như git) trở nên rườm rà, vì bạn cần đảm bảo chỉ mã liên quan đến engine được commit bằng cách lọc các thay đổi.

Vì vậy, nếu bạn thấy cần cấu trúc độc lập cho các module tùy chỉnh, hãy lấy module "summator" của chúng ta và chuyển nó ra thư mục cha của engine:

mkdir ../modules
mv modules/summator ../modules

Biên dịch engine cùng module của chúng ta bằng cách cung cấp tùy chọn build custom_modules, tùy chọn này nhận một danh sách đường dẫn thư mục chứa các module C++ tùy chỉnh, phân tách bằng dấu phẩy, tương tự như sau:

scons custom_modules=../modules

Hệ thống build sẽ phát hiện tất cả module trong thư mục ../modules và biên dịch chúng tương ứng, bao gồm cả module "summator" của chúng ta.

Cảnh báo

Mọi đường dẫn truyền vào custom_modules sẽ được chuyển nội bộ thành đường dẫn tuyệt đối để phân biệt giữa module tùy chỉnh và module có sẵn. Điều này có nghĩa là những việc như sinh tài liệu cho module có thể phụ thuộc vào một cấu trúc đường dẫn cụ thể trên máy của bạn.

Tùy chỉnh việc khởi tạo các kiểu của module

Module có thể tương tác với các lớp có sẵn khác của engine trong lúc chạy và thậm chí ảnh hưởng đến cách các kiểu lõi được khởi tạo. Cho đến giờ, chúng ta đã dùng register_summator_types để đưa các lớp của module vào sử dụng trong engine.

Thứ tự thiết lập engine có thể được tóm tắt sơ bộ thành danh sách các phương thức đăng ký kiểu sau:

preregister_module_types();
preregister_server_types();
register_core_singletons();
register_server_types();
register_scene_types();
EditorNode::register_editor_types();
register_platform_apis();
register_module_types();
initialize_physics();
initialize_navigation_server();
register_server_singletons();
register_driver_types();
ScriptServer::init_languages();

Lớp Summator của chúng ta được khởi tạo trong lời gọi register_module_types(). Hãy hình dung chúng ta cần đáp ứng một số phụ thuộc runtime chung của module (như singleton), hoặc cho phép override các callback phương thức hiện có của engine trước khi chính engine gán chúng. Trong trường hợp đó, chúng ta muốn đảm bảo các lớp của module được đăng ký trước mọi kiểu có sẵn khác.

Đây là lúc chúng ta có thể định nghĩa một phương thức tùy chọn preregister_summator_types(), phương thức này sẽ được gọi trước mọi thứ khác trong giai đoạn thiết lập engine preregister_module_types().

Giờ chúng ta cần thêm phương thức này vào file header và file nguồn register_types:

godot/modules/summator/register_types.h
#define MODULE_SUMMATOR_HAS_PREREGISTER
void preregister_summator_types();

void register_summator_types();
void unregister_summator_types();

Ghi chú

Không giống các phương thức đăng ký khác, chúng ta phải định nghĩa tường minh MODULE_SUMMATOR_HAS_PREREGISTER để hệ thống build biết cần đưa những lời gọi phương thức nào vào lúc biên dịch. Tên module cũng phải được chuyển thành chữ hoa.

godot/modules/summator/register_types.cpp
#include "register_types.h"

#include "core/object/class_db.h"
#include "summator.h"

void preregister_summator_types() {
    // Called before any other core types are registered.
    // Nothing to do here in this example.
}

void register_summator_types() {
    ClassDB::register_class<Summator>();
}

void unregister_summator_types() {
   // Nothing to do here in this example.
}

Viết tài liệu tùy chỉnh

Viết tài liệu có vẻ là một việc nhàm chán, nhưng rất nên viết tài liệu cho module mới tạo để người dùng dễ tận dụng nó hơn. Chưa kể đoạn mã bạn viết một năm trước có thể trở nên khó phân biệt với mã do người khác viết, vì vậy hãy tử tế với chính mình trong tương lai!

Có một số bước để thiết lập tài liệu tùy chỉnh cho module:

  1. Tạo một thư mục mới ở gốc của module. Tên thư mục có thể là bất kỳ, nhưng chúng ta sẽ dùng tên doc_classes xuyên suốt phần này.

  2. Bây giờ, chúng ta cần sửa config.py, thêm đoạn mã sau:

    def get_doc_path():
    return "doc_classes"

def get_doc_classes():
    return [
        "Summator",
    ]

Hàm get_doc_path() được hệ thống build dùng để xác định vị trí của tài liệu. Trong trường hợp này, chúng sẽ nằm trong thư mục modules/summator/doc_classes. Nếu bạn không định nghĩa hàm này, đường dẫn tài liệu cho module sẽ quay về thư mục chính doc/classes.

Phương thức get_doc_classes() cần thiết để hệ thống build biết những lớp đã đăng ký nào thuộc về module. Bạn cần liệt kê tất cả các lớp của mình ở đây. Những lớp bạn không liệt kê sẽ nằm trong thư mục chính doc/classes.

Mẹo

Bạn có thể dùng Git để kiểm tra xem mình có bỏ sót lớp nào không bằng cách xem các file chưa được theo dõi với git status. Ví dụ:

git status

Ví dụ kết quả đầu ra:

Untracked files:
    (use "git add <file>..." to include in what will be committed)

    doc/classes/MyClass2D.xml
    doc/classes/MyClass4D.xml
    doc/classes/MyClass5D.xml
    doc/classes/MyClass6D.xml
    ...

  1. Bây giờ chúng ta có thể tạo tài liệu:

Chúng ta có thể làm việc này bằng cách chạy doctool của Godot, tức là godot --doctool <path>, lệnh này sẽ xuất tài liệu tham khảo API của engine ra <path> đã cho ở định dạng XML.

Trong trường hợp của chúng ta, ta sẽ trỏ nó tới gốc của repository đã clone. Bạn có thể trỏ nó tới một thư mục khác, rồi chỉ sao chép những file bạn cần.

Chạy lệnh:

bin/<godot_binary> --doctool .

Bây giờ nếu bạn vào thư mục godot/modules/summator/doc_classes, bạn sẽ thấy nó chứa file Summator.xml, hoặc các lớp khác mà bạn đã tham chiếu trong hàm get_doc_classes.

Chỉnh sửa (các) file theo hướng dẫn cơ bản về class reference rồi biên dịch lại engine.

Khi quá trình biên dịch hoàn tất, tài liệu sẽ có thể truy cập được trong hệ thống tài liệu tích hợp của engine.

Để tài liệu luôn được cập nhật, từ giờ trở đi bạn chỉ cần sửa một trong các file XML và biên dịch lại engine.

Nếu bạn thay đổi API của module, bạn cũng có thể trích xuất lại tài liệu, chúng sẽ chứa những nội dung bạn đã thêm trước đó. Tất nhiên, nếu bạn trỏ nó tới thư mục godot của mình, hãy đảm bảo không làm mất công sức bằng cách trích xuất tài liệu cũ từ một bản build engine cũ hơn đè lên tài liệu mới hơn.

Lưu ý rằng nếu bạn không có quyền ghi vào <path> đã cung cấp, bạn có thể gặp lỗi tương tự như sau:

ERROR: Can't write doc file: docs/doc/classes/@GDScript.xml
   At: editor/doc/doc_data.cpp:956

Viết unit test tùy chỉnh

Có thể viết các unit test độc lập như một phần của module C++. Nếu bạn chưa quen với quy trình unit test trong Godot, hãy xem Unit test.

Quy trình như sau:

  1. Tạo một thư mục mới tên tests/ dưới gốc của module:

cd modules/summator
mkdir tests
cd tests

  1. Tạo một test suite mới: test_summator.h. Header phải có tiền tố test_ để hệ thống build có thể thu thập và đưa nó vào tests/test_main.cpp, nơi các test được chạy.

  2. Viết một vài test case. Đây là một ví dụ:

godot/modules/summator/tests/test_summator.h
#pragma once

#include "tests/test_macros.h"

#include "modules/summator/summator.h"

namespace TestSummator {

TEST_CASE("[Modules][Summator] Adding numbers") {
    Ref<Summator> s = memnew(Summator);
    CHECK(s->get_total() == 0);

    s->add(10);
    CHECK(s->get_total() == 10);

    s->add(20);
    CHECK(s->get_total() == 30);

    s->add(30);
    CHECK(s->get_total() == 60);

    s->reset();
    CHECK(s->get_total() == 0);
}

} // namespace TestSummator

  1. Biên dịch engine với scons tests=yes, rồi chạy các test bằng lệnh sau:

./bin/<godot_binary> --test --source-file="*test_summator*" --success

Bây giờ bạn sẽ thấy các assertion vượt qua.

Thêm biểu tượng tùy chỉnh cho trình chỉnh sửa

Tương tự như cách viết tài liệu độc lập bên trong module, bạn cũng có thể tạo biểu tượng tùy chỉnh của riêng mình cho các lớp để hiển thị trong trình chỉnh sửa.

Về quy trình thực tế để tạo biểu tượng trình chỉnh sửa tích hợp vào engine, trước tiên hãy xem Biểu tượng trình chỉnh sửa.

Sau khi đã tạo (các) biểu tượng, hãy tiếp tục với các bước sau:

  1. Tạo một thư mục mới tên icons ở gốc của module. Đây là đường dẫn mặc định mà engine tìm biểu tượng trình chỉnh sửa của module.

  2. Di chuyển các biểu tượng svg vừa tạo (đã tối ưu hay chưa) vào thư mục đó.

  3. Biên dịch lại engine và chạy trình chỉnh sửa. Giờ (các) biểu tượng sẽ xuất hiện trong giao diện trình chỉnh sửa ở những chỗ phù hợp.

Nếu bạn muốn lưu biểu tượng ở chỗ khác trong module, hãy thêm đoạn mã sau vào config.py để ghi đè đường dẫn mặc định:

def get_icons_path():
    return "path/to/icons"

Tổng kết

Hãy nhớ:

  • Dùng macro GDCLASS cho kế thừa, để Godot có thể bao bọc (wrap) nó.

  • Dùng _bind_methods để liên kết các hàm của bạn với scripting, và cho phép chúng hoạt động như callback cho signal.

  • Tránh đa kế thừa cho các lớp được expose cho Godot, vì GDCLASS không hỗ trợ điều này. Bạn vẫn có thể dùng đa kế thừa trong các lớp của riêng mình, miễn là chúng không được expose cho API scripting của Godot.

Nhưng chưa hết, tùy vào việc bạn làm, bạn sẽ gặp một số bất ngờ (hy vọng là tích cực).

  • Nếu bạn kế thừa từ class_Node (hoặc bất kỳ kiểu node dẫn xuất nào, như Sprite2D), lớp mới của bạn sẽ xuất hiện trong trình chỉnh sửa, trong cây kế thừa của hộp thoại "Add Node".

  • Nếu bạn kế thừa từ class_Resource, nó sẽ xuất hiện trong danh sách resource, và mọi thuộc tính được expose đều có thể được tuần tự hóa khi lưu/tải.

  • Theo cùng logic đó, bạn có thể mở rộng trình chỉnh sửa và gần như mọi khu vực của engine.
