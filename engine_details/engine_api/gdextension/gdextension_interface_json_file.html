File JSON giao diện C

File gdextension_interface.json là "nguồn chân lý" cho API C mà Godot dùng để giao tiếp với các GDExtension.

Bạn có thể dùng file thực thi Godot để xuất file này bằng lệnh sau:

godot --headless --dump-gdextension-interface-json

File này được dùng bởi các binding ngôn ngữ GDExtension để sinh code sử dụng API này dưới bất kỳ hình thức nào hợp lý nhất với ngôn ngữ đó.

Ghi chú

Đừng nhầm file này với extension_api.json, file cũng được các binding ngôn ngữ GDExtension sử dụng và chứa thông tin về các lớp và phương thức mà Godot expose. gdextension_interface.json ở mức thấp hơn và được dùng để tương tác với các lớp và phương thức cấp cao hơn đó.

Với các ngôn ngữ có thể mở rộng qua C, hoặc cung cấp công cụ để tương tác với code C, bạn cũng có thể dùng file thực thi Godot để xuất một file header C được sinh sẵn:

godot --headless --dump-gdextension-interface

Ghi chú

File header này tương thích với các phiên bản trước của file header từng đi kèm Godot 4.5 trở về trước, nghĩa là nó giữ lại một số lỗi chính tả trong tên để đảm bảo tương thích.

Mục tiêu của trang này là giải thích định dạng JSON cho các binding ngôn ngữ GDExtension muốn tự sinh code từ JSON.

Cấu trúc tổng thể

File JSON được chia thành 3 phần:

  • Header, gồm một số thông tin linh tinh ở cấp cao nhất của file JSON.

  • Khóa types, định nghĩa mọi kiểu dùng trong giao diện GDExtension.

  • Khóa interface, định nghĩa mọi con trỏ hàm có thể load qua con trỏ hàm GDExtensionInterfaceGetProcAddress, được truyền cho mọi GDExtension khi chúng được load.

Có một JSON schema đầy đủ đi kèm mã nguồn Godot.

Dù có thể thêm kiểu và hàm giao diện mới ở mỗi bản phát hành minor của Godot, chúng tôi cố gắng không bao giờ thay đổi chúng theo cách phá vỡ tương thích ngược, hay xóa chúng. Mọi hàm giao diện đều được gắn nhãn phiên bản Godot mà nó được giới thiệu (khóa since), nên bạn luôn có thể dùng phiên bản mới nhất của file, và chỉ cần tránh dùng bất cứ thứ gì thuộc các phiên bản Godot mới hơn phiên bản bạn đang nhắm tới.

Header

"Header" gồm 3 khóa linh tinh ở cấp cao nhất của file:

  • _copyright: Văn bản bản quyền và giấy phép chuẩn mà Godot đưa vào mọi file mã nguồn.

  • $schema: Trỏ tới JSON schema, tương đối so với file này. Đặt schema trong cùng thư mục có thể hữu ích nếu bạn xem file bằng trình soạn thảo code hiểu JSON schema.

  • format_version: Một số nguyên chỉ phiên bản của định dạng file (tức là schema). Hiện tại chỉ có một phiên bản định dạng (1). Nếu chúng tôi thay đổi định dạng file theo cách không tương thích, con số này sẽ được tăng lên. Nó không phản ánh phiên bản của dữ liệu trong file (nên sẽ không thay đổi giữa các phiên bản Godot), mà chỉ phản ánh định dạng. Hy vọng sẽ không bao giờ phải dùng đến nó, nhưng nó cho phép các trình sinh code báo lỗi sớm nếu gặp giá trị không mong đợi ở đây.

Kiểu

Phần types là một mảng các kiểu sẽ được dùng bởi các kiểu khác và bởi các hàm giao diện ở phần cuối.

Các kiểu nên được đánh giá theo thứ tự. Kiểu phía sau có thể tham chiếu tới kiểu phía trước, nhưng kiểu phía trước sẽ không tham chiếu tới kiểu phía sau.

Có một nhóm nhỏ kiểu tích hợp sẵn không được liệt kê tường minh trong JSON:

  • void

  • int8_t

  • uint8_t

  • int16_t

  • uint16_t

  • int32_t

  • uint32_t

  • int64_t

  • uint64_t

  • size_t (uint32_t trên kiến trúc 32-bit và uint64_t trên kiến trúc 64-bit)

  • char

  • char16_t

  • char32_t

  • wchar_t

  • float

  • double

Các kiểu này tương ứng với các kiểu C tương đương.

Ngoài ra, kiểu có thể kèm các modifier như:

  • * (ví dụ int8_t*) để chỉ con trỏ tới kiểu đó

  • const (ví dụ const int8_t*) để chỉ kiểu const

Mỗi kiểu được định nghĩa trong file JSON thuộc một trong 5 "kind":

  • enum

  • handle

  • alias

  • struct

  • function

Bất kể "kind" là gì, mọi kiểu đều có thể có các khóa sau:

  • kind (bắt buộc): "Kind" của kiểu.

  • name (bắt buộc): Tên của kiểu, có thể dùng như một định danh C hợp lệ.

  • description: Một mảng chuỗi mô tả kiểu, trong đó mỗi chuỗi là một dòng tài liệu (định dạng description này được dùng xuyên suốt file JSON).

  • deprecated: Một đối tượng với các khóa riêng gồm phiên bản Godot mà kiểu bị deprecated (since), thông điệp giải thích việc deprecated (message), và tùy chọn một thứ thay thế nên dùng (replacement).

Enum

Enum là số nguyên 32-bit với một tập giá trị cố định. Trong C, chúng có thể được biểu diễn bằng enum.

Chúng có các khóa sau:

  • is_bitfield: Nếu là true, enum này là một bitfield, trong đó các giá trị enum có thể được kết hợp bằng phép OR bit. Mặc định là false.

  • values: Mảng các giá trị cố định của enum này, mỗi giá trị có name, value và description.

Enum nên được biểu diễn bằng int32_t, trừ khi is_bitfield là true, khi đó nên dùng uint32_t.

Ví dụ

{
    "name": "GDExtensionInitializationLevel",
    "kind": "enum",
    "values": [
        {
            "name": "GDEXTENSION_INITIALIZATION_CORE",
            "value": 0
        },
        {
            "name": "GDEXTENSION_INITIALIZATION_SERVERS",
            "value": 1
        },
        {
            "name": "GDEXTENSION_INITIALIZATION_SCENE",
            "value": 2
        },
        {
            "name": "GDEXTENSION_INITIALIZATION_EDITOR",
            "value": 3
        },
        {
            "name": "GDEXTENSION_MAX_INITIALIZATION_LEVEL",
            "value": 4
        }
    ]
}

Handle

Handle là con trỏ tới các struct opaque. Trong C, chúng có thể được biểu diễn bằng void * hoặc struct{} *.

Chúng có các khóa sau:

  • is_const: Nếu là true, kiểu handle này được xem là "con trỏ const", nghĩa là dữ liệu bên trong sẽ không bị thay đổi. Mặc định là false.

  • is_uninitialized: Nếu là true, kiểu handle này được xem là trỏ tới vùng nhớ chưa khởi tạo (có thể được khởi tạo bằng các hàm giao diện). Mặc định là false.

  • parent: Tên tùy chọn của một kiểu handle khác, nếu kiểu handle này là phiên bản const hoặc chưa khởi tạo của kiểu cha. Chỉ có ý nghĩa nếu is_const hoặc is_uninitialized là true.

Handle có kích thước bằng con trỏ trên kiến trúc tương ứng (ví dụ 64-bit trên x86_64 và 32-bit trên x86_32).

Ví dụ

{
    "name": "GDExtensionStringNamePtr",
    "kind": "handle"
}

Alias

Alias là tên thay thế cho một kiểu. Trong C, chúng có thể được biểu diễn bằng typedef.

Chúng chỉ có một khóa bổ sung:

  • type: Kiểu mà alias là tên thay thế. Nó có thể kèm modifier như mô tả ở trên.

Chúng nên được biểu diễn bằng cùng kiểu C với kiểu mà chúng tham chiếu tới.

Ví dụ

{
    "name": "GDExtensionInt",
    "kind": "alias",
    "type": "int64_t"
}

Struct

Struct đại diện cho các struct của C (tức một khối bộ nhớ gồm các thành viên cho trước theo thứ tự), và nên tuân theo mọi quy tắc bố cục và căn chỉnh giống như struct C.

Chúng chỉ có một khóa bổ sung:

  • members: Một mảng đối tượng, mỗi đối tượng có name, type (có thể kèm modifier) và description.

Ví dụ

{
    "name": "GDExtensionCallError",
    "kind": "struct",
    "members": [
        {
            "name": "error",
            "type": "GDExtensionCallErrorType"
        },
        {
            "name": "argument",
            "type": "int32_t"
        },
        {
            "name": "expected",
            "type": "int32_t"
        }
    ]
}

Hàm

Function đại diện cho các kiểu con trỏ hàm C, với danh sách đối số và kiểu trả về, và nên tuân theo cùng yêu cầu về kích thước và căn chỉnh như con trỏ hàm C.

Chúng có các thành viên sau:

  • return_value: Một đối tượng có type (có thể kèm modifier) và description. Nếu hàm không có giá trị trả về, mục này sẽ bị lược bỏ.

  • arguments (bắt buộc): Một mảng đối số của hàm, mỗi đối số có type (có thể kèm modifier), name và description.

Ví dụ

{
    "name": "GDExtensionPtrConstructor",
    "kind": "function",
    "arguments": [
        {
            "name": "p_base",
            "type": "GDExtensionUninitializedTypePtr"
        },
        {
            "name": "p_args",
            "type": "const GDExtensionConstTypePtr*"
        }
    ]
}

Giao diện

Phần interface của file JSON là danh sách các hàm giao diện, có thể được load theo name bằng con trỏ hàm GDExtensionInterfaceGetProcAddress, được truyền cho mọi GDExtension khi chúng được load.

Các hàm interface có một số khóa giống với kiểu, bao gồm name (bắt buộc), deprecated và description.

Chúng cũng có return_value và arguments (bắt buộc), với định dạng giống các khóa tương ứng của kiểu hàm (như đã mô tả ở phần trước).

Chỉ có một vài khóa riêng biệt:

  • since (bắt buộc): Phiên bản Godot đã giới thiệu hàm interface này.

  • see: Một mảng chuỗi mô tả các tham chiếu bên ngoài có thêm thông tin, ví dụ tên lớp hoặc hàm trong mã nguồn Godot, hoặc URL trỏ đến tài liệu.

  • legacy_type_name: Tên cũ được dùng cho kiểu con trỏ hàm trong header do Godot sinh ra, khi tên cũ không khớp với quy tắc đặt tên của các kiểu này. Trường này chỉ tồn tại để chúng tôi có thể sinh header theo cách tương thích ngược với header của Godot 4.5 trở về trước, và bạn không nên dùng nó trừ khi cũng cần duy trì khả năng tương thích với header cũ.

Ví dụ

{
    "name": "get_godot_version",
    "arguments": [
        {
            "name": "r_godot_version",
            "type": "GDExtensionGodotVersion*",
            "description": [
                "A pointer to the structure to write the version information into."
            ]
        }
    ],
    "description": [
        "Gets the Godot version that the GDExtension was loaded into."
    ],
    "since": "4.1",
    "deprecated": {
        "since": "4.5",
        "replace_with": "get_godot_version2"
    }
}
