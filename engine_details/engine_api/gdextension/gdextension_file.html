File .gdextension

Giới thiệu

File .gdextension trong dự án của bạn chứa chỉ dẫn về cách load GDExtension. Các chỉ dẫn được chia thành những mục cụ thể. Trang này sẽ cho bạn cái nhìn tổng quan nhanh về các tùy chọn khác nhau có sẵn. Để bắt đầu với C++ (godot-cpp), hãy xem Ví dụ GDExtension C++.

Mục configuration

Thuộc tính

Kiểu

Mô tả

entry_symbol

String

Tên của hàm entry dùng để khởi tạo GDExtension. Hàm này nên được định nghĩa trong file register_types.cpp khi dùng godot-cpp. Cần thêm mục này để extension hoạt động.

compatibility_minimum

String

Phiên bản tương thích tối thiểu. Ngăn các phiên bản Godot cũ hơn load những extension phụ thuộc vào tính năng của các phiên bản Godot mới hơn. Chỉ hỗ trợ từ Godot 4.1 trở lên

compatibility_maximum

String

Phiên bản tương thích tối đa. Ngăn các phiên bản Godot mới hơn load extension. Chỉ hỗ trợ từ Godot 4.3 trở lên

reloadable

Boolean

Load lại extension khi biên dịch lại. Tính năng reload được hỗ trợ cho binding godot-cpp từ Godot 4.2 trở lên. Các binding ngôn ngữ khác có thể hỗ trợ hoặc không. Cờ này chủ yếu nên dùng khi phát triển hoặc debug một extension.

android_aar_plugin

Boolean

GDExtension là một phần của plugin Android v2. Khi xuất, cờ này sẽ báo cho trình chỉnh sửa biết các thư viện dùng chung native của GDExtension được xuất bởi các binary AAR của plugin Android.

Mục libraries

Trong mục này, bạn có thể đặt đường dẫn tới các binary đã biên dịch của thư viện GDExtension. Bằng cách chỉ định feature flag, bạn có thể lọc phiên bản nào sẽ được load và xuất cùng game tùy theo feature flag nào đang bật. Mọi feature flag phải khớp với feature flag của Godot hoặc export flag tùy chỉnh của bạn thì mới được load trong game đã xuất. Ví dụ, macos.debug nghĩa là nó sẽ được load nếu Godot bật cả cờ macos và debug. Mỗi dòng của mục được đánh giá từ trên xuống dưới.

Đây là ví dụ về cách nó có thể trông như thế nào:

; A comment line starts with a semicolon. This line is ignored by the engine.
[libraries]

macos.debug = "./bin/libgdexample.macos.template_debug.dylib" ; Inline comments are also allowed.
macos.release = "./bin/libgdexample.macos.template_release.dylib"
windows.debug.x86_32 = "./bin/libgdexample.windows.template_debug.x86_32.dll"
windows.release.x86_32 = "./bin/libgdexample.windows.template_release.x86_32.dll"
windows.debug.x86_64 = "./bin/libgdexample.windows.template_debug.x86_64.dll"
windows.release.x86_64 = "./bin/libgdexample.windows.template_release.x86_64.dll"
linux.debug.x86_64 = "./bin/libgdexample.linux.template_debug.x86_64.so"
linux.release.x86_64 = "./bin/libgdexample.linux.template_release.x86_64.so"
linux.debug.arm64 = "./bin/libgdexample.linux.template_debug.arm64.so"
linux.release.arm64 = "./bin/libgdexample.linux.template_release.arm64.so"
linux.debug.rv64 = "./bin/libgdexample.linux.template_debug.rv64.so"
linux.release.rv64 = "./bin/libgdexample.linux.template_release.rv64.so"

Đường dẫn có thể là tương đối hoặc tuyệt đối (bắt đầu bằng res://). Nên dùng đường dẫn tương đối, vì chúng cho phép extension tiếp tục hoạt động nếu được cài vào thư mục khác với thư mục chỉ định trong đường dẫn.

Các mục được khớp theo thứ tự, nên nếu hai bộ feature tag có thể cùng khớp một hệ thống, hãy đặt bộ cụ thể hơn lên trước:

[libraries]

linux.release.editor.x86_64 = "./bin/libgdexample.linux.template_release.x86_64.so"
linux.release.x86_64 = "./bin/libgdexample.linux.noeditor.template_release.x86_64.so"

Dưới đây là danh sách một số tùy chọn tích hợp sẵn (để biết thêm, xem feature tag):

Mục icons

Mặc định, Godot dùng icon Node trong Scene dock cho các node GDExtension. Có thể đặt icon tùy chỉnh bằng cách tham chiếu tới tên của nó và đường dẫn resource của một file SVG.

Ví dụ:

[icons]

GDExample = "res://icons/gd_example.svg"

Đường dẫn nên trỏ tới một ảnh SVG 16×16 pixel, với hai tùy chọn được bật cho ảnh trong dock Import:

  • Editor > Scale with Editor Scale.

  • Editor > Convert Colors with Editor Theme.

Bật cả hai tùy chọn giúp icon hoạt động giống nhất có thể với các icon gốc của trình chỉnh sửa. Đọc hướng dẫn tạo icon để biết thêm thông tin.

Mục dependencies

Trong mục này, bạn đặt đường dẫn của các thư viện phụ thuộc của GDExtension. Mục này được dùng nội bộ để xuất các thư viện phụ thuộc khi xuất file thực thi của game. Bạn có thể chọn thư viện phụ thuộc nào được load tùy theo feature flag của file thực thi được xuất. Ngoài ra, bạn có thể đặt một thư mục con tùy chọn để chuyển các thư viện phụ thuộc vào. Nếu không cung cấp đường dẫn, Godot sẽ chuyển các thư viện vào cùng thư mục với file thực thi của game.

Cảnh báo

Trên macOS, các thư viện dùng chung bắt buộc phải nằm trong thư mục tên Frameworks với cấu trúc thư mục như sau: Game.app/Contents/Frameworks.

[dependencies]

macos.debug = {
    "res://bin/libdependency.macos.template_debug.framework" : "Contents/Frameworks"
}
macos.release = {
    "res://bin/libdependency.macos.template_release.framework" : "Contents/Frameworks"
}
windows.debug = {
    "res://bin/libdependency.windows.template_debug.x86_64.dll" : "",
    "res://bin/libdependency.windows.template_debug.x86_32.dll" : ""
}
windows.release = {
    "res://bin/libdependency.windows.template_release.x86_64.dll" : "",
    "res://bin/libdependency.windows.template_release.x86_32.dll" : ""
}
linux.debug = {
    "res://bin/libdependency.linux.template_debug.x86_64.so" : "",
    "res://bin/libdependency.linux.template_debug.arm64.so" : "",
    "res://bin/libdependency.linux.template_debug.rv64.so" : ""
}
linux.release = {
    "res://bin/libdependency.linux.template_release.x86_64.so" : "",
    "res://bin/libdependency.linux.template_release.arm64.so" : "",
    "res://bin/libdependency.linux.template_release.rv64.so" : ""
}
