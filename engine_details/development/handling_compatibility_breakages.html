Xử lý việc phá vỡ tương thích

Vậy là bạn đã thêm một tham số mới vào một phương thức, thay đổi kiểu trả về, thay đổi kiểu của một tham số hoặc thay đổi giá trị mặc định của nó, và giờ hệ thống kiểm thử tự động báo lỗi phá vỡ tương thích?

Nên tránh phá vỡ tương thích, nhưng khi cần thiết, đã có sẵn các hệ thống để xử lý việc này sao cho quá trình chuyển đổi diễn ra suôn sẻ nhất có thể.

Một ví dụ thực tế

Những thay đổi này được lấy từ pull request #88047, vốn đã thêm các tùy chọn tìm đường mới cho AStarGrid2D và các lớp AStar khác. Trong số các thay đổi khác, những phương thức sau đã được sửa đổi trong core/math/a_star_grid_2d.h:

Vector<Vector2> get_point_path(const Vector2i &p_from, const Vector2i &p_to);
TypedArray<Vector2i> get_id_path(const Vector2i &p_from, const Vector2i &p_to);

Thành:

Vector<Vector2> get_point_path(const Vector2i &p_from, const Vector2i &p_to, bool p_allow_partial_path = false);
TypedArray<Vector2i> get_id_path(const Vector2i &p_from, const Vector2i &p_to, bool p_allow_partial_path = false);

Điều này có nghĩa là phải thêm các binding phương thức tương thích mới vào tệp, nằm trong phần protected của mã, thường được đặt cạnh _bind_methods():

#ifndef DISABLE_DEPRECATED
    TypedArray<Vector2i> _get_id_path_bind_compat_88047(const Vector2i &p_from, const Vector2i &p_to);
    Vector<Vector2> _get_point_path_bind_compat_88047(const Vector2i &p_from, const Vector2i &p_to);
    static void _bind_compatibility_methods();
#endif

Chúng nên bắt đầu bằng _ để cho biết chúng là nội bộ, và kết thúc bằng _bind_compat_ theo sau là số PR đã đưa ra thay đổi (88047 trong ví dụ này). Các phương thức tương thích này cần được triển khai trong một tệp riêng, như core/math/a_star_grid_2d.compat.inc trong trường hợp này:

#ifndef DISABLE_DEPRECATED

TypedArray<Vector2i> AStarGrid2D::_get_id_path_bind_compat_88047(const Vector2i &p_from_id, const Vector2i &p_to_id) {
    return get_id_path(p_from_id, p_to_id, false);
}

Vector<Vector2> AStarGrid2D::_get_point_path_bind_compat_88047(const Vector2i &p_from_id, const Vector2i &p_to_id) {
    return get_point_path(p_from_id, p_to_id, false);
}

void AStarGrid2D::_bind_compatibility_methods() {
    ClassDB::bind_compatibility_method(D_METHOD("get_id_path", "from_id", "to_id"), &AStarGrid2D::_get_id_path_bind_compat_88047);
    ClassDB::bind_compatibility_method(D_METHOD("get_point_path", "from_id", "to_id"), &AStarGrid2D::_get_point_path_bind_compat_88047);
}

#endif // DISABLE_DEPRECATED

Trừ khi thay đổi về tương thích phức tạp, phương thức tương thích nên gọi trực tiếp phương thức đã sửa đổi thay vì sao chép lại phương thức đó. Hãy đảm bảo khớp các tham số mặc định của phương thức đó (trong ví dụ trên là false).

Tệp này luôn phải được đặt cạnh tệp gốc và có đuôi .compat.inc thay vì .cpp hoặc .h. Tiếp theo, tệp này cần được include trong tệp .cpp mà ta đang thêm phương thức tương thích, tức là core/math/a_star_grid_2d.cpp:

core/math/a_star_grid_2d.cpp
#include "a_star_grid_2d.h"
#include "a_star_grid_2d.compat.inc"

#include "core/variant/typed_array.h"

Cuối cùng, cần ghi lại các thay đổi API GDExtension. Để làm điều này, trước tiên hãy biên dịch Godot trên nhánh master, rồi chạy nó với cờ --dump-extension-api:

git switch master
scons
godot --dump-extension-api

Thao tác này sẽ tạo một tệp tên extension_api.json trong thư mục hiện tại. Chuyển sang nhánh tính năng của bạn, biên dịch lại Godot, rồi chạy nó với cờ --validate-extension-api theo sau là đường dẫn đến tệp extension_api.json vừa tạo:

git switch my-feature-branch
scons
godot --validate-extension-api /path/to/extension_api.json

Thao tác này sẽ tạo ra một số dòng bắt đầu bằng Validate extension JSON như sau:

Validate extension JSON: Error: Field 'classes/AStar2D/methods/get_id_path/arguments': size changed value in new API, from 2 to 3.
Validate extension JSON: Error: Field 'classes/AStar2D/methods/get_point_path/arguments': size changed value in new API, from 2 to 3.
Validate extension JSON: Error: Field 'classes/AStar3D/methods/get_id_path/arguments': size changed value in new API, from 2 to 3.
Validate extension JSON: Error: Field 'classes/AStar3D/methods/get_point_path/arguments': size changed value in new API, from 2 to 3.
Validate extension JSON: Error: Field 'classes/AStarGrid2D/methods/get_id_path/arguments': size changed value in new API, from 2 to 3.
Validate extension JSON: Error: Field 'classes/AStarGrid2D/methods/get_point_path/arguments': size changed value in new API, from 2 to 3.

Chú ý

Nếu bạn gặp lỗi Hash changed cho một phương thức, điều đó có nghĩa là binding tương thích bị thiếu hoặc không đúng. Những dòng như vậy không nên được thêm vào tệp validation, mà cần được sửa bằng cách bind đúng phương thức tương thích. Hãy kiểm tra kỹ những điều sau:

  • Đối với phương thức tương thích (phương thức có tên kết thúc bằng số PR), kiểu, tên và giá trị mặc định của các tham số phải giống hệt phiên bản của phương thức trước khi bạn thay đổi.

  • Trong _bind_compatibility_methods(), tên tham số được truyền cho macro D_METHOD() trong ClassDB::bind_compatibility_method() phải giống hệt tên trong lời gọi ClassDB::bind_method() của phương thức gốc.

Thêm các dòng này, kèm theo một comment giải thích thay đổi API là gì và các biện pháp đã thực hiện để tránh phá vỡ tương thích, vào một tệp validation được đặt tên theo ID pull request trên GitHub và đặt trong thư mục của phiên bản Godot mà thay đổi đó lẽ ra đã phá vỡ tương thích.

Vì ví dụ này là cho PR #88047, tên tệp sẽ là GH-88047.txt, và vì thay đổi được thực hiện trong quá trình phát triển 4.3 (tức là thay đổi so với 4.2), tệp sẽ nằm trong thư mục misc/extension_api_validation/4.2-stable/.

Xem bên dưới để có ví dụ đầy đủ về một tệp như vậy cho PR này:
