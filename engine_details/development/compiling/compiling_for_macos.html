Biên dịch cho macOS

Ghi chú

Trang này mô tả cách biên dịch các binary trình chỉnh sửa và export template cho macOS từ mã nguồn. Nếu bạn muốn xuất dự án sang macOS, hãy đọc Xuất cho macOS.

Yêu cầu

Để biên dịch trên macOS, bạn cần những thứ sau:

  • Python 3.9+.

  • Hệ thống build SCons 4.4+.

  • Xcode (hoặc Command Line Tools for Xcode nhẹ hơn).

  • Vulkan SDK cho MoltenVK (macOS không hỗ trợ Vulkan sẵn). Bạn có thể cài nhanh phiên bản Vulkan SDK mới nhất bằng cách chạy misc/scripts/install_vulkan_sdk_macos.sh trong repository mã nguồn Godot.

Ghi chú

Nếu bạn đã cài Homebrew, bạn có thể dễ dàng cài SCons bằng lệnh sau:

brew install scons

Việc cài Homebrew cũng sẽ tự động tải Command Line Tools cho Xcode nếu bạn chưa có.

Tương tự, nếu bạn đã cài MacPorts, bạn có thể dễ dàng cài SCons bằng lệnh sau:

sudo port install scons

Xem thêm

Để lấy mã nguồn Godot cho việc biên dịch, xem Lấy mã nguồn.

Để có cái nhìn tổng quan về cách dùng SCons cho Godot, xem Giới thiệu về hệ thống build.

Biên dịch

Mở terminal, đi tới thư mục gốc của mã nguồn engine.

Để biên dịch cho máy Mac dùng chip Intel (x86-64), hãy dùng:

scons platform=macos arch=x86_64

Để biên dịch cho máy Mac dùng chip Apple Silicon (ARM64), hãy dùng:

scons platform=macos arch=arm64

Mẹo

Nếu bạn biên dịch Godot để thay đổi hoặc đóng góp cho engine, bạn có thể muốn dùng các tùy chọn SCons dev_build=yes hoặc dev_mode=yes. Xem Các alias cho development và production để biết thêm thông tin.

Nếu mọi thứ suôn sẻ, file thực thi binary kết quả sẽ được đặt trong thư mục con bin/. File thực thi này chứa toàn bộ engine và chạy mà không cần bất kỳ phụ thuộc nào. Chạy nó sẽ mở Project Manager.

Ghi chú

Không nên dùng file thực thi trình chỉnh sửa độc lập; nó luôn nên được đóng gói thành bundle .app để tránh các vấn đề kích hoạt UI.

Ghi chú

Nếu bạn muốn dùng cài đặt trình chỉnh sửa riêng cho các bản build Godot của mình và các bản phát hành chính thức, bạn có thể bật Chế độ tự chứa (self-contained) bằng cách tạo một file tên ._sc_ hoặc _sc_ trong thư mục bin/.

Biên dịch với hỗ trợ AccessKit

AccessKit cung cấp hỗ trợ cho trình đọc màn hình.

Biên dịch với AccessKit cần cài thêm các phụ thuộc. Nếu muốn bỏ qua bước này, bạn có thể dùng tùy chọn SCons accesskit=no.

Bạn có thể cài các phụ thuộc cần thiết bằng cách chạy python misc/scripts/install_accesskit.py trong repository mã nguồn Godot. Sau khi chạy script này, hãy biên dịch Godot như bình thường.

Ghi chú

Bạn có thể tùy chọn tự build các thư viện godot-accesskit-static theo các bước sau:

  1. Clone thư mục godot-accesskit-c-static và di chuyển vào đó.

  2. Chạy lệnh sau:

cd accesskit-c
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build
cmake --install build

Thư viện tĩnh AccessKit nên được build bằng cùng trình biên dịch mà bạn dùng để build Godot.

Để biên dịch Godot với bản build AccessKit tùy chỉnh, hãy thêm accesskit_sdk_path={path} để chỉ cho SCons nơi tìm các thư viện AccessKit:

scons platform=macos accesskit_sdk_path=<...>

Biên dịch với hỗ trợ ANGLE

ANGLE cung cấp một lớp chuyển đổi từ OpenGL ES 3.x sang Metal và có thể dùng để cải thiện hỗ trợ cho renderer Compatibility trên một số GPU cũ có driver OpenGL lỗi thời.

Biên dịch với ANGLE cần cài thêm các phụ thuộc. Nếu muốn bỏ qua bước này, bạn có thể dùng tùy chọn SCons angle=no.

Bạn có thể cài các phụ thuộc cần thiết bằng cách chạy python misc/scripts/install_angle.py trong repository mã nguồn Godot. Sau khi chạy script này, hãy biên dịch Godot như bình thường.

Ghi chú

Bạn có thể tùy chọn tự build các thư viện godot-angle-static theo các bước sau:

  1. Clone thư mục godot-angle-static và di chuyển vào đó.

  2. Chạy lệnh sau:

git submodule update --init
./update_angle.sh
scons

Bạn cũng có thể chỉ định kiến trúc build bằng arch={architecture}.

Thư viện tĩnh ANGLE nên được build bằng cùng trình biên dịch mà bạn dùng để build Godot.

Để biên dịch Godot với bản build ANGLE tùy chỉnh, hãy thêm angle_libs={path} để chỉ cho SCons nơi tìm các thư viện ANGLE:

scons platform=macos angle_libs=<...>

Tự động tạo bundle .app

Để tự động tạo bundle .app giống các bản build chính thức, hãy dùng tùy chọn generate_bundle=yes ở lệnh SCons cuối cùng dùng để build trình chỉnh sửa:

scons platform=macos arch=x86_64
scons platform=macos arch=arm64 generate_bundle=yes

Tạo bundle .app thủ công

Để hỗ trợ cả hai kiến trúc trong một binary "Universal 2" duy nhất, hãy chạy hai lệnh trên rồi dùng lipo để gộp chúng lại:

lipo -create bin/godot.macos.editor.x86_64 bin/godot.macos.editor.arm64 -output bin/godot.macos.editor.universal

Để tạo bundle .app, bạn cần dùng template nằm trong misc/dist/macos_tools.app. Thông thường, với một binary trình chỉnh sửa đã tối ưu được build bằng dev_build=yes:

cp -r misc/dist/macos_tools.app ./bin/Godot.app
mkdir -p bin/Godot.app/Contents/MacOS
cp bin/godot.macos.editor.universal bin/Godot.app/Contents/MacOS/Godot
chmod +x bin/Godot.app/Contents/MacOS/Godot
codesign --force --timestamp --options=runtime --entitlements misc/dist/macos/editor.entitlements -s - bin/Godot.app

Ghi chú

Nếu bạn đang build nhánh master, bạn cũng cần thêm hỗ trợ cho thư viện Vulkan portability MoltenVK. Theo mặc định, nó sẽ được liên kết tĩnh từ bản cài Vulkan SDK cho macOS của bạn. Bạn cũng có thể chọn liên kết động bằng cách truyền use_volk=yes và đưa thư viện động vào bundle .app:

mkdir -p <Godot bundle name>.app/Contents/Frameworks
cp <Vulkan SDK path>/macOS/lib/libMoltenVK.dylib <Godot bundle name>.app/Contents/Frameworks/libMoltenVK.dylib

Chạy bản build headless/server

Để chạy ở chế độ headless, chế độ cung cấp chức năng của trình chỉnh sửa để xuất dự án một cách tự động, hãy dùng bản build thông thường:

scons platform=macos target=editor

Sau đó dùng đối số dòng lệnh --headless:

./bin/godot.macos.editor.x86_64 --headless

Để biên dịch bản build server debug có thể dùng với các công cụ gỡ lỗi từ xa, hãy dùng:

scons platform=macos target=template_debug

Để biên dịch bản build server release được tối ưu để chạy dedicated game server, hãy dùng:

scons platform=macos target=template_release production=yes

Build export template

Để build export template cho macOS, bạn phải biên dịch với các target không có trình chỉnh sửa: target=template_release (template release) và target=template_debug.

Template chính thức là các binary Universal 2 hỗ trợ cả kiến trúc ARM64 và Intel x86_64.

  • Để hỗ trợ ARM64 (Apple Silicon) + Intel x86_64:

    scons platform=macos target=template_debug arch=arm64
scons platform=macos target=template_release arch=arm64
scons platform=macos target=template_debug arch=x86_64
scons platform=macos target=template_release arch=x86_64 generate_bundle=yes

  • Để chỉ hỗ trợ ARM64 (Apple Silicon) (kích thước file nhỏ hơn, nhưng kém tương thích với phần cứng cũ):

    scons platform=macos target=template_debug arch=arm64
scons platform=macos target=template_release arch=arm64 generate_bundle=yes

Để tạo bundle .app giống các bản build chính thức, bạn cần dùng template nằm trong misc/dist/macos_template.app. Quá trình này có thể được tự động hóa bằng tùy chọn generate_bundle=yes ở lệnh SCons cuối cùng dùng để build export template (để mọi binary đều được đưa vào). Thao tác này sẽ tạo file godot_macos.zip trong bin/ và đồng thời gọi lipo để tạo binary Universal 2 từ hai binary ARM64 và x86_64 riêng biệt (nếu cả hai đã được biên dịch trước đó).

Ghi chú

Bạn cũng cần thêm hỗ trợ cho thư viện Vulkan portability MoltenVK. Theo mặc định, nó sẽ được liên kết tĩnh từ bản cài Vulkan SDK cho macOS của bạn. Bạn cũng có thể chọn liên kết động bằng cách truyền use_volk=yes và đưa thư viện động vào bundle .app:

mkdir -p macos_template.app/Contents/Frameworks
cp <Vulkan SDK path>/macOS/libs/libMoltenVK.dylib macos_template.app/Contents/Frameworks/libMoltenVK.dylib

Trong hầu hết trường hợp, nên ưu tiên liên kết tĩnh vì nó giúp việc phân phối dễ dàng hơn. Ưu điểm chính của liên kết động là cho phép cập nhật MoltenVK mà không cần biên dịch lại export template.

Nếu bạn tạo .app thủ công, bạn có thể nén thư mục macos_template.app thành zip để tạo lại template macos.zip giống bản phân phối chính thức của Godot:

zip -r9 macos.zip macos_template.app

Để dùng export template tùy chỉnh, bạn có thể chọn file godot_macos.zip trong phần tùy chọn nâng cao của export preset:

Ngoài ra, nếu bạn muốn mọi preset đều dùng export template tùy chỉnh, bạn có thể đổi tên file godot_macos.zip thành macos.zip và chuyển nó tới vị trí mặc định của export template:

::

~/Library/Application Support/Godot/export_templates/<GODOT_VERSION>/macos.zip

Biên dịch chéo cho macOS từ Linux

Bạn có thể biên dịch cho macOS trong môi trường Linux (và có thể cả trên Windows bằng Windows Subsystem for Linux). Để làm vậy, bạn cần cài OSXCross để có thể dùng macOS làm target. Trước tiên, hãy làm theo hướng dẫn để cài đặt nó:

Clone repository OSXCross về một nơi nào đó trên máy (hoặc tải file ZIP và giải nén ở đâu đó), ví dụ:

git clone --depth=1 https://github.com/tpoechtrager/osxcross.git "$HOME/osxcross"

  1. Làm theo hướng dẫn để đóng gói SDK: https://github.com/tpoechtrager/osxcross#packaging-the-sdk

  2. Làm theo hướng dẫn để cài đặt OSXCross: https://github.com/tpoechtrager/osxcross#installation

Sau đó, bạn cần đặt OSXCROSS_ROOT là đường dẫn tới bản cài OSXCross (cùng nơi bạn đã clone repository/giải nén file zip), ví dụ:

export OSXCROSS_ROOT="$HOME/osxcross"

Giờ bạn có thể biên dịch bằng SCons như bình thường:

scons platform=macos

Nếu phiên bản SDK OSXCross của bạn khác với phiên bản mà hệ thống build SCons mong đợi, bạn có thể chỉ định một phiên bản tùy chỉnh bằng đối số osxcross_sdk:

scons platform=macos osxcross_sdk=darwin15

Khắc phục sự cố

Fatal error: 'cstdint' file not found

Nếu bạn gặp lỗi biên dịch dạng này ngay từ đầu, nhiều khả năng là do bản cài đặt Xcode command line tools cần được sửa chữa sau khi cập nhật macOS hoặc Xcode:

./core/typedefs.h:45:10: fatal error: 'cstdint' file not found
45 | #include <cstdint>
   |          ^~~~~~~~~

Chạy hai lệnh sau để cài đặt lại Xcode command line tools (nhập mật khẩu quản trị viên khi được yêu cầu):

sudo rm -rf /Library/Developer/CommandLineTools
sudo xcode-select --install

Nếu vẫn không được, hãy thử cập nhật Xcode từ Mac App Store rồi thử lại.
